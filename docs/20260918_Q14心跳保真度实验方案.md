# Q14 心跳保真度实验方案（草案——花真金，执行需用户批准）

- **日期**：2026-09-18（夜批处理产出）
- **性质**：实验方案（未执行）。执行是心跳执行器的硬门槛（设计文档 §5-5）。
- **上游**：[20260918_CC路由与代理调研](20260918_CC路由与代理调研.md)、[20260918_Task派活拦截可行性调研](20260918_Task派活拦截可行性调研.md)、设计文档 §3.5

## 0. 实验要回答的三件事

1. daemon 能否从会话 jsonl 重构出与 CC 真实请求**逐字节等价前缀**的保温请求？
2. 首跳（确定性命中窗 ≤10min 内、对真实前缀发出）实收 cacheRead ratio 是否 ≥0.85？
3. 连跳 3 次是否稳定 HIT（对账矩阵 HIT/HIT，排除自我续命假阳性）？

## 1. 调研新事实对实验设计的影响

| 事实 | 影响 |
|---|---|
| CC → cc-switch.exe（127.0.0.1:15721），令牌字面量 `PROXY_MANAGED`，真钥只在代理侧 DB | beat 直打代理即可，daemon 无需持有真钥 |
| 代理**改写请求**：模型映射（别名→上游名）、剥 `[1M]` 后缀、thinking 整流、参数白名单 | beat 必须发**CC 别名**（如 `claude-opus-5[1M]`），代理自会映射；发 jsonl 回显名（如 `GLM-5.3`）会被映射进 default 档（glm-5.3-flash）→ **必 miss** |
| jsonl assistant 记录的 `model` 是上游回显名，不是 CC 发的别名 | 别名反查：settings.json 的 `ANTHROPIC_DEFAULT_*_MODEL`，或 cc-switch DB 供应商映射 |
| 代理不记请求体 | 报文模板无法从代理日志取，必须旁路抓包 |
| 缓存跨客户端共享（实验报告 §2） | beat 与 CC 真实请求撞同一内容前缀即互蹭——机制前提成立 |

## 2. 三段式设计

### 段一：抓包（取得"CC 真实报文模板"）

- 起一个本地转发器（Python，监听 127.0.0.1:15722 → 转发 127.0.0.1:15721，落盘请求体；~80 行，放 `experiments/beat-fidelity/`）
- 临时把 `~/.claude/settings.json` 的 `ANTHROPIC_BASE_URL` 改为 15722（**改动用户配置——需用户在场批准**；实验后立即还原）
- 跑一次真实小会话（`claude -p`，2-3 轮工具调用，制造 41k+ 前缀可复用大 system）
- 产出：CC 请求的完整形状——headers、`model` 别名、`system`/`tools` 数组结构与序列化细节、`messages` 排布、thinking/参数
- 待确认：15721 是明文 http 还是 https（明文则可纯旁路监听，免改配置）

### 段二：重构（BeatBuilder 与模板 diff）

- daemon 侧新件 `BeatBuilder`：读会话 jsonl → 重构 `[system + tools + u1…uN]`（不含末轮 assistant 输出，§3.5）+ 别名反查模型名
- 与段一模板做**逐字段 diff**：任何不等（含 tools 顺序、未知字段、数值类型）都记缺陷；全等才进段三
- 纯本地，零花费

### 段三：实跳（花真金，需批准）

- 3 个独立臂：各一段全新 41k+ 真实前缀（CC 轨造出后闲置）
- 每臂：闲置第 8 分钟发首跳（BeatBuilder 产物直打 15721）→ 读实收 cacheRead；HIT 则 +8min、+16min 两跳
- 通过判据：首跳 ratio ≥0.85 ×3 臂；续跳 HIT；对账矩阵 HIT/HIT（会话自己 resume 一发读地面真值）
- **花费预算（GLM 积分）**：每臂首跳命中 ≈41k×1.7/1e4≈7 积分，miss 全价 ≈28 积分；3 臂最坏（全 miss）≈84 积分 + 地面真值 resume 一发 ≈7-28 积分。**上限约 100-120 积分**——执行前须用户点头

## 3. 不做 / 后置

- Codex 轨：后置（设计 §7）
- L3 并发探针（beat+resume 同发、双 beat、代理串行化、429）：与段三同场顺手可测两项（双 beat 同发、beat 与 resume 相邻秒级），完整 L3 清单执行器启用门槛时再跑
- 代理侧 cache_control 注入：本机未生效（调研实证），不依赖

## 4. 失败分支预案

- 段二 diff 不等 → 修 BeatBuilder 重 diff；结构性不等（CC 每次注入动态内容）→ 触发 §3.5"保真度备胎"（代理侧捕获原样重放），单独立项
- 段三首跳 miss 且地面真值 HIT → TTL/时序问题，复测而非改判据
- 段三 HIT 但地面真值 MISS → 自我续命实锤，停：执行器方案推倒，回到备胎
