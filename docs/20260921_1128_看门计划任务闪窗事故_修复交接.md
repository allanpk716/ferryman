## 一句话结论

`FerrymanWatchdog` 计划任务每 5 分钟用 `powershell -WindowStyle Hidden` 包装拉起 `ferryman watchdog`，Windows 的行为是**先把控制台黑窗建出来再隐藏**，所以每 5 分钟闪一次黑窗（全天 288 次）。已把计划任务和 Run 键自启都改成 **wscript + VBS 隐身启动器**（GUI 子系统宿主，天生不创建控制台），源码同步改完、测试全过、线上已部署并验证。

## 事故还原（证据链）

1. **现象**：用户屏幕不停闪控制台黑窗，快到看不清内容。
2. **静态排查**：最近 3 小时运行过的计划任务里，`\FerrymanWatchdog` 每 5 分钟一跳（`MSFT_TaskTimeTrigger(repeat every PT5M)`），动作是：
   ```
   powershell -NoProfile -WindowStyle Hidden -Command "Start-Process -FilePath '<exe>' -ArgumentList 'watchdog' -WindowStyle Hidden"
   ```
3. **节律实锤**：`~/ferryman/watchdog.log` 全天整齐记录 5 分钟一跳（10:03:00、10:08:00、10:13:00……一小时 12 次），与用户看到的闪窗频率吻合。
4. **根因**：`-WindowStyle Hidden` ≠ 无窗。窗口先创建（可见）再隐藏（不可见），中间肉眼可见一闪。Task Scheduler 在**交互会话**直接拉 console 子系统进程时必然走这条路径。
5. **为什么 ensure.ps1 的同款写法没闪过**：钩子场景里 PowerShell 是 CC（node）拉起来的，父进程的控制台本来就被 `windowsHide` 压住，子进程再 `Start-Process -WindowStyle Hidden` 时窗从未可见过；Go 侧 `LaunchDaemon` 也有 `SysProcAttr{HideWindow:true}` 双保险，同样真不闪。**唯独计划任务这条链，Task Scheduler 是"裸拉"console 进程**，所以只有它闪。
6. **顺带发现**：Run 键自启（`AutostartCommand`）是同一构造，每次登录也会闪一次，一并修了。

**修法选型**：`wscript.exe`（GUI 子系统，天生无控制台）+ 10 行 VBS，内部 `WshShell.Run "目标", 0, False`（风格 0 = 子进程隐藏，False = 不等待，与旧 Start-Process 形态行为等价）。这是 PM2 的 `pm2-windows-startup` 同款机制，本机 PM2 自启就在用，久经验证。

## 源码变更明细（未提交，4 个文件）

### internal/installer/watchdog.go

- **`WatchdogTR(vbs string)`——参数语义变了**：原来传 exe 路径、返回 powershell 包装串；现在传 VBS 路径、返回 `wscript.exe "<vbs>"`。**包外无调用点**（已 grep 全仓库确认，调用全在本包内）。
- 新增 `watchdogVBSName = "watchdog-hidden.vbs"` 常量、`watchdogVBSBody(exe)`（VBS 内容构造，全 ASCII——对齐 EnsureLauncher 的 ASCII 铁律）、`WatchdogVBSPath()`（落点 `~/ferryman/watchdog-hidden.vbs`）、`EnsureWatchdogVBS(dir, exe)`（幂等落盘，dir 注入供测试指临时目录）。
- `WatchdogTaskInstall()` 改为**先落 VBS 再建任务**——VBS 缺位 = 任务每跳空转，响亮失败（对齐票22 骑手 M3"地基写不出绝不报就绪"）。
- `realTaskDeps()` 的 tr 改由 `WatchdogVBSPath()` 推导。
- `daemonStartScript`/`daemonStartPSArgs` **保留未动**（仍被 `LaunchDaemon` 用，那条链真不闪）；只更新了注释，标明它们不再与 Run 键共用。
- 文件头冒烟清单第 5 条已改写（原"无窗口闪现"结论是错的，已注明事故背景）。

### internal/installer/autostart.go

- **`AutostartCommand(launcher)` 返回值形态变了**：从 powershell 包装串改为 `wscript.exe "<launcher 同目录>\start-daemon-hidden.vbs"`。`autostartStatusOf` 的逐字比对用的就是这同一构造，所以 doctor 的 installed/mismatch 判定自动一致，**无需改 doctor**。
- 新增 `daemonVBSName` 常量、`DaemonVBSPath(launcher)`、`daemonVBSBody(launcher)`、`ensureDaemonVBS(launcher)`。
- `AutostartInstall()` 改为先落 VBS 再写键值（理由同上）。
- import 增加 `os`。

### internal/installer/watchdog_test.go / autostart_test.go

- 旧形态逐字断言全部改为 wscript 形态；`TestSchtasksCreateArgsVerbatim` 的"无窗口标志"断言改为"wscript 隐身宿主"断言。
- 新增 4 个测试：`TestWatchdogVBSBodyVerbatim`、`TestEnsureWatchdogVBSWrites`、`TestDaemonVBSBodyVerbatim`、`TestEnsureDaemonVBSWrites`（落盘测试走 `t.TempDir()`，不碰真 dataDir，对齐本包"绝不真写"的副作用纪律）。
- **`go vet` + `go test ./internal/installer/ -count=1` 全过；整树 `go build ./cmd/ferryman` 通过**。

### 兼容性/迁移注意

- **老用户升级路径**：新 exe 跑一次 `ferryman watchdog install` + `ferryman autostart install` 即迁移（`/F` 幂等覆盖；Run 键值不符会被当作 mismatch 覆盖修复——这正是三态设计的行为，无需额外迁移代码）。
- **降级风险**：旧 exe 重跑 install 会把任务/Run 键写回闪窗形态（闪回来但不坏）。
- 别手改两个 VBS——文件头有 `auto-generated, do not edit` 标记，install 会覆盖。
