# Ferryman（摆渡人）开发交接文档

> 产出日期：2026-09-16 09:45 ｜ 来源：research_things 完整调研（同目录 `20260916_0853_Agent会话闲置缓存失效与自动交接_技术调研.md`，建议一并拷入新项目 `docs/`）
> 本文档自包含：新项目里一个全新会话拿到它即可开工，无需原对话背景。
> 命名：Ferryman / 摆渡人（用户已选定）。隐喻：缓存死了，摆渡人把旧会话上下文的精华"渡"到新会话。

---

## 1. 一句话定义

**Ferryman 是一个本机常驻守护进程：监控 Claude Code / Codex（后续 Pi、DeepSeek Harness）的会话文件，发现会话闲置超时后自动用便宜模型总结成"交接 MD"，并通过各 Agent 的提交前钩子强制拦截"凉会话"的继续使用，引导用户 /clear 后开新会话（自动注入交接 MD），从而避免为死缓存全量重付 input 费用/额度。**

四个动作：**守望（watch）→ 摆渡（summarize）→ 闸门（gate）→ 归还（restore）**。

## 2. 为什么要做（经济学，30 秒版）

- AI CLI 的 input 约 **95% 走缓存读取（1 折）**；闲置超过缓存保质期（TTL）后，下一次发消息要把全部历史按原价（Anthropic 写价 1.25×）重算——**差价约 12.5 倍**。有实测：91 万 token 会话晾 45 分钟，回来一句"继续"吃掉当天额度 ~20%。
- 本机实际路由（2026-09-16）：Claude Code 走 CC Switch 代理（127.0.0.1:15721）→ 主力 **GLM-5.3（智谱 Coding Plan 订阅）**；Codex 0.153.0 走 ChatGPT 订阅。**订阅制下缓存失效不直接扣钱、扣的是额度与速度**（智谱官方明文"缓存差异化计费不含 Coding Plan"；OpenAI Codex 订阅 2026-04 起按 token 折算 credits，cached input 按 10% 计）。切 API key 路线时才是真金白银。价值排序：**省额度 > 省钱 > 续接快**。
- 社区真空位：idle 触发+自动总结+外部提醒+强制拦截的完整链路**无任何现成品**（唯一跑通过 idle 自动压缩的 dthinkr/auto-compactor 已删库，数据遗留在 anthropics/claude-code issue #71254 评论区：842,223 → 13,555 token）。

## 4. 系统架构

```
                        ┌──────────────────────────────────────────┐
                        │  Ferryman 守护进程（本机常驻，HTTP）        │
                        │  · 会话台账：session_id→最后活动/大小/标题   │
                        │  · 轮询两个会话目录 mtime（数百文件，秒级轮询够用）│
                        │  · 闲置判定（拦截阈值默认30min；总结阈值独立，默认更长）│
                        │  · 摆渡执行器：读jsonl→抽正文→调可配置模型→写交接MD │
                        │  · 交接MD库（自带目录，独立于transcript存活）    │
                        │  · /gate 接口：钩子来问"放不放行"             │
                        │  · 通知：调 claude-notify（Toast/Pushover）   │
                        └──────────────────────────────────────────┘
     ↑问询(每个prompt一次)              ↑只读jsonl                    ↑写完通知用户
┌────┴─────┐  ┌──────────┴───┐  ┌──────┴───────┐  ┌────────────┴───┐
│ CC 适配器 │  │ Codex 适配器  │  │ (Pi 适配器)   │  │ (dsh 适配器)    │
│UserPrompt│  │UserPrompt    │  │input事件      │  │agent/pre-step  │
│Submit钩子 │  │Submit钩子    │  │action:handled│  │reject / CC桥    │
└──────────┘  └──────────────┘  └──────────────┘  └────────────────┘
用户被拦 → 手敲 /clear → 新会话 SessionStart 钩子自动注入该项目最新交接 MD → 继续
```

## 5. 各家拦截/注入配方（全部已核实，2026-09-16）

### 5.1 Claude Code（v2.1.232 即可用）

**拦截（UserPromptSubmit hook）**
- 触发点：用户按回车后、消息发给模型前。TUI / headless `-p` / `--resume` 全都触发。
- 阻断方式 A：`exit 2` + stderr 写提示文案 → prompt 被抹除不进上下文，stderr 显示给用户。
- 阻断方式 B：stdout JSON：`{"decision":"block","reason":"此会话已闲置X分钟，缓存已失效。交接文档: <路径>。请 /clear 后新开会话（将自动加载交接）。","suppressOriginalPrompt":true}`
- 放行+注入：`{"hookSpecificOutput":{"hookEventName":"UserPromptSubmit","additionalContext":"..."}}`（**additionalContext 必须嵌在 hookSpecificOutput 里，放顶层被静默忽略**——官方点名的坑）。
- stdin 字段：`session_id`、`transcript_path`、`cwd`、`prompt`、`permission_mode`、`hook_event_name` 等。
- 超时：默认 30s，**超时=放行（fail-open）**；显式设 `timeout: 2-3` 秒，且脚本内 HTTP 调用要设更短的内层超时。
- 官方还有 `type:"http"` 的 hook（POST 事件 JSON 到本机端口，响应体即决策 JSON）——**2.1.232 是否可用需实测**，不可用则退化为 command hook + curl。
- hooks 不能替用户执行 /clear（官方明令 "They can't trigger `/` commands"）——提示文案让用户手敲。
- 配置示例（追加到现有 hooks，勿动 Orca 的）：
```json
"UserPromptSubmit": [{"hooks": [{"type": "command", "command": "ferryman-gate.cmd", "timeout": 3}]}]
```
（并按第 3 节地雷同步进 CC Switch 模板）

**归还（SessionStart hook，matcher: startup/clear/resume/compact）**
- stdout（exit 0）即注入上下文；匹配 `clear`/`startup` 时注入"该项目最新交接 MD"。注意 SessionStart **不能阻断**（只能注入）。
- v2.1.251+ 的 SessionStart(resume) 自带 `seconds_since_last_response` 字段——本机 2.1.232 没有，用台账替代。

### 5.2 Codex CLI（0.153.0）

- 配置：`~/.codex/hooks.json`（或 config.toml 内联 `[hooks]`），Windows 用 `commandWindows`/`command_windows` 覆盖命令。
- **UserPromptSubmit 支持 JSON `{"decision":"block","reason":"..."}`（reason 必须非空，否则记为 Failed 且不阻断、fail-open）或 exit 2 + stderr**。被拦 turn 零 token、不写 rollout（源码级确认）。
- ⚠ **部署大坑：hook 信任机制**——非托管 hook 必须先在 TUI 里 `/hooks` 审查信任（按定义哈希），**未信任的 hook 被静默跳过且 fail-open**。改了 hook 定义要重新信任。headless（codex exec）下要么预置信任、要么 `--dangerously-bypass-hook-trust`。
- 超时默认 600s、超时=不阻断；显式设短。
- SessionStart 注入：matcher `startup|resume|clear|compact`；stdout 纯文本或 `hookSpecificOutput.additionalContext`；默认上限 `additionalContextLimit` **2500 token**，超出走"spilling"（全文存临时文件、模型收首尾预览+路径）——大交接 MD 不截断，反而因祸得福。
- 拦截语义与 CC 高度同构（都认 exit 2 + stderr），问询脚本可复用。

### 5.3 Pi / omp（后期）

- Pi 扩展 `input` 事件（提交点，skill 展开前）：返回 `{action:"handled"}` = 硬闸（agent loop 完全跳过，配 `ctx.ui.notify` 提示）；`{action:"transform", text}` 可改写；`before_agent_start`/`context` 事件注入。**所有工具里最干净的提交点拦截**。
- omp：hooks=extensions 包装，`.omp/hooks/pre/`、`~/.omp/agent/hooks/` 目录约定；无超出上游的提交点能力。
- 会话：`~/.pi/agent/sessions/` JSONL 树结构。

### 5.4 DeepSeek Harness / dsh（后期）

- 官方产品（deepseek-ai/deepseek-harness，MIT，2026-08-13 开源 dev preview，注意会有破坏性变更；npm 仿品多，认准 `@deepseek-ai/dsh`）。
- 原生拦截：`agent/pre-step` 返回 `{kind:'reject'}`；工具门禁 `tools/pre-execute` deny/ask；`agent/session-start` 注入（不能阻断）。
- **自带 CC hooks 兼容桥（dsh-hooks-claude-code）**：UserPromptSubmit deny → 正确转成 reject。我们给 CC 写的钩子大概率直接复用。

### 5.5 无闸门工具的兜底（可选、最后做）

- Crush/Goose/Aider 无提交前拦截（Crush 未实现、Goose 仅观察、Aider 无 hooks）。
- 代理层兜底：LiteLLM `async_pre_call_hook` 可拒绝/改写请求——但 Anthropic 协议里没有 session id，只能启发式（input 规模 + messages 条数 + 前缀哈希状态表）。定位：非主路径。

## 6. 守护进程设计要点

1. **台账（ledger）**：按 `session_id` 记最后活动时间、上下文大小、标题、项目路径、Agent 类型。闲置判定**只信台账，不解析 jsonl**（官方确认 transcript 异步落盘有延迟；钩子触发时新 prompt 可能还没写入——台账里记的"上次写入"天然就是上一轮）。
2. **轮询**：扫描两个会话目录的 mtime（数百文件规模，1-5 秒轮询完全够；后续要快可上 ReadDirectoryChangesW/USN，用户文件搜索项目有积累）。
3. **两个独立阈值**（都要按 Agent/服务商/模型分别可配）：
   - **拦截阈值**（问询 /gate 时的"凉了"判定）：默认 **30 分钟**（用户定）；
   - **总结触发阈值**（多久没动才开始摆渡）：默认更长（如 2 小时，待定），避免"倒杯咖啡回来就被总结"。
   - 另有**最小上下文门槛**（如 <20K token 的会话不值得管，跳过）。
4. **/gate 接口**：POST `{session_id, agent, cwd, prompt摘要?}` → `{decision: "allow"|"block", reason, handoff_path?}`。钩子侧脚本只做搬运。**守护进程不可达/超时 → allow（fail-open，与 CC/Codex 原生语义一致；要 fail-closed 得在钩子脚本里显式做）**。
5. **摆渡执行器**：独立 API 调用（不驱动原会话、不污染 transcript）。原料=jsonl 提取的 user/assistant 正文；**大工具输出截断/跳过**（20MB 级会话必须做输入上限）；发给可配置模型（默认候选：GLM-5.3-Flash（10万token≈8分钱）/ 本地 4090 Qwen3.8-27B（零成本）/ 主力模型（最贵最好）——用户要求留空可配置，后议）；走 CC Switch 或直连智谱均可配。
6. **交接 MD 库**：Ferryman 自管目录（如 `~/ferryman/handoffs/`），命名 `YYYYMMDD_HHMM_<项目名>_<会话标题>.md` + 一份 `index.json`。**独立于 transcript**（CC transcript 30 天自动清理，交接必须活得比它久）。
7. **交接 MD 模板**（建议）：目标是什么 / 已完成+关键结论 / 未完成+下一步 / 关键文件与改动清单 / 踩过的坑与决策 / 给新会话的第一句话（续接指令）。
8. **通知**：总结完成后调 claude-notify（Pushover + Windows Toast 已就绪），文案带 MD 路径。

## 8. 明确不做的事（设计红线）

- ❌ 不做保活（keep-alive）：社区实测服务端每天定点强制清缓存（有人实测早 8 点），跨夜不可靠，且持续花钱；
- ❌ 不抢 5 分钟缓存过期窗（只在按量 API 路线有意义，复杂度暴增）；
- ❌ 不碰运行中的会话（不注入 /compact、不改 jsonl）——只读+外置总结，规避官方更新风险（前科 #75837）；
- ❌ 不嵌进 Orca、不动 Orca 的 hooks（独立工具）；
- ❌ 不升级 CC。

## 9. 后端验证最小闭环（第一步要干的事）

1. **台账+轮询**：守护进程扫两个会话目录，维护台账（标题/最后活动/大小）——验收：能在日志里看到 238+317 个会话的正确状态。
2. **CC 闸门**：写 UserPromptSubmit 钩子（先 command 型）连守护进程 /gate——验收：拿一个闲置超阈值的真实旧会话，发消息被拦并显示提示文案；活跃会话不受影响；**同时验证 CC Switch 切换供应商后钩子仍在**（否则就是踩了第 3 节的地雷，要把钩子进模板）。
3. **拦截零成本**：被拦的那次提交在会话文件里无新增、`/cost` 无变化。
4. **摆渡+归还**：对一个超阈值会话跑总结→写 MD→Toast 通知；然后 /clear，验证 SessionStart 钩子自动注入该 MD——验收：新会话第一轮就知道"昨天干到哪了"。
5. （顺手）Codex 钩子照抄 CC 语法改一版，过 `/hooks` 信任流程，同样验证 2-3 步。

## 10. 坑清单（实现时逐条对照）

1. CC Switch 覆盖 settings.json 抹 hooks（本机已踩过，见第 3 节）；
2. Codex hook 未信任=静默跳过+fail-open；改定义要重新信任；
3. CC UserPromptSubmit 超时 30s 默认 fail-open；`additionalContext` 放顶层被静默忽略；
4. 被拦 prompt 会被**抹除**——用户 /clear 后要重打那句话（TUI 上翻能否找回，实测确认，写进提示文案）；
5. jsonl 格式官方不保证稳定——防御式解析，挂了退 mtime-only；
6. 20MB 级会话：总结器必须做输入截断策略；
7. 闲置判定防误伤：后台 subagent/长命令会持续写文件——按"最后写入"算（宁可多等），且总结触发前再查一次；
8. dsh 会话是 zstd 压缩；
9. CC transcript 30 天清理（`cleanupPeriodDays`）——交接 MD 库独立存放；
10. 多机器（NUC10/服务器）上的会话不在视野内，v1 只管本机。

## 12. 技术栈建议（未拍板，验证阶段自由选）

- **验证期**：Python 最快（轮询+JSON 解析+zstd+HTTP server 一天能跑通；Windows 上跑常驻无碍）；
