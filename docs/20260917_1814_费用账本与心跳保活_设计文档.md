## 0. 范围与授权边界

- **T41 实装**：费用账本（六科目）+ report CLI + 策略计算器（纯公式）+ SYSTEM_PROMPT 两招（经 E1 验证）。
- **设计定案但不实装**：心跳执行器（体外重放运行时）。其授权需先过 §5 两道门槛。
- **职责边界**：机器等机器（主会话等子代理）归心跳；人不在的闲置归摆渡/闸门。

## 1. 费用账本

### 1.1 价格表（Q1/Q16）

- 宿主：本机 `config.toml`（T39 血统：不进代码、不进 git），`config.example.toml` 给 GLM 示例。
- 每条目：provider+model → `P_in` / `P_cache` / `P_out` + 自述单位（如 GLM 积分系数 6.9/1.7/24 每万 token）+ 生效日期。
- 版本化：每条流水**钉死记账时依据的价格表版本**，改价不重算旧账。
- 缺省语义：`P_cache` 允许缺省——缺省即无缓存经济，策略计算器**拒绝**推导心跳参数，report 标注"该 provider 节省额不可算"。宁可少报，不造数。

### 1.2 科目（Q2/Q15）

| 科目 | 记什么 | 记账点 |
|---|---|---|
| `handoff` | 摆渡每次模型调用（含 L2 分块、重试、**失败**） | `ferry.py`（usage 已捕获，接持久化） |
| `beat` | 每次心跳（执行器未授权前仅占坑） | 执行器（未来） |
| `block` | 闸门每次拦截 + 当时前缀规模 S | `server.py` gate |
| `inject` | 归还注入的交接 token 数（成本侧） | restore |
| `bypass` | 逃生门绕过（不计节省，反事实对照组） | gate |
| `window` | 等待窗口起止 + 当时 S（executor 无关，Q13 先行） | 子代理事件 handler |

**隐私不变量**：只记元数据与金额——时间、会话/族系/项目/Agent、token 数、单价版本、结果码；**永不落消息内容**。心跳体外重放走会话本就在用的同一路由，无新增内容暴露面。

### 1.3 存储与查询（Q4/Q5/Q7）

- 存储：数据根下 `accounts/YYYYMM.jsonl`，append-only，按月滚动（本地时区），每行带 schema 版本字段；全项目一本（行内带 project/session/agent）；不自动清理；**无历史可回填，从零起**。
- 统计单位：每条流水带 `session_id`（明细）+ `lineage_id`（聚合键）；**报表主视图按族系**——"这段对话总共花/省多少"，下钻文件明细。理由：block→inject→净节省因果链天然跨 resume。
- 查询：`ferryman account report`——人读表格 + `--json`；过滤 `--since/--until/--project/--session/--kind`；报告尾部附**复算附录**（价格表版本、公式版本、一行复算命令）。

### 1.4 成效账：节省的反事实口径（Q3）

```
每次拦截节省 = S×(P_in − P_cache) − 交接注入tokens×P_in − handoff成本
```

- 毛值/净值都报。
- **只有真实兑现的避免才计节省**：bypass 绕过的拦截不计（照付全量，入对照组）；保温期内会话未回归 → **无效保温**，纯亏损单列。
- 节省额只在 report 层由**版本化成效公式**计算，原始流水永不改写；公式升级旧报告可重算。

## 2. 策略计算器（Q6）

纯公式模块，无副作用，输入价格表 + 实测 TTL，闭式输出：

- 心跳间隔 `τ = 0.8 × T`（GLM：T=10min → 8min）
- 单次心跳成本 `= S×P_cache + ~300×P_out`
- 放任过期代价 `= S×P_in`
- 心跳划算的等待上限 `≈ τ × S×(P_in−P_cache) / 单次成本`（GLM S=150k：1428s≈23.8min；2026-09-18 修正，原估 ~25–28min 偏乐观；S 越小上限越短，300×P_out 项占比变大——30k 下限即为此而设）
- 首跳时机 = T0+τ（闲置满 τ 再首跳；2026-09-17 修正见 §3.6，原宽限期默认 5min 作废）与最小前缀阈值（默认 30k）的推导默认值，config 可覆盖
- 分档决策矩阵：≤8min 不作为 / 8–28min 心跳 / ≥28min 放任过期（大前缀先 compact）
- 无 `P_cache` 输入 → 拒绝输出心跳参数

## 3. 心跳（设计定案，未实施）

### 3.1 触发状态机（Q8）

- **开窗**：子代理派发事件（现有 `/subagent` 钩子）→ 主会话进入等待窗口；跟踪该会话**在飞子代理集合**（含嵌套）。
- **起跳**（全部满足）：主会话闲置满 τ 即首跳（T0+τ，§3.6 修正；原宽限期 5min 作废）+ 台账前缀 ≥ 阈值 + opt-in。
- **节律**：每 τ 一跳，间隔自上一次成功 HIT 起算。
- **停跳**：**最后一个子代理完成**（agent loop 自动续跑，暖缓存即刻兑现）或主会话恢复写入或等待超划算上限（记"放任过期"事件）。
- 全程默认 off，config 显式开；状态与累计花费随时可查、一键停。

### 3.2 执行器载体（Q9）

体外重放：daemon 从会话文件读稳定前缀（复用摆渡稳定快照机制），按该 Agent 请求形状**逐 token 重构**（不一致即全 miss），直打 CC Switch 本地代理（与真实使用同计费同缓存路由），`max_tokens` 压最小，不写会话文件、聊天界面无感。前缀重构机器自 `experiments/cache-ttl/` pi 轨移植。**先只做 CC 轨**（Codex rollout→请求重构复杂度高，挂后续）。

### 3.3 自校验回路（Q10）

- 每跳：预期 cacheRead ≈ S，实收 ratio ≥0.85 判 HIT；记预测 vs 实收对账行。
- miss：记异常 + notify 告警 + **停跳**（连续 miss = 服务端策略漂移，继续跳纯烧钱）+ 建议重跑 `experiments/cache-ttl/`。
- TTL 宿主：config.toml（带 measured_at 与来源报告）；**自适应只告警建议、不自写 config**——改数必须人工审过留痕。
- **地面真值**：闭窗后主会话 jsonl 下一条 assistant 记录的实收 cacheRead（守望本来就在读文件，免费取得）。

### 3.4 "有意义节约"的证明（Q11/Q13）

- 事后策略对比：对每个已闭窗口（时长 d、前缀 S 已入账），并排算四策略成本——①不作为 ②心跳 ⌈d/τ⌉ 跳 ③放任+等待前 compact ④超时交接——实际策略标记；总体聚合"若全用最优可省 X"。
- 事前仿真（T41 即有）：report 基于 `window` 流水出"若心跳开启"仿真节——**证明先于实施**。
- 裁决门槛：≥30 个窗口或两周数据后再决定授权。

### 3.5 机制细节定案（2026-09-17 实现讨论补强）

**缓存机制前提**（实验 §2 已证）：按内容前缀组织的 KV 缓存，最长公共前缀匹配、逐 token 二值命中、命中刷新 TTL、**跨会话共享**（键是内容不是会话身份）——体外重放能续真会话的命，全靠这条。

**心跳请求的精确形状**：逐 token 复刻 `[system + tools + u1…uN]`——即会话最后一发真实请求的完整输入前缀；**不含末轮 assistant 输出**（那是上一发的输出，不属于其请求前缀；会话恢复首发为 `[…uN, aN, 新输入]`，可缓存前缀恰是 `[…uN]` 主干）。`max_tokens` 1–16，模型名与该会话一致（缓存按模型组织；max_tokens/temperature 不影响缓存键）。心跳回复 token 直接丢弃——它只延伸出无人使用的支链 `[…uN+回复]`，主干被读取刷新。**保活可行前提**：下一发的全部前缀内容已落 jsonl（悬空 tool_use 时下一发含未来内容、无法复刻）——与 T31 悬空检测天然对齐。

**自我续命风险（最险失败模式）**：若重构差一个 token，首跳 miss=**全价重付**（S×P_in）并写出一条只有后续心跳自己会命中的废缓存；会话恢复照旧 miss 再付全价——比不作为更亏。故：miss 即停跳的经济依据=第一跳 miss 本身就是一次全价重付。

**证明链三段式**：跳的 cacheRead 只证明"P_beat 活着"；唯一算数的是**地面真值**=闭窗后主会话自己首发的实收 cacheRead（回扫 jsonl 下一条 assistant usage——回填逻辑属执行器任务，T41 账本已留位）；对账矩阵按窗口算：

| 心跳 | 会话首发 | 判定 |
|---|---|---|
| HIT | HIT | 真保温：省 = S×(P_in−P_cache) − Σ跳 |
| HIT | MISS | **保真度失败（自我续命实锤）**→ 告警+停跳+重过 §5-5 门槛 |
| MISS | HIT | TTL 比实测长/时序问题 → 复测 |
| MISS | MISS | 保温中途被驱逐 → 告警+复测 |

**Q14 协议细化**：首跳必须在确定性命中窗内（≤10 min）对真实前缀发出——首跳的 HIT 只能来自与真前缀的匹配（自我续命的头一跳没有自己的缓存可命中）；后两跳验证存续；ratio≥0.85 同时挡住"只蹭到共享系统头"的部分命中假阳性。

**冲突面**：请求无状态+缓存内容寻址→并发心跳与会话互不损坏（浪费一跳的钱而已）；每会话单飞标志 + "主会话一有写入即停跳"把窗口收敛到秒级；重复触发最坏多付一跳（26 积分级），无正确性损伤；读档走稳定快照。

**保真度备胎**（Q14 不过时再议）：代理侧捕获一次真实报文、原样重放（字节级保真）——代价是动 CC Switch 或加旁路监听；不预设结论。

### 3.6 执行策略与并发定案（2026-09-17 第三轮盘问，本节 Q 编号为该轮编号）

**单会话时间轴**（GLM 例：T=10min、τ=8min、S=150k 时 auto 上限 cap=1428s≈23.8min）：

```
T0 ════ 主会话发出派活请求，缓存写好，存活钟开始走
        （守护进程用台账"该会话最后一次写入"近似 T0）
 ├ 0~8min   安静期（多数子代理几分钟即回，缓存必活，零花费）
 ├ 8min     第①跳——先过四道预检：全局开关开 / 窗口还开 / 台账无新写入 /
 │           前缀≥30k → 定格快照 → 体外重放 → 看实收：
 │           ≈S → 记账排下一跳；≈0（miss）→ 停 + 告警
 ├ 16min    第②跳（同一份快照、同样四道预检）
 ├ 24min    第③跳——仅当前缀 ≥216k（cap≥1440s）才存在；S=150k 到 16min
 │           后已达 cap，第②跳即末跳
 ══ 撞上以下四件事之一，立即永久停跳 ══
   A. 子代理全部返回（窗口闭，主会话自动复活）
   B. 主会话提前动了（在飞那跳记"白花"）
   C. miss → 停 + 告警（TTL 疑似漂移，建议复测，不自改配置）
   D. 到达等待上限（auto 或手动）→ 停，放任过期
 └ 停跳之后：主会话恢复付一次全款（GLM/150k ≈103 积分），有上界；
   S=150k 时最多 2 跳 ≈52.4 积分（cap=1428s<1440s，第③跳排不进；
   前缀 ≥216k 才容得下第③跳，渐近上界 cap→1468s、恒 ≤3 跳 ≈78.7 积分）
```

**首跳时机修正**：本节推翻 §2/§3.1 原定的"宽限期默认 5min"（实测前估数），定为**首跳 = T0+τ**。推演：5min 起跳使每个 5–8min 短等待白花一跳（26 积分），8min 起跳对长等待跳数不多一跳——严格占优。实现时同步修正 policy.py 的 `grace_s=300` 默认值。

**安全垫（"完成瞬间撞失效"问题）**：任意刷新后缓存至少还活 T−τ=2min，而子代理全回到主会话自动续跑只隔秒级——完成时刻永远落在安全垫内，**无需临场决策**，0.8 系数买的就是这个。真正裸奔仅两处且各有归属：等待超上限（设计如此，一次全款封顶）；主会话卡权限审批（人冷场泳道，归摆渡）。

**三泳道**（谁在等决定机制；心跳与摆渡**永不耦合**）：

| 谁在等 | 机制 | 动作 | 花费 |
|---|---|---|---|
| 机器等机器 | 心跳 | 安静 τ → 每 τ 一跳 → 四停之一 | GLM/150k ≤2 跳 ≈52 积分（前缀更大才到 3 跳） |
| 人不在场 | 摆渡+闸门 | 25min 总结 → 35min 拦截 → 归还 | handoff 科目 |
| 交界地带 | 自然交接棒 | 子代理活跃期间摆渡本就被推迟；心跳到上限自停后，人未回则闲置钟继续走向摆渡 | 两段各自封顶 |

明确否决：心跳决策路径中**永不出现**"跳几次→转摆渡→清空重来"分支——子代理等待自动恢复，交接成本（生成+新会话全款重建）高于一次缓存重算（实验报告 §5 已算），且子代理活跃期间摆渡本就推迟，两道无冲突可解。

**并发定案（Q1/Q2）**：
- 执行器=守护进程内调度线程，单例继承端口独占；不引入任何 OS 级锁。
- 服务商侧无需锁：缓存按内容寻址、并发读安全（实验已观测跨会话共享）。真实风险面全在本地：CC Switch 代理串行化（可能拖慢真实请求数秒）与心跳/子代理共享限流——均列入 §5-5 L3 探针。
- 单飞纪律：每会话同时最多一跳在飞，上一跳完成并记账后才排下一跳。
- 撞车四场景：①双方在飞、缓存活 → 各读各的，beat 白花 ~26 积分；②beat 在飞时会话恢复 → 同前；③缓存死+双方同刻 → 主会话本就付全价，beat 增量 ~103 积分且 miss 即停；④重复跳（bug）→ 单飞防住。**损失上界 = 一跳**。
- 不变式：beat 永远走会话同路由（路由不可知→不跳，兼作隐私不变量）；429/网络错退避跳过；**miss 绝不重试**（重试=给自己续命，§3.5）。

**前缀快照（Q3）**：首跳前用稳定快照机制（复用摆渡"两次读到相同偏移+哈希才接受"）定格一份，整窗重放同一字节；恢复的真实请求=快照+小尾部，命中主体不受影响，尾部付小钱。

**等待上限旋钮（Q5 修订/Q11）**：每服务商+每会话现算（价格表三价+实测 TTL+当前前缀大小，公式见 §2）。默认 `auto`；手动只能往下收；往上截断回 auto 并提示。到上限：停跳、记无效保温、窗口保持开等子代理、不再花钱。

**测试分层（Q4）**：L1 离线 pytest+fake provider（请求形状、状态机全转移含"闭窗时一跳在飞"竞态、记账行、429 退避、miss 不重试）＝**合并门槛**；L2 保真度（=§5-5 Q14）+ L3 并发探针（beat+resume 同发、双 beat、CC Switch 并发、daemon 重启、429 共存）＝**启用门槛**。代码可先合，默认 off。

**运维定案（Q7–Q10）**：
- 每服务商一格实测寿命 `[heartbeat.<provider>] ttl_s / ttl_measured_at`；无格子的服务商不跳。
- 一键停=全局开关，立即生效不重启；状态（谁在跳/跳几次/花了多少）并入现有状态查询。
- beat 流水带"白花"标注；report 可算纯浪费与有效率。
- miss 告警：日志+状态标红+report 单列；不做系统弹窗。

**事前提示（Q13 修订）**：默认关；可配置"派活子代理很多+前缀很大"时 hook 提示风险、问是否先压缩；能否真拦住列调研（PreToolUse 否决 Task、否决后回环行为、Codex 对等性）。"默认不拦、只提示"基调不变。

### 3.7 时间线查看器与反跑（Q14 修订–Q20）

- **形态**：常备只读查看器，Go 后端 + web 前端（见 ADR-0003）。打开 → 会话列表（时间/标题/工作目录）→ 单会话时序图；事后随时回看。
- **图元**：每次请求一根柱分段上色（绿=缓存命中 / 红=新输入全价 / 蓝=输出）；事件标记（子代理派活/返回箭头、心跳圆点——点高=实收命中量、handoff 旗、闸门叉/归还箭）；等待窗口背景带；缓存存活倒计时淡出阴影（安全垫宽度一眼可见）；心跳预测 vs 实收标注。**永不渲染消息内容**（隐私红线）。
- **回放**：拖时间游标，画面只显示游标前的事件与累计花费。
- **反跑**：选历史等待窗口 → 参数面板（价格/寿命/τ 系数/上限/首跳时机）→ 同一套策略公式按该窗口真实时长与前缀大小现算三线对比：若当时这样配 vs 实际发生 vs 什么都不做。直接服务于 §3.4 事后策略对比与 §5-4 窗口审查。
- **用量落库（数据地基）**：守望增量尾读会话文件，把每条助手记录的用量落账（时间/会话/族系/项目/输入/命中/新建/输出/模型名）+ 当时最新标题。动机：会话文件 30 天清理，不落库则事后回顾与**地面真值**（窗口后首发实收命中）俱失；存标题先例=交接库。隐私：只数字与类型，零消息内容。
- **调度洞察**：用量落库先以 Python 小补丁落地（迁移数周间数据钟先走——≥30 窗口/两周的数据门槛在关键路径上）；查看器为 Go 滩头。

### 3.8 Go 迁移与实施顺序（Q25–Q28）

全文见 ADR-0003。顺序：用量落库（Python 小补丁）→ Go 查看器（滩头）→ Go 守护核心（守望/闸门/台账/交接库/账本，以现有 164 测试为规格移植）→ Go 摆渡执行器 → observe 烧机切换 → 心跳执行器（原生 Go，Python 中从未实现；授权铁律不变：数据门槛+保真实验+用户明确放行）。钩子自举：多合一子命令 exe；守护活→毫秒转发；不活→照旧放行（fail-open 不动）+后台无窗口拉起 serve。

### 4.1 末段定格（2026-09-18 定案）

**问题**：交接对"会话最后在干什么"无结构保证——骨架逐字部分只有文件与命令（无消息内容），模型叙事靠自觉（质量侥幸非契约）；实测 20260918 晨间交接的骨架"最后 5 条命令"取的竟是数小时前的命令（末段保真当场失守，提取器取段逻辑待修）。

**定案**：骨架新增确定性"末段定格"节——保留最后一轮完整对话，三档规则：

| 末条形态 | 处理 |
|---|---|
| 普通文本 | 逐字：用户末条 ≤500 字、助手末条 ≤1500 字，超长尾部截断标注"（已截断，全文见会话文件）" |
| **待选择交互**（AskUserQuestion / 选项列表收尾） | **确定性提取**：问题一句话 + 选项标签纯文本列表，标注"（上次停在选择，原文见会话文件）"；**续接第一句话=重述该选择** |
| 工具调用/结构化片段 | 摘要（工具名+一句话），永不逐字倒 JSON/交互原文 |

位置：INJECT 层最前（先"当时在干什么"再整体战况），全文保留。防注入由既有"不可信摘录"框架覆盖。理由：确定性问题用确定性手段；待选择恰是用户最需一眼接上的时刻，不赌模型自觉；选项本就在结构化 JSON 里，提取零模型成本。
