## 方法

编排器 `experiments/beat-fidelity/q14s3.py`（可复跑）：

1. 转发器 15722→15721（复用 `experiments/capture`，SSE 冲刷已修），捕获落 `~/ferryman/captures-q14s3/`（本地永不入库）
2. 3 个独立臂：`%TEMP%\q14-arm1..3` 项目级 settings 覆盖路由，各跑一发 `claude -p "只回复两个字：收到"` 造真实前缀；T0=转发器收包时刻（17:42:58 / 17:43:24 / 17:43:49）

4. T0+1500s 地面真值：同目录 `claude -p --continue` 续跑，读会话 jsonl assistant usage

## 花费（实付）

创建 3×（input 22642/17842/22962，含共享前缀命中 1024/5824/704）＋心跳 9×（cr 23616+in 50）＋真值 3×（cr 23616+in 74）＋预检 1 发微请求。合计 input≈64.1k、cache_read≈290.9k、output≈0.4k，**按方案价格折算 ≈93 积分**（在 100–120 预算内；编排器打印的 109.3 因 jsonl 逐块 usage 重复计数偏高，作废）。造臂本身 ≈43 积分——原方案设想用现成真实会话闲置当臂，本次用合成会话代替，属预算外新增，已如实计入。

## 偏差如实声明

- **前缀 23.6k < 方案目标的 41k+**：命中判据与体积无关；如需大前缀复测，改 `--prompt` 造更大目录即可
- **单轮形状**：捕获的是会话第一发 [system+tools+u1]。路线 B 按构造覆盖任意轮次——生产重放的就是该会话真实最后请求，多轮序列化形状无需复刻（这正是弃 A 选 B 的原因）
- **无 no-beat 对照臂**：TTL≈600s 已由 0917 实测定案，矩阵判定不需要对照组
- 首跳晚点全部 0.0s；beat 延迟 3.8–13.8s（GLM 侧）

## 工程雷（发射前修复，留档）

1. 捕获里 `Authorization`/`X-Api-Key` 均被转发器脱敏（值含 `…`），urllib 按 latin-1 编码头值即炸——重放头部须跳过脱敏对并重建 `PROXY_MANAGED` 字面量
2. **GLM 的 SSE 把真实 usage 放 `message_delta`，`message_start` 全 0**——合并时必须覆盖而非 setdefault，否则每跳必被误判 miss
3. 事件调度器混合元组解包会在首个事件处崩溃（py_compile 查不出，预检+走查抓出）
