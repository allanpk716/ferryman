# 自建 CC 专用最小路由器（替代 cc-switch 的 Claude 链路）评估

- **日期**：2026-09-19（源码级评估：cc-switch main 分支 `src-tauri/src/proxy/` + 本机实测行为）
- **问题**：Ferryman 心跳架构（ADR-0007 透传+内存快照）已把 daemon 放进 CC 流量路径——既然如此，是否干脆自建一个只服务 Claude Code 的最小路由器，退役 cc-switch 的 Claude 链路？
- **结论**：**做，且与 ADR-0007 合并成同一条路**。cc-switch 全仓约 1.9MB Rust（proxy 模块 900KB + providers 转换层 1.9MB 里的大头），但本机 Claude→GLM 链路**实际生效的改写只有 4 件**，Go 复刻约 500 行；其余 90% 是与本链路无关的多协议网关产品面。自建后 beat 与真流量走过**同一份改写**，缓存键全链路自洽，第三方漂移风险（"重放正确却 miss"）这一类直接消失。

## 3. 形态：并进 ferryman.exe，一个端口三层职责

```
CC ──▶ ferryman daemon :PORT ──▶ GLM (open.bigmodel.cn/api/anthropic)
         ├─ 路由层：model 映射＋[1M] 剥离＋真钥注入＋media 降级（本评估新增）
         ├─ 快照层：内存留每会话最后一份请求体（ADR-0007 原样）
         └─ 心跳层：快照原样重放 max_tokens=1（Q14 已验证）
```

关键收益：**beat 重放的请求与真实流量走同一份改写代码**——自己改写自己重放，缓存键永远自洽。原架构里"cc-switch 改写行为漂了导致重放 miss"的风险类别整体消失（ADR-0007 设的复审触发器不再需要）。

config 草案（T39 隐私规矩：真钥只活本机 config.toml，永不入库）：

```toml
[router]                    # CC 专用路由（替代 cc-switch Claude 链路）
listen = "127.0.0.1:15722"  # 端口待定
[router.provider.glm]
base_url = "https://open.bigmodel.cn/api/anthropic"
auth_token = "…"            # 真钥，从 cc-switch.db providers 抄一次
text_only = true            # media 降级开关
[router.provider.glm.models]
opus = "GLM-5.3[1M]"        # 与现 cc-switch「GLM Coding」档位一一对应
fable = "GLM-5.3[1M]"
sonnet = "glm-5.3-flash[1M]"
haiku = "glm-5.3-flash"
default = "glm-5.3-flash[1M]"
subagent = "glm-5.3-flash[1M]"
```

## 3a. 两层配置的澄清（2026-09-19 复查补）

模型名相关配置存在**两层**，职责不同，别混：

**CC 侧（`~/.claude/settings.json` env，自建后冻结不动）**：
- `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU,FABLE}_MODEL`＝别名表（claude-opus-5[1M] 等）——决定 CC 往请求里**发什么名字**，router 不碰
- `CLAUDE_CODE_SUBAGENT_MODEL`＝子代理名——现值是**真名** `glm-5.3-flash[1M]`（cc-switch 接管时代的残留），CC 直发此名；mapper 的精确匹配保留分支（剥 [1M] 后相等→原样保留，`model_mapper.rs:99-104`）就是为这种非别名直发兜底的。自建后可以保持现状（subagent 配置项对齐即可），也可以将来规范回别名
- `ANTHROPIC_DEFAULT_*_MODEL_NAME`＝展示/计量名（GLM-5.3 等）——纯 UI/计费显示，不进请求体

**Provider 侧（router config，切供应商只动这里）**：
- 六键映射表：opus/fable/sonnet/haiku/default(ANTHROPIC_MODEL)/subagent——`model_mapper.rs:21-56` 逐键对应
- 兜底顺序：档位 contains 匹配 → fable 未配归 opus → 子代理精确保留 → default → 原样透传
- 上游 base_url、真钥、text_only 名单

切换供应商时 CC 侧别名层无需改动（claude-* 照发，router 换映射表）——比 cc-switch 的 settings.json 接管/还原机制（`proxy_live_backup` 那套）更干净；只有展示名 `_MODEL_NAME` 属于"不改也能用，改了显示准"。

**1M 上下文的两半**：① `[1M]` 后缀在 model 名里——router 剥（映射后仍带则再剥）；② 1M 激活信号在 `anthropic-beta` 头（`context-1m-2025-08-07`）——随 beta 重建规则保留（见生效清单 #6）。两半都在 router 改写路径内，beat 重放走同一路径，自洽。

## 4. 迁移路径（三步，每步可回退、可用 Q14 验证）

1. **透传版**：daemon 起 15722→15721（上游仍指 cc-switch），快照+心跳上线——即 ADR-0007 原样，零改写。
2. **改写版**：实现四件改写，上游从 cc-switch 切到 GLM 直连；`q14s3.py` 原样重跑（对账矩阵即回归测试）。
3. **退役**：cc-switch 从 Claude 链路摘除（可保留安装做 Codex 等其他轨道，或整体退役）；CC 的 settings.json 由我们接管（就一行 base_url，本来就要写）。

## 5. 失去什么（如实）

- **GUI 供应商切换**：cc-switch 的核心产品面。单供应商期无感；"以后用其他的"时加 config 或面板按钮（数据结构已按 provider 表设计）。
- **failover/熔断**：多供应商热切换才需要，后置。
- **cc-switch 的 usage 面板**：Ferryman 账本＋时间线查看器已覆盖且更细（四列口径+对账）。
- **别人修 bug**：改写正确性变成自己的责任——但受益是对称的（见 §3），且错映射的信号明确（上游 4xx／Q14 类 miss），可用测试钉死。

## 6. 工作量与风险

- **代码量**：核心 ~550-700 行 Go（映射 80＋剥缀 15＋换钥与出站头卫生/beta 重建 70＋media 降级 100＋listener/透传复用 forwarder.go＋config）＋测试 ~300 行（映射矩阵、[1M] 边界、beta 重建、text-only 降级、SSE 透传）。**1-2 张票**。
- **风险**：①media 降级语义必须抄对——今天你 CC 里的图片就是被换成标记的（GLM-5.3 text-only 名单），行为对齐即可，别"顺手优化"；②上游 API 行为变化（GLM anthropic 端点）——cc-switch 同样暴露，且我们只依赖最基本面；③daemon 单点——透传方案固有，不变（独立 handler 路径＋看门＋base_url 秒回退 15721）。

## 7. 与既有决策的关系

- ADR-0006（双泳道心跳+Q14 门槛）：不变，Q14 已过。
- ADR-0007（捕获重放）：步骤 1 原样保留；步骤 2 把"上游=cc-switch"升级为"上游=GLM 直连＋自持改写"，作为其延伸而非推翻——届时补一段补记或新 ADR。
- 闸门/摆渡/账本：零改动。
