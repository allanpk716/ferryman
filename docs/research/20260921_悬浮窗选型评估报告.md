# Ferryman 用量悬浮窗 · 技术选型评估报告

> 日期：2026-09-21 ｜ 性质：**调研评估，非开发授权**
> 依据：串行 5 项调研（Ferryman 盘点 / AntFeedingLog 盘点 / 框架联网对比 / 余量 API 联网 / 汇总窗先例），原始笔记见同目录 `20260921_悬浮窗选型调研_笔记.md`
> 前提：服务商宇宙以开发中的渡口多上游 spec（`docs/superpowers/specs/20260921-渡口多上游直连-spec.md`，worktree `不同LLM供应商`）为准，**不按本 worktree 现状代码评估**

## 一、结论（先说答案）

**推荐 A 案：Wails v3（beta）以 library 模式做进 Ferryman 本体，悬浮窗是 `ferryman serve` 的第三个窗口形态（面板 15900 之外多一个置顶小窗）。** 备选 B 案：独立 Tauri 2 子项目（AntFeedingLog 全套样板可抄）。两案都不需要为"余额查询"单独开子项目——查询器做成 Ferryman 内的每上游一个解析器即可，数据消费者（悬浮窗）不必独立于 Ferryman，因为 **token 级用量只有 Ferryman 台账能出**。

三条硬事实支撑这个结论：

1. **没有任何服务商提供 token 级周/月用量 API**（五家全查过）——"用了多少"这列数据只能来自本地台账，悬浮窗与 Ferryman 数据面天然强耦合，独立出去反而要跨进程搬数据。
2. **余量/窗口百分比基本都能查**（智谱 5h+周、Kimi 最全、Claude 订阅有半公开端点、DeepSeek/中转只有余额）——但每家端点形状、鉴权、解析坑都不同，天然是"每上游一个解析器"的集合，属于渡口上游表 `balance_url` 思路的扩展（spec 票 03 只做了 active 单条，全量显示是悬浮窗侧的新增面）。
3. **WebView2 系在 Windows 上"透明背景+点击穿透"兼得做不到**（Wails #6088 open；Tauri 只能整窗穿透）——但常驻用量面板不需要穿透（点上去看详情反而是需求），此坑不阻塞。

## 二、需求拆解（悬浮窗要显示什么）

按用户原话 + 中午补充：

| 信息类别 | 内容 | 数据来源（调研实证） |
|---|---|---|
| 每个已添加上游的余量 | 5h 窗剩余、周用量、月度用量 | 查询（智谱/Kimi/Claude）+ 本地推算（见下表） |
| 两类供应商分开 | 渡口上游表（CC 腿，Anthropic 协议）+ 摆渡供应商表（OpenAI 协议，独立） | 渡口多上游 spec 已定义两张表分立 |
| 全部已配置条目 | "每一个我添加过的"——不只 active 那条 | 需悬浮窗侧逐条查（spec 只保证 active 余额行进 /stats） |

**谁查得出什么**（Agent④ 实证总表，细节见笔记"发现四"）：

| 上游 | 5h 窗剩余 | 周用量 | 月度用量 | 余额 |
|---|---|---|---|---|
| 智谱 CodingPlan | ✅ %+倒计时 | ✅ % | ❌→本地推算 | ✅ |
| Kimi Coding | ✅ 含 resetTime | ✅ | ⚠️ 月度池要网页凭证 | ✅ 加油包 |
| DeepSeek 按量 | 无此概念 | ❌→本地推算 | ❌→本地推算 | ✅ |
| Claude 订阅 | ✅ 半公开端点 | ✅ % | ❌→本地推算 | ✅ extra_usage |
| 中转站 | 无此概念 | 面板累计 | 面板累计 | ✅ |

**本地推算的底子在但维度缺**：四列 token 全量流水在账本（accounts/YYYYMM.jsonl），月聚合已有（/report scope=month）；**5h 滚动窗、周聚合代码里没有，需新增**——这是悬浮窗数据面的主要开发量，且无论选哪个框架都躲不开（属 Ferryman 侧工作）。

## 三、技术路线对比（三案）

### A 案（推荐）：Wails v3 library 模式挂进 Ferryman exe

- **为什么顺**：v3 官方定位就是"给现有 Go 程序加前端"；AssetServer 直接吃 embed.FS——现有 vanilla WebUI 技术栈零切换；托盘可与 getlantern 共存（wails#1521 先例）或迁 v3 原生托盘；单 exe 不新增常驻进程；工具链仍是 Go+Node，构建秒-分钟级。
- **悬浮窗能力**：AlwaysOnTop / Frameless / BackgroundType.Translucent / --wails-draggable / 多窗口全有；启动白闪用 visible:false 先载后显（符合本仓"零闪窗铁律"）。
- **代价与风险**：v3 是 beta（2026-08 进 Beta，beta.24，需锁 tag 接受升级节奏）；**#6088：透明+穿透互斥**（本场景不需要穿透，可接受）；自启/自动更新无官方方案（自启可走计划任务/注册表，Ferryman 已有 Run 键自启先例可复用）。
- **内存口径**：Go 侧 ~10MB + WebView2 进程树（空闲 <100MB，每 webview 实例 20-30MB）——注意悬浮小窗+设置窗若各开一个 webview，是两份实例开销。

### B 案（备选）：独立 Tauri 2 子项目

- **为什么仍值得列**：2.11.6 稳定线；悬浮窗全家桶最齐（含 set_ignore_cursor_events 整窗穿透）；**AntFeedingLog 就是现成参考实现**——托盘/自启/单实例/自动更新/axum+SSE 通信全是可照抄的样板，且其 ADR-0001 已论证过弃 Electron 的内存账。
- **代价**：Rust 双栈（MSVC+VS C+++Node，首编 5-15 分钟）；悬浮窗与 Ferryman daemon 跨进程通信（HTTP+SSE，AntFeedingLog 的 axum 样板反过来用）；两份托盘两个常驻进程。
- **适用条件**：若你把"统一汇总窗"远景看得很重、想让它独立演进不被 Ferryman 的发布节奏绑死，B 案的独立性是真实收益。

### C 案（兜底/过渡）：零框架

- Rainmeter 皮肤定时 GET Ferryman 的 JSON 端点（TrafficMonitor/Rainmeter 先例）；或任何窗口 + PowerToys Always On Top 手动钉住。**一周内想看到数字选这个**，交互弱，不满足远景。

### 出局项

- **Electron**：常驻 93-180MB + 安装包 150MB+，Q5 红线下出局（唯一优势"穿透配方最成熟"本场景用不上）。
- **Fyne**：Windows 透明无内置、HTML 零复用=界面全重写，无收益。
- **WPF/WinUI 3**：能力天花板但 .NET 独立栈零复用；WinUI 3 窗口基础问题多年未清。
- **Wails v2**：已进维护模式，单窗口写死，不考虑。

## 四、数据面架构（两案通用）

1. **余量查询器**：Ferryman 内 `每上游一个解析器`（智谱/Kimi/Claude/中转形状全不同，全为"未文档化但稳定"——解析要宽容，盯 cc-switch 参考实现，仓库纪律已立）。Claude 订阅行用本机 CC OAuth 凭据，**轮询 ≥3 分钟 + token 刷新 + 缓存兜底**（过期 token 去调会被 429 封 1 小时）。
2. **本地推算**：台账加 5h 滚动窗/周聚合维度（月已有）；估算值在 UI 上必须标注"估算"，不与查询值混排（Round 1 Q1 推荐，待确认）。
3. **悬浮窗 ↔ 数据面**：读 daemon HTTP（127.0.0.1:7311，Bearer token 现成）；A 案进程内直连亦可。
4. **刷新节奏**：本地台账准实时；远端余额/配额 5-15 分钟轮询（各家限流差异，Claude 最严）。

## 五、统一汇总窗远景（架构留什么口）

先例结论：Windows 上该品类无完整先例，按零件拼——TrafficMonitor（壳）/ ntfy·HA 事件总线（协议）/ ClaudeBar（首个面板内容）。若 v1 按此设计，将来自动获得多程序接入能力：

- **协议**：各程序 POST `localhost:PORT/v1/state`（JSON，带静态 token）+ 周期心跳，汇总端超时判 stale（ntfy/MQTT LWT 语义）。
- **两张表**：current state（每生产者一条，覆盖写）+ event log（环形缓冲）——悬浮窗常驻区渲染前者、展开区渲染后者（Home Assistant 教科书分法）。
- **前端订阅**：SSE（EventSource 断线自动重连，AntFeedingLog 同款模式）。
- **Toast 分工**：高优先级事件才弹系统 Toast（beeep），常驻数据不进 Toast。
- v1 只做用量面板，但壳按"数据源可插拔"设计（Round 1 Q4 推荐，待确认）——A/B 两案都能承载（前端反正都是网页技术）。

## 六、风险清单

| 风险 | 等级 | 缓解 |
|---|---|---|
| Wails v3 是 beta（A 案） | 中 | 锁 beta tag；B 案保底；C 案兜底 |
| 透明+穿透互斥（WebView2 系通病） | 低（本场景不需要穿透） | 若将来要穿透：整窗穿透+动态切换（Tauri 模式）或等 #6088 |
| 各家配额端点形状漂移（智谱 2026 年中刚改过 type 名） | 中 | 解析器宽容+单测夹具；盯 cc-switch |
| Claude OAuth 端点限流/封禁 | 中 | ≥3 分钟轮询+token 刷新+缓存；不做就退本地推算 |
| 渡口多上游 spec 在开发中，配置形状可能再变 | 中 | 悬浮窗读 spec 收敛稿的表结构；等该 worktree 合并后再动工数据面接线 |
| 启动白闪违反零闪窗铁律 | 低 | visible:false 先载后显（既定解法） |
| 多 webview 实例内存翻倍 | 低 | 悬浮窗+设置窗共用一个 webview 或设置窗按需开 |

## 七、决策记录（全部关闭，2026-09-21）

1. **选 B 案：独立 Tauri 2 子项目**（Wails v3 挂本体方案弃）。
2. **服务商范围 = 三家**：GLM CodingPlan、Kimi Coding Plan、DeepSeek 官方 API（Claude 订阅行不做；中转站暂不涉及）。
3. **架构分工**：费用/余量数据的**获取统一由主程序（Ferryman）做**；悬浮窗**纯读消费**，后续独立开发。
4. **通信契约**：主程序新增只读聚合端点（如 `GET /widget/summary`）一次给齐；本地用量秒级、远端余量 5-15 分钟（缓存单源在主程序侧）。
5. **仓库形态**：monorepo——本仓 `widget/` 子目录，非独立仓库（用户裁定：契约早期反复，跨仓协调成本高）。三条件：①自带 Cargo/package/CI（路径过滤），工具链不进主构建；②widget 永不 import Go 代码只认 HTTP 契约；③拆分出口 `git subtree split widget/` 写明。
6. **壳行为包**：托盘常驻+右键菜单、不出现在任务栏、置顶、无边框、可拖、点击展开、开机自启、单实例；v1 仅用量数据源但前端按可插拔留结构；无穿透、无贴边收起。
7. **节奏**：悬浮窗壳先行（Tauri 骨架+mock+设计稿）；数据面（查询器+5h/周聚合）等渡口多上游 worktree 合并后立项。
8. **落档**：ADR-0012 已立（`docs/adr/0012-widget-tauri-subproject-quota-in-core.md`）；CONTEXT.md 新增"用量悬浮窗"节（悬浮窗/悬浮窗发布线/聚合端点/余量查询器/查询值/估算值）。
9. **独立升级线**（2026-09-21 补定）：升级查询与自升级完全在 widget 内（Tauri updater + GitHub Releases 签名 latest.json，样板=AntFeedingLog `docs/release.md`），独立 tag 独立发版，与主程序发布通道（ADR-0010）互不牵动；聚合端点契约带版本号字段，widget 对未知字段向前兼容。
10. **UI 与契约设计定稿**（2026-09-21 Round 3，8 问全裁）：每上游一个**圆控件**，环=剩余制（蓝 5h/橙 周/紫 月预算/绿 DS 预算；<20% 黄、<10% 红）；月度无官方分母→文字计数起步、自设月预算后补为可选环；DeepSeek 圆心 ¥余额+底部今/周花费（估）；默认竖排贴右缘可切横排、位置记忆、托盘收起；**显示配置全在 widget 侧**（daemon 无状态返回全部上游）；契约分组 `upstreams[]`+`handoff{}`；刷新=30s 轮询+恢复可见即拉。三家真实返回结构以 cc-switch 源码实证（笔记"发现六"：智谱裸 key+percentage=已用%且无绝对值、Kimi 绝对值口径漂移、DeepSeek 字符串金额）。HTML mock：`docs/research/20260921_悬浮窗mock.html`。
11. **重置倒计时行**（2026-09-21 补定）：5h/周窗距重置剩余时间常驻于圆控件下方第一行（`●2h28m · ●2d14h` 式），颜色随所属环、告警同步变色加粗；由契约 `resets_at`（ISO）本地推算、逐分钟刷新，零新增查询；显示开关归显示配置；DeepSeek/摆渡无窗口不显示。

### DeepSeek 口径注记

DeepSeek 官方无 usage API，只有 `/user/balance`（is_available + 三金额）——其"用量/费用"为台账本地口径（估算值），UI 需与 GLM/Kimi 的官方查询值区分标注。

## 八、ADR 草稿（待你确认后立为 0012）

- 备选：A 案 Wails v3 挂本体（被弃：beta 风险+主 exe 纯度）；C 案 Rainmeter（过渡兜底）。
