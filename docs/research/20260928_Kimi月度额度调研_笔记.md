# Kimi 月度额度体系调研笔记

- 调研日：2026-09-28（真机抓包同日，笔记落盘 09-29）
- 触发：悬浮窗要给 Kimi 补「月度」档。用户问题：网页端可见「月度总额度」（Coding 消耗一块 + 网页/App 消耗一块），如何正确拿到这个完整月度总量。
- 证据等级：**[官方]** = 官方文档/官方论坛原文；**[社区]** = GitHub issue/源码/linux.do 等，附来源；**[推断]** = 基于多处证据的判断。Kimi 额度体系换代快（见 §1 拆分风波），本笔记有效期以 Kimi 改版为限。

## 0. 一句话结论

Kimi 会员是一个**共享月度额度池**——网页/App、Kimi Code、Kimi Work 同池按 token 扣，Code 是被官方单独计量的一块；**但官方任何渠道只给百分比，不给绝对总量**。用 Coding API key 能否拿到月度字段随套餐而变：本机账号（老套餐，响应带 7 天窗）今天拿不到；新套餐（Go/Plus/Pro/Max，取消周窗）能拿到 `limit_month_total`/`limit_month_code`。

## 1. 额度池结构：一个池，Code 是被单独计量的子块

- 现行体系（存量老套餐与新套餐均如此）**[官方多处]**：所有会员功能（K3 对话、Kimi Code、Kimi Work、Agent 等）从同一个**月度池**按 token 扣。Kimi Code 额外叠加 5 小时滚动窗 +（老套餐）7 天窗；子窗打满只冻 Code，月池打满全部冻结。
- 网页端「月度总额度」页（设置 → 订阅 → 额度，`kimi.com/membership/subscription?tab=quota`）显示：总额度百分比、下次刷新时间、最近约 1000 条逐笔明细（按功能分类 CODING/CHAT/AGENT/SLIDES/DEEP_RESEARCH…）。
- 「总量 − 其中 Coding」与官方数据模型吻合：GetSubscriptionStats 给 `amountUsedRatio`（月池已用比）+ `kimiCodeUsedRatio`（其中 Code 占比）**[社区，源码级]**。
- **绝对量不存在公开口径** **[官方]**：官方不公布各档月池的绝对 token 数或金额，网页也只显示百分比。社区数字（如 Moderato≈108M tokens）全是估算。要绝对值只能本地校准估算并标注——本仓纪律「宁可缺失不错标」，默认不做。
- **演进风险** **[社区]**：2026-07-19 官方曾宣布把会员拆成「通用会员 + Coding 会员」两个独立 SKU，约 12 小时因骂声下架；后以「改名不拆分」落地（Go/Plus/Pro/Max，价格不变）；已有新套餐用户看到「编码与办公额度拆开」的界面（linux.do/t/2651863）。**建模必须把总池与 Code 子块分开留位，不能焊死「一个池」。**

## 2. 档位与 API（2026-09 时点）

- **老套餐（存量用户在此体系）** **[官方帮助中心]**：Andante ¥49 / Moderato ¥99 / Allegretto ¥199 / Allegro ¥699（月付，年付折至 ¥39–559/月；均含 Kimi Code，Allegretto 起含 K3 与 1M/高速版；另有免费档 Adagio）。
- **新套餐（改名不拆分）** **[官方 Kimi Code 文档]**：Go ¥49（**无 coding 额度**）/ Plus ¥99 / Pro ¥199 / Max ¥699。**新套餐取消每周额度窗，只保留 5h 窗 + 月总额度**；K3/1M 门槛变为 Plus/Pro 起。
- 国际站 kimi.ai 为完全独立体系（Moderato $19 / Allegretto $39 / Allegro $99 / Vivace $199）**[官方]**。
- 计量：按实际 token 消耗扣池，非次数制（2026-01-28 起 Code 从次数制切 token）**[社区，注意时效]**。
- API：订阅 base URL = `https://api.kimi.com/coding`（Anthropic 兼容）/ `https://api.kimi.com/coding/v1`（OpenAI 兼容），国际站 `api.kimi.ai` **[官方文档]**。开放平台按量付费是另一套账号（`api.moonshot.cn` / platform.kimi.com），key（`sk-xxx`）与订阅 key（`sk-kimi-xxx`）不互通，混用 401。
- 模型 4 个 **[官方]**：`k3`（1M）、`k3-256k`、`kimi-for-coding`（已升级为 K2.8 Preview，1M）、`kimi-for-coding-highspeed`（K2.7 Code 高速版，约 5-6 倍速、约 3 倍额度消耗，Pro 起）。

## 3. key 通道：`GET https://api.kimi.com/coding/v1/usages`

- 鉴权 `Authorization: Bearer sk-kimi-xxx`；官方论坛称之为「实验性端点」**[官方论坛]**；cc-switch 生产在用（其 `coding_plan.rs` 已核实同款端点）。
- **本机真机响应（2026-09-28 抓包，老套餐，完整未删）**：

```json
{
  "usage": { "limit": "100", "used": "3", "remaining": "97", "resetTime": "2026-10-05T01:36:13.682097Z" },
  "limits": [ { "window": { "duration": 300, "timeUnit": "TIME_UNIT_MINUTE" },
               "detail": { "limit": "100", "used": "1", "remaining": "99", "resetTime": "2026-09-28T13:36:13.682097Z" } } ],
  "usages": { "limit_5h": { "used_ratio": 0.012443, "reset_time": "2026-09-28T13:36:12Z" },
              "limit_7d": { "used_ratio": 0.025041, "reset_time": "2026-10-05T01:36:12Z" } }
}
```

- 字段口径：顶层 `usage` = 7 天窗，`limits[0].detail` = 5h 窗，`usages`（复数）= 同两窗的比率版。`limit/used/remaining` 是**内部额度单位非 token**；limit=100 即百分比口径（本仓 `kimi.go` 已有 HasAbs 防御）。
- **字段集合随套餐漂移** **[社区，多份 2026-09 实测样本交叉]**：老套餐回 5h+7d；新套餐回 5h + `limit_month_total`（月池已用比）+ `limit_month_code`（月内 Code 已用比）+ 各自 `reset_time`；部分账号另有 `boosterWallet`（加油包钱包）。解析纪律：**有什么读什么，别假设键存在**。新套餐样本（CodexBar #3694 等）：

```json
"usages": { "limit_5h": { "used_ratio": 0.086628, "reset_time": "…" },
            "limit_7d": { "used_ratio": 0.171279, "reset_time": "…" },
            "limit_month_total": { "used_ratio": 0.0338, "reset_time": "2026-10-15T07:49:10Z" },
            "limit_month_code":  { "used_ratio": 0.0,     "reset_time": "2026-10-15T07:49:10Z" } }
```

- 已知坑 **[社区]**：① `usage`（单数）与 `usages`（复数）可能互相矛盾；部分账号 `used_ratio` 长期为 0 的服务端 bug（MoonshotAI/kimi-code #3908/#3951）——两套都读、`reset_time` 已过期者不采信。② 端点持续演进：早年无月度字段，2026-09 已实测出现（#4046 追踪）。
- `GET api.moonshot.cn/v1/users/me/balance` **与订阅额度无关** **[官方]**：开放平台（按量付费）的现金余额接口，`sk-kimi-` key 调它 401。悬浮窗不得用它做 Kimi 订阅额度。（09-21 选型笔记的否定结论维持。）

## 4. 网页端背后：Connect RPC（非公开、随改版易碎）

**[社区，2026-07 从前端代码确认 + 罗盘源码核实]** 协议 JSON over POST，Base `https://www.kimi.com/apiv2`，鉴权 `authorization: Bearer <access_token>`（取自登录态页面的 localStorage，另有 httpOnly cookie），未登录 401：

| 端点（apiv2 下） | body | 关键响应字段 |
|---|---|---|
| `kimi.gateway.membership.v2.MembershipService/GetSubscriptionStats` | 空 | `subscriptionBalance.amountUsedRatio`（月池已用比）、`.kimiCodeUsedRatio`（其中 Code 占比）、`ratelimitCode5h/7d.ratio`（Code 5h/7d 窗比例） |
| `…MembershipService/GetSubscription` | 空 | `subscription.currentStartTime`（当前计费周期起点，可推刷新时间） |
| `…MembershipService/ListBalanceActions` | `{"pageSize":200}` | `actions[]`：`feature`/`title`/`timestamp`/`items[0].amountRatio`（该笔占月池比例；实际单次约回 20 条） |
| `kimi.gateway.billing.v1.BillingService/GetUsages` | `{"scope":["FEATURE_CODING"]}` | Code 窗口计数 `usages[]` + `totalQuota` |

- 限制：官方不返回逐请求 token 数、不返回月池绝对金额；一切绝对值均为社区校准估算（如罗盘默认月池 PAYG 等价 ¥1600，纯估算）。
- token 会过期（有效期未知，需实测）；过期需从浏览器重新导出。
- 最脆兜底：无头浏览器带登录态抓订阅页 DOM（`kimi-quota-monitor`、`opencli kimi usage` 路线），不建议主链。

## 5. 重置规则

**[官方]** 月池按**订阅日**刷新（如每月 1 日 15:00 开通则每月 1 日 15:00 刷新），与自然月无关；当期额度到期清零、不结转。Code 老会员另有以订阅日 D1 为起点的 7 天周期额度 + 5h 滚动窗；新会员取消周窗只留 5h + 月池。加油包（Extra Usage）：月池扣完后按量扣钱包，网页端与 Kimi Code **共用**同一加油包余额，人民币计价。

## 6. 与本仓现状对账（2026-09-28 考古）

- 数据面：`KimiQuota{FiveHour, Week}` 无月字段（`internal/quota/quota.go:94-97`）；`parseKimi` 只取顶层 usage→周窗、首条 `limits[].detail`→5h 窗（`internal/quota/kimi.go`）。真机响应证实**不是漏检**——老套餐响应里就没有月窗。悬浮窗 Kimi 5h/周双环 2026-09-25 已点亮真数据在跑。

## 7. 取数路径排序（按可靠性）

1. **首选主链：`GET api.kimi.com/coding/v1/usages`（Bearer sk-kimi-）** —— 无登录态、headless、cc-switch 生产同款；5h/7d/（新套餐）月总池/月内 Code 四组比例 + 各自 reset_time + 加油包一个 key 全拿。缺点：非文档化、字段随套餐漂移、偶发 used_ratio=0 服务端 bug（容错：双形状都解析、reset 过期不采信）。
2. **月度增强：kimi.com Connect RPC**（GetSubscriptionStats/GetSubscription/ListBalanceActions）—— 唯一覆盖「网页/App 侧消耗」与逐笔明细的口，且不挑套餐；非公开 + 登录 token 会过期，只作月度增强，失败降级路径 1。
3. `api.moonshot.cn/v1/users/me/balance`：仅开放平台按量 key 的现金余额，与订阅额度无关（若日后配了按量 key 可另做一张卡片）。
4. 无头浏览器抓 DOM：最脆，不建议主链。
- 展示口径：百分比 + 重置倒计时（与现有 5h/周环一致）；绝对量不估算。
