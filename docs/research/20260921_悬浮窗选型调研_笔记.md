## 发现二：AntFeedingLog 真身（Agent②，2026-09-21 盘点）

- **它不是"前后端分离"，是 Tauri 2 桌面应用**：Rust 壳 + Vue 3 + TS + Vite + naive-ui + ECharts + SQLite（rusqlite）。
- 常驻形态齐全：托盘常驻、关窗收托盘、开机自启（tauri-plugin-autostart）、单实例、GitHub Releases 签名自动更新。
- 另有进程内嵌网页端：axum HTTP（默认 17321）+ Bearer + SSE，"后端推版本号、前端对账重拉"，**前端零 setInterval**——比轮询更适合悬浮窗的模式。
- 规模：Rust ~3.19 万行（29 模块）、Vue 组件 20 个 ~8430 行；测试 505 Vitest + 557 cargo；6 篇 ADR + 19 篇 spec；npm 生产依赖仅 4 个。
- **ADR-0001 已论证过选型**：弃 Electron（~80MB 安装包/常驻 150-200MB），选 Tauri（~10MB，复用系统 WebView2）。
- **悬浮窗本体（置顶/无边框/透明/穿透）在该项目零配置**——但属 Tauri 2 窗口配置级能力（alwaysOnTop / decorations / transparent / set_ignore_cursor_events），不需新增依赖。
- 可直接搬运：托盘/自启/单实例样板、axum+SSE 通信样板、紧凑卡片（ColonyCard）与图表页（StatsPage/ECharts）范式、mocks 静态设计稿工作法。

## 发现三：悬浮窗框架对比（Agent③，2026-09-21 联网）

一句话：**首选 Wails v3 library 模式挂进 Ferryman 主 exe；备选独立 Tauri 2 子项目；"透明+穿透兼得"在 WebView2 系是硬坑但本场景大概率不需要穿透。**

### 关键事实（数字均来自联网出处，详见总表）

- **Wails**：v2 已进维护模式（v2.10.2，2025-07）；**v3 2026-08-02 进 Beta，beta.24（2026-09-20）**，定位就是"给现有 Go 程序加前端"——AssetServer 可直接吃 embed.FS（**现有 vanilla WebUI 可复用**）；托盘内置且可与 getlantern 共存（wails#1521 有先例）；单 exe ~8-10MB。坑：**#6088（2026-09-08 open）Windows 上透明+穿透互斥**（LWA_ALPHA 破坏逐像素透明；WebView2 子窗口先吃点击；正解 CoreWebView2CompositionController，Go 无绑定）；自启/自动更新无官方方案；beta 风险需锁 tag。
- **Tauri 2**：稳定线 2.11.6（2026-09-19），3.0-alpha 已出。悬浮窗全家桶（always_on_top/decorations/transparent/set_ignore_cursor_events/自绘拖拽/多窗口）。坑：启动白闪（#5170，解法 visible:false 先载后显）、透明窗鬼影（#14764）、穿透只能整窗+动态切换（#13070 关闭为重复）。内存各基准打架（42-154MB），Windows 走 WebView2 不吃 WebKit 亏。工具链最重（Rust MSVC + VS C++ + Node，首编 5-15 分钟）。
- **Electron 44**：悬浮窗配方最成熟（setIgnoreMouseEvents forward:true 动态穿透），但常驻 93-180MB、安装包 150MB+、Node 栈与 Go 零交集——只作对照，Q5 红线下出局。
- **Fyne 2.8.1**：置顶有、**Windows 透明无内置、无穿透**；空闲 ~100MB 与 WebView2 同量级；HTML 零复用=界面全重写——不推荐。
- **WPF**：能力天花板（Win32 直通），但 .NET 独立栈 60-100MB+，零复用；WinUI 3 窗口基础问题多年未清，不推荐。
- **go-webview2 裸嵌**：能嵌进已有 HWND+手写 WS_EX_TOPMOST|LAYERED，最薄路径，但维护状态不明、全 DIY。
- **Rainmeter 4.5.22**（仍维护）：零代码兜底——skin 轮询 Ferryman 本地 HTTP/JSON 即可显示，交互弱。
- **PowerToys Always On Top**：任意窗口 Win+Ctrl+T 钉住，最省事兜底。

### 总表（内存/体积为联网实测口径，各基准有分歧）

| 维度 | Tauri 2 | Wails v3 | Electron | Fyne | WPF | go-webview2 裸嵌 |
|---|---|---|---|---|---|---|

| 点击穿透 | 整窗+动态切换 | **与透明互斥(#6088)** | 最成熟 | 无 | 有 | DIY |
| 托盘/自启/单实例/更新 | 官方插件全齐 | 托盘+单实例；自启/更新缺 | 全齐 | 托盘有 | 生态全 | 全 DIY |

### 判断注记

- 若悬浮窗**不需要点击穿透**（常驻面板点上去看详情反而是需求）→ Wails v3 当前能力够。
- AntFeedingLog 的 Tauri 样板（托盘/自启/单实例/更新/axum+SSE）在独立子项目路线下可大量照抄；Wails 路线下仅前端范式（紧凑卡片/ECharts/事件驱动对账）可抄。
- 白闪问题与本仓"零闪窗铁律"记忆条目相关：无论哪条路线，启动时 visible:false 先载后显是既定解法。

## 发现四：余量 API 可得性（Agent④，2026-09-21 联网+本地）

一句话：**五家上游没有任何一家给"token 级周/月用量"API——用量列全部依赖本地台账；余量/窗口百分比基本都能查，但每家的端点、鉴权、解析坑都不同。**

### 谁查得出什么（悬浮窗视角总表）

| 上游 | 5h 窗剩余 | 周用量 | 月度用量 | 余额 | 鉴权材料 |
|---|---|---|---|---|---|
| 智谱 CodingPlan | **可查**（%+重置倒计时） | **可查**（%） | 查不到→本地推算 | 可查（现金余额） | 推理同款 key（quota 端点裸 key 不带 Bearer） |
| Kimi Coding | **可查**（limit/used/remaining/resetTime） | **可查** | 共享月度池 API key 查不到（要网页凭证） | 加油包钱包可查 | 推理同款 sk-kimi key |
| DeepSeek 按量 | 无此概念 | 本地推算 | 本地推算 | **可查**（三件套） | 推理同款 key |
| Claude 订阅 | **可查**（半公开 OAuth 端点） | **可查**（%） | 查不到（只有 %），token 数本地推算 | extra_usage 桶 | 本机 CC OAuth 凭据（非 API key） |
| 中转站（new-api/one-api） | 无此概念 | 面板累计 | 面板累计 | **可查** | 推理同款 key |

### 关键端点

- 智谱：`GET open.bigmodel.cn/api/monitor/usage/quota/limit`（5h=unit:3 / 周=unit:6；type 兼容 `TOKENS_LIMIT`/`CREDIT_LIMIT` 两种，信封有/无 data 两种形状——cc-switch #6153/#6402 翻过车）；团队版 `?type=2` 要额外两个 org 头。套餐语义：Lite 2000/5h+10000/周积分，Pro 12000/60000，Max 28000/140000；历史套餐高峰期 3 倍系数。
- Kimi：`GET api.kimi.com/coding/v1/usages` 一个端点给齐（顶层 usage=周窗，limits[] 里 duration:300min=5h 窗；数值口径在百分比/绝对数间漂移，拿 limit 归一化）；`/v1/users/me/balance` 是开放平台另一套账号，**不适用** Coding Plan。
- DeepSeek：`GET api.deepseek.com/user/balance`（is_available + balance_infos 三金额字符串）；**无 usage API、无窗口概念**。
- Claude 订阅：`GET api.anthropic.com/api/oauth/usage`（半公开，即 CC `/usage` 背后；Bearer CC OAuth token + `anthropic-beta: oauth-2025-04-20` + **必须带 `User-Agent: claude-code/<版本>`**；返回 five_hour/seven_day/seven_day_opus/seven_day_sonnet/extra_usage；utilization 有 0-100 与 0-1 两种口径需归一化）。**硬约束**：限流，过期 token 去调=最长 1 小时 429 封禁；轮询 ≥3 分钟（社区安全线），悬浮窗 5-15 分钟足够。Admin API 只管 Console 消费，个人账号不可用。
- 中转：`GET /dashboard/billing/subscription`（hard_limit_usd）+ `GET /dashboard/billing/usage?start&end`（total_usage，单位 0.01 美元），余额=前者−后者/100；**OpenAI 本尊已弃用这对端点**（回 403/404），只对中转面板有效——`balance_url` 每上游独立配置是对的，不能猜。

### 判断注记

- "查询 + 本地推算"混合结构与 Round 1 Q1 推荐一致；且 token 级用量只有 Ferryman 台账能出 → 悬浮窗与 Ferryman 数据面强耦合，支持"读 Ferryman daemon"的架构方向。
- 余量查询器将来是"每上游一个解析器"的集合（智谱/Kimi/Claude/中转形状全不同）——独立子模块或独立子项目有理由，但数据消费者（悬浮窗）不必独立于 Ferryman。
- 跨家共同点：全都"未文档化但稳定"，解析器要宽容 + 盯 cc-switch 参考实现（仓库纪律已立）。

## 发现五：统一通知汇总窗先例（Agent⑤，2026-09-21 联网）

一句话：**Windows 上没有现成的完整先例（通知聚合器品类已死，被系统通知中心吸收），但每个零件都有活的先例可拼。**

- **Toast 是错误载体**：横幅约 5 秒就沉入通知中心、无常驻卡片形态——用量余量这种常驻数据必须自绘悬浮窗；Toast 只留给高优先级弹出（Go 发 Toast 用 beeep 或 axllr8tr/toast，go-toast/toast 已停滞）。
- **最贴近的先例**：TrafficMonitor（46k 星，C++ 常驻悬浮窗，正朝"壳+插件 DLL"演进——壳与数据分离正是本远景方向，只是它插件是本机 DLL、我们要跨进程 HTTP）。
- **多程序→一汇总端最轻模式**：各程序 POST localhost + 汇总端超时判死——ntfy（Go 单二进制，POST URL 即发通知）验证过；MQTT 的 LWT（断线遗嘱）+ retain 语义 = 心跳+超时标记 stale+新订阅者补快照。
- **状态与事件分两张表**：Home Assistant 的 state（最新值可覆盖，新订阅者立刻拿全量快照）/ event（只追加流水）分离是教科书——悬浮窗常驻区渲染前者、展开区渲染后者。
- **前端到汇总端用 SSE**：EventSource 断线自动重连（浏览器内建），比 WebSocket 省心。
- **鉴权**：单用户桌面机 localhost 绑定 + 静态 token（与 Ferryman 现有 provider 密钥同套管理）够了；命名管道（go-winio）是升级路径不必先上。
- **产品形态验证**：macOS 菜单栏的 ClaudeBar/TokenBar 已在做"AI 用量余量面板"（TokenBar 甚至内置本地代理旁路统计 token——与 Ferryman 摆渡位置同构）。
- **零新增依赖的演示路线**：Rainmeter（仍维护）皮肤定时 GET JSON 即可出活；OBS browser-source 模式 = 无边框置顶 WebView 指向现有 WebUI 页。
- **死掉但思路可抄**：Growl/Snarl（"生产者→本地总线→可换肤显示端"三段式）；xbar/SwiftBar（stdout 即协议的极轻插件契约）。
- **未找到活跃实现**（如实）：纯本地跨应用通知聚合悬浮窗；读他人通知的 UserNotificationListener 要 MSIX+授权，不现实——好在聚合对象是自家程序，绕开整个死品类。

## Round 3：UI 与契约设计定稿（2026-09-21 下午，8 问全裁决）

1. **月度环分母**：A 起步——GLM/Kimi 无月度官方限额，月度不做成环，做控件下方文字计数（台账估算）；B 后补为可选设置（自设月预算当环分母）。共存：不设预算不画环。
2. **环语义**：剩余制（满弧=满额）；基色区分指标（蓝=5h、橙=周、紫=月预算、绿=DeepSeek 预算）；剩余 <20% 变黄、<10% 变红（告警色覆盖基色，不闪不弹）。
3. **圆心与展开**：圆心=供应商标识（DeepSeek 格放 ¥余额）；hover tooltip 出各环数字；单击展开详情卡（值/上限/%、5h 与周重置倒计时、查询/估角标、最后更新时间）。
4. **DeepSeek 控件**：同尺寸圆形换内容——圆心 ¥余额（查询值）、可选预算环（默认关）、底部小字"今 ¥x·估 周 ¥y·估"。

## 发现六：三家真实返回结构（cc-switch 源码实证，2026-09-21）

来源：`farion1231/cc-switch`（仓库纪律钦定参考实现）`src-tauri/src/services/coding_plan.rs` + `src-tauri/src/services/balance.rs`，gh api 拉源码逐行核对。

### 智谱 GLM（quota 端点）

`GET {open.bigmodel.cn | api.z.ai}/api/monitor/usage/quota/limit`，**鉴权=裸 key（Authorization 头直接放 key，不带 Bearer 前缀）**：

```json
{ "success": true,
  "data": {
    "level": "Pro",
    "limits": [
      { "type": "TOKENS_LIMIT", "unit": 3, "number": 5,
        "percentage": 38.0, "nextResetTime": 1760000000000 },
      { "type": "TOKENS_LIMIT", "unit": 6, "number": 7,
        "percentage": 55.0, "nextResetTime": 1760300000000 } ] } }
```

- `type` 兼容 `TOKENS_LIMIT`/`CREDIT_LIMIT`（大小写不敏感）；`unit:3`=5h 窗、`unit:6`=周窗——**unit 是唯一可信分类锚**：周期末尾周窗的 reset 会早于 5h 窗，按 nextResetTime 排序必把两桶标反（cc-switch issue #3036）；`number` 取值 5/7/1 均实测过，不可绑死。
- `percentage`=**已用百分比**，**端点不给绝对值**（无 limit/remaining 数字）→ GLM 环只能画百分比（剩余=100−percentage），详情卡无绝对数行，也不可能有"本月剩多少积分"的官方口径（月度=台账估算的既有结论因此更硬）。
- `nextResetTime`=毫秒时间戳；5h 桶在 0% 等状态下可能缺失该字段。老套餐（2026-02-12 前订阅）只回 1 条 TOKENS_LIMIT（只有 5h 环，UI 自然降级为单环）。
- 团队版 `?type=2` 需额外 org 头（上轮笔记记录；本次源码未见该分支，实施期核对）。

### Kimi Coding（usages 端点）

`GET api.kimi.com/coding/v1/usages`（Bearer sk-kimi key）：

```json
{ "usage": { "limit": 5000.0, "remaining": 2750.0, "resetTime": "…" },
  "limits": [ { "detail": { "limit": 1500.0, "remaining": 1200.0, "resetTime": "…" } } ] }
```

- 顶层 `usage`=周窗；`limits[].detail`=5h 窗（cc-switch 遍历所有带 detail 的条目一律当 5h）。
- **给绝对值**：used = limit − remaining；但**数值口径在百分比/绝对数间漂移**（limit≈100 整数时是百分比口径）→ 归一化（remaining/limit）算百分比永远对；绝对数展示要防误读，单位实施期核对。
- `resetTime` 格式多变（ISO/时间戳都要兼容）。

### DeepSeek（balance 端点）

`GET api.deepseek.com/user/balance`（Bearer key）：

```json
{ "is_available": true,
  "balance_infos": [ { "currency": "CNY", "total_balance": "110.00",
    "granted_balance": "10.00", "topped_up_balance": "100.00" } ] }
```

- 金额是**字符串字面量**（"110.00"；与本仓 balance.go 的 UseNumber 字面量处理一致）；total = granted（赠送）+ topped_up（充值）→ 详情卡可拆两行。
- 无 usage API、无窗口概念（既有结论复核成立）。

### 对契约 v0 的直接后果

- `remaining_pct` 为主字段；GLM 不带绝对值，Kimi 可选带 `abs{remaining,limit}`（口径漂移风险标注），DeepSeek 余额带 `breakdown{granted,topped_up}`。
- `resets_at` 契约统一 ISO8601（GLM 毫秒时间戳在查询器内转换）；"单位是什么"这类实施期待核对的疑点在契约里用可选字段承载，不硬编码猜测。
