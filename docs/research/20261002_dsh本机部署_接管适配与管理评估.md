## 2. 适配方案（Ferryman 侧怎么接）

### 2.1 渡口路由（一次性配置，消灭 key 欠账）

写 home 级 `~/.dsh/cordis.patch.yml`（对 web/desktop 两 profile 都生效、且最高优先）：

```yaml
- id: llm-pi-ai
  config:
    providers:
      ferryman-dock:
        apiKeyEnv: FERRYMAN_DOCK_TOKEN    # 渡口入站占位令牌：不校验，非空即可
        api: anthropic-messages
        baseURL: http://127.0.0.1:15722
        models:
          - id: glm-5.3
            contextWindow: 200000
```

加 `~/.dsh/.env`：`FERRYMAN_DOCK_TOKEN=ferryman`。默认模型：web profile patch 加 `agent-default-model` 行指 `ferryman-dock/glm-5.3`；desktop 的默认模型行在 profile patch，被 home 层……注意叠加序是 home 最后＝home 赢，若不想劫持桌面端选择，就只放 providers、默认模型行留在各 profile patch 自主决定——**推荐后者**（渡口只当"多出来的一个供应商"，用不用、谁默认，各实例自己选，最小侵入）。

- **zai-coding-cn 路由保留**作直连回退（key 补上即活，两路并存不冲突——pi-ai 路由字典天然多路由）。
- 欠账 #1（`setx ZAI_CODING_CN_API_KEY`）：接管后**不再阻塞**（渡口持真钥）；想留直连回退再补 key，优先级降为可选。
- 渡口侧配套（本仓 Go 改动，属渡口车道工作）：
  1. 识别 `User-Agent: deepseek-harness/*` 分岔 dsh/CC 流量；
  2. `ExtractSessionID` 第三回落（pi-ai sessionId 落线形态＝spike 项，见调研报告 §3.4）；
  3. dsh 车道改写集（CC 五件不照抄：`[1M]` 剥除/claude-code beta 重建对 dsh 不适用）——过 ADR 再动手。

### 2.2 守望与台账

- 加 dsh 会话根（`~/.dsh/sessions/--*--/<id>/session.vN.jsonl(.zstd)`，取数值最高代）；双实例共根，台账天然不分实例。
- **zstd 必须在 Go 侧解**（klauspost/compress，逐帧独立可流读）。不能走 `compression:'none'` 配置捷径：持久化后端明文"一个 root 只属一种编码，混编码拒绝、双写不支持"，现存 2 目录已是 zstd，切 none 直接炸。
- 事件 `time`＝内容时钟现成；`assistant/message.usage` 四列不相交口径＝记账第二独立源（渡口 dock 科目为主、可对账）。
- 手机会话特征预判：短脉冲交互（查进度/批审批/问一句）→ **问询守望（机器等人）在 dsh 轨的价值权重高于 CC 轨**，dsh 轨设计时优先排；等待窗口（机器等机器）判据需按 dsh 事件重选（子女会话目录写入＋`agent/status`），CC 的 async 文案判据不移植。

### 2.3 闸门与归还

- MVP：官方 `dsh-hooks-claude-code` 桥装进 **web profile**（手机链路先覆盖——这是新热区），`configPath` 指 Ferryman 发的 dsh 专用 hooks.json（复用现有 CC 钩子脚本；桥尊重 hooks.json 自设 timeout，显式设 2-3s）。
- desktop profile 是 Electron 专属名（CLI 拒绝其 boot/config-dump），插件走桌面端 UI 的插件管理装——**二期再说**，桌面端会话非热区。
- 归还的桥路硬伤（SessionStart detached、赶不上首请求）依旧成立；手机场景反而更疼（手机上更难"重发一句"）。若 dsh 轨要上 enforce，**原生插件（`agent/created` awaited 注入）应与闸门 enforce 同批交付**，不是可延项——这是相对调研报告 §3.2 的修正：桥只够 observe 期用。
- 桥与 ios-control 共存无冲突（不同扩展点，同 profile 多插件原生支持）。

## 4. 排序建议

1. **今天**：CLI 实例常驻化（VBS+计划任务）——不依赖任何 Ferryman 改动，重启电脑前必须还上。
2. **spike（半天）**：借现成部署做 pi-ai 线形状验证——web profile 临时加一条 mock/渡口路由，抓 anthropic-messages 请求看 sessionId 落点（调研报告 §3.4 一锤定音；比另起 mock 环境省事，dsh 已在跑）。
3. **MVP（1-2 天）**：渡口 UA 分岔＋ExtractSessionID 回落；home patch 写渡口路由（欠账 #1 消失）；守望加 dsh 根＋Go 解 zstd；桥装 web profile 跑闸门 observe。
4. **定 ADR**：dsh 车道改写集；dsh 轨术语入 CONTEXT.md。
5. **二期**：ferryman-dsh 原生插件（归还 awaited 注入——**与闸门 enforce 同批**，见 §2.3 修正）；问询守望 dsh 轨判据；desktop profile 覆盖。

## 5. 与既有决策的勾稽

- 服务商接管战役（2026-09-30 定案）："切供应商只翻渡口上游表、零写盘"——dsh 经 home patch 一次性配置后完全符合；CC/codex 的 apply 手术在 dsh 上降级为"可选的手工配置辅助"。
- 改写五件纪律：dsh 流量出现第六件要么缺陷要么过 ADR——dsh 车道改写集就是那个 ADR 的标的。
- 零闪窗铁律、长跑测试带截止、发版资产契约：本评估新增工作全部落在既有纪律内，无新例外。
