# Task 派活拦截可行性调研（PreToolUse 拦子代理派发）

日期：2026-09-18。调研方式：只读官方文档 + 社区来源 + 本机 `~/.claude` 钩子配置。未做实机实验（未标注"实测"的结论均来自文档与社区，见文末信心水平）。

## 结论先行

**能拦。** Claude Code 派发子代理（Task/Agent 工具调用）是一次普通的工具调用，`PreToolUse` 钩子可以拦下来，支持四种裁决：`allow` / `deny` / `ask` / `defer`。其中 **`ask` 会把权限确认框抛给用户**（Ferryman 想要的"提示用户"正好用它），`deny` 会把 reason 作为工具错误回给模型、回合继续——模型可能原地重试或换路，需要 daemon 计数升级裁决。主要坑有两个：工具名随版本在 `Task`/`Agent` 之间变（matcher 写 `Task|Agent` 并实测确认）；命令钩子超时或起不来时**静默放行**（官方明说"别指望卡住的钩子当闸门"）。UserPromptSubmit 闸门语义没记错：exit 2 或 `decision:"block"` 都能挡住 prompt。Codex CLI 现在也有对等的 PreToolUse 钩子（拦 spawn_agent），可做第二适配器。

---

## 1. PreToolUse 能否拦截 Task 工具调用

**能。** 官方 Hooks reference（https://code.claude.com/docs/en/hooks ，旧域名 docs.claude.com/en/docs/claude-code/hooks 301 到这里）：

- PreToolUse "Runs after Claude creates tool parameters and before processing the tool call. **Matches on any tool name except `EndConversation`**"，并列出内建工具：`Bash`、`PowerShell`、`Edit`、`Write`、`Read`、`Glob`、`Grep`、**`Agent`（Spawns a subagent）**、`Workflow`、`WebFetch`、`WebSearch`、`AskUserQuestion`、`ExitPlanMode` 及所有 MCP 工具。即派发子代理就是一次工具调用，走同一条 PreToolUse 通路。
- 注意命名：现行文档把派子代理的工具叫 **`Agent`**；旧版叫 `Task`（GitHub issue #21614 里仍叫 Task）。**matcher 建议写 `"Task|Agent"`**（纯字母数字加 `|`，走精确匹配列表语义），并在装机的 CC 版本上用 `claude --debug-file` 首跑确认实际 `tool_name`。
- matcher 规则（同页）：`"*"`/空/省略 = 匹配全部；只含字母、数字、`_`、`-`、空格、`,`、`|` = 精确串或 `|`/`,` 分隔的列表；含其他字符 = JavaScript 正则（未锚定，`RegExp.prototype.test`）。逗号分隔需 v2.1.191+。
- 钩子 stdin 收到：`tool_name`、`tool_input`（Task 调用时含 `subagent_type`、`description`、`prompt`）、`tool_use_id`、`session_id`、`transcript_path`、`cwd`。daemon 判"前缀多大、已派几个"所需信息够用（前缀大小可由 transcript_path 算，或由 daemon 侧已有账本推）。

### 退出码 2 的语义

- "Exit 2 means a blocking error." 对 PreToolUse：**工具调用被阻断**。阻断消息 = JSON 里的 blocking reason（有的话），否则用 stderr。
- "A hook that blocks by exiting 2 routes the same way as `"deny"`: **Claude sees the stderr message as the denial reason**." —— 模型看得见拒绝原因。
- **重要反例（fail-open）**：命令钩子超时**不阻断**——"A timed-out `command`, `http`, or `mcp_tool` hook doesn't block the tool call. The call continues through the normal permission flow, **so don't count on a stalled hook to act as a gate**." 钩子起不来（脚本路径错、exit 127）同样是非阻断错误、调用照走。Ferryman 的闸门一贯 fail-open（DESIGN §4），这里语义一致，但要意识到：daemon 卡死 = 拦截静默失效。

### JSON 输出 permissionDecision

PreToolUse 用 `hookSpecificOutput`（四种裁决 + 可改写入参），多钩子冲突时优先级 **`deny` > `defer` > `ask` > `allow`**：

| 裁决 | 行为（文档原文/近义转述） |
|---|---|
| `allow` | 跳过权限确认，直接放行 |
| `deny` | "Claude Code reads the JSON decision, blocks the tool call, **and shows Claude the reason**" —— 调用被否，reason 回给模型 |
| `ask` | **弹权限确认框给用户**。"the permission prompt displayed to the user includes a label identifying where the hook came from"（`[settings]`/`[plugin:名]`/`[skill]` 标注来源）。auto 模式下 hook 的 ask 也**强制弹框**：分类器只能否、不能默默批 |
| `defer` | 仅 `-p` 非交互模式：暂停进程、把 pending tool call 交给外层程序（`stop_reason: "tool_deferred"`），交互会话里忽略 |

Ferryman 场景下 `ask` 就是"提示用户再决定"的正解；`defer` 适合未来 Ferryman 自己包 `claude -p` 时用。

另有两点值得记：

- `updatedInput` 可以在放行前改写入参（本次用不上，但说明 PreToolUse 通路权限很全）。
- 钩子同样跑在**子代理内部**（"Hooks from settings files, managed policy settings, and plugins also run inside subagents"），input 带 `agent_id`/`agent_type`。matcher 只写 `Task|Agent` 时，只有主会话派发才命中，子代理内部的工具调用不会误伤。

## 2. 阻断后的回环风险

**deny 后回合继续，模型拿到 reason，自己决定下一步——没有内建重试上限。**

- 官方机制（同一页，prompt-based hooks 一节的对照说明）：命令钩子的 `permissionDecision: "deny"` 效果等价于 prompt 钩子 `continueOnBlock: true`——"return the reason to Claude **as the tool error** so it can adjust and **continue**"。即：调用变成为一个失败的 tool result，agent loop 带着原因继续转。
- 可能走向：① 原样重试同一个 Task 调用（PreToolUse 再次触发——daemon 可按 session 计数，第二次起升级为 `ask` 或加码 reason）；② 换个工具或自己干（对"该压缩了"的提示来说，模型更可能去压缩或继续主对话，但不能保证）；③ 放弃该步。
- **没有 PreToolUse 版的防死循环护栏**。Stop/SubagentStop 钩子有 8 次连续阻断上限和 `stop_hook_active` 字段，PreToolUse 的 deny 没有对应机制——计数和升级必须由钩子（即 Ferryman daemon）自己做。
- 社区经验（Steve Kinney, "Claude Code Hook Control Flow"，https://stevekinney.com/courses/ai-development/claude-code-hook-control-flow ）：**含糊的 deny 会导致循环**，精确、给出下一步动作的 deny 能让模型照做。所以 reason 文案要写成动作指令（"上下文已 X tokens、已派 N 个子代理；先 /compact 再重新派"），不要只写"blocked"。
- 已知边缘 bug（GitHub issue #21614，https://github.com/anthropics/claude-code/issues/21614 ，v2.1.23，已关闭标 duplicate）：子代理**内部**的 Skill 工具调用被 PreToolUse 挡时 CC 崩溃（`Aborted()`）。Ferryman 在主会话层拦 Task 派发，不走"子代理内部工具被挡"那条出问题的路径，风险低；但升级 CC 版本后建议回归测一次。

## 3. UserPromptSubmit 阻断语义（Ferryman 现有闸门）

**没记错，语义确认。** 同一官方页：

- "Runs when the user submits a prompt, **before Claude processes it**."
- exit 2："**Blocks prompt processing and erases the prompt**"；等价 JSON 形状 `{"decision": "block", "reason": "..."}`——"the block message shows the reason **to the user**, and it isn't added to context"（reason 给用户看，不进模型上下文，因为 prompt 根本没送出去）。
- exit 0 时普通 stdout / `additionalContext` 会作为 system reminder 注入上下文（Ferryman gate 的 additional_context 通道就是这个）。
- 该事件命令钩子默认超时降到 30s；超时输出丢弃、**prompt 照常放行**（又是 fail-open）。
- 本机 `~/.claude/settings.json` 实测注册：`UserPromptSubmit` 挂着 `C:\WorkSpace\agent\Ferryman\hooks\ferryman-gate.ps1`（block 时转发 `{decision:'block', reason, suppressOriginalPrompt}`）。**`suppressOriginalPrompt` 在现行 reference 页已不见记载**（现行文档只写 decision/reason，且明说 UserPromptSubmit 不能替换 prompt 本体），字段是否仍被 honors 建议在目标版本上实测确认——不影响闸门可用性，只影响"原 prompt 是否还会显示"。

## 4. Codex CLI 对等性

**有对等机制，形态接近 Claude Code，可做第二适配器。** 信心中等（来源以第三方博客 + 文档镜像为主，见信心水平）：

- OpenAI Codex CLI 已上线 hooks 系统（feature key `hooks`，默认开启；旧 `codex_hooks` 旗标是弃用别名）。事件含 `PreToolUse`、`PostToolUse`、`PermissionRequest`、`SessionStart`、`UserPromptSubmit`、`SubagentStart`、`SubagentStop`、`Stop`、`PreCompact`/`PostCompact`、`SessionEnd`、`Interrupt` 等。
- 拦工具调用：`PreToolUse` 返回 `"permissionDecision": "deny"` + reason（旧 `{"decision":"block"}` 形状也收），或 **exit 2 + stderr**；`allow` + `updatedInput` 可改写入参。与 CC 几乎同构。
- 拦子代理派发：Codex 的派发工具是 `spawn_agent`（别名 `Agent`），PreToolUse 匹配它即可挡住派发本身；`SubagentStart` 同样只能注入上下文、不能阻断——与 CC 同款限制。
- 配置与信任：`~/.codex/hooks.json` + `<repo>/.codex/hooks.json`（repo 覆盖 user）；非托管钩子要先过**哈希信任审查**（`/hooks` 菜单信任，改动需重审；`--dangerously-bypass-hook-trust` 单次跳过）。对 Ferryman 意味着：装钩子后用户要手动信任一次。
- 盲区：**hosted/云侧工具不走钩子通路**，官方口径是"guardrail, not a complete enforcement boundary"。
- 出处：https://learn.chatgpt.com/docs/hooks ；https://agenticcontrolplane.com/blog/codex-cli-hooks-reference ；https://blakecrosley.com/blog/codex-hooks-make-the-harness-real ；早期功能请求 https://github.com/openai/codex/issues/14882 。

## 对 Ferryman 的建议

1. **做，用 PreToolUse + JSON 裁决，别用 exit 2。** matcher 写 `"Task|Agent"`；新增一个 `hooks\ferryman-taskgate.ps1`（复用 gate 的自举/Token/fail-open 骨架，见 `C:\WorkSpace\agent\Ferryman\hooks\ferryman-gate.ps1`），POST daemon 新端点（如 `/taskgate`），daemon 按"当前前缀估算 tokens + 本会话已派子代理数"给裁决：超限 → `permissionDecision: "deny"`，reason 写成可执行指令（"先 /compact 再派"）；连续第 N 次拒 → 升级 `permissionDecision: "ask"` 弹给用户。`ask` 在 auto 模式也强制弹框，交互体验有保障。
2. **回环防线放在 daemon**：每 session 计 Task deny 次数（现成 `/subagent` 计数端点可扩展），deny reason 一次比一次具体；不做计数就会吃"模型原地刷 Task"的循环。
3. **保持 fail-open 纪律但要知情**：命令钩子超时/起不来 = 拦截静默失效（官方原话"don't count on a stalled hook to act as a gate"）。钩子 timeout 维持 3s 量级、daemon 侧 2s 响应截止，与现有 gate 一致；daemon 不健康时宁可放行并记账（"拦截漏斗"在账本单列）。
4. **别动 SubagentStart**：它只能注入上下文、不能阻断（官方明确），现有 `ferryman-subagent.ps1` 计数职责不变；真正的闸只能装在派发工具的 PreToolUse 上。
5. **顺手取数**：PostToolUse 匹配 `Agent` 时，完成侧 `tool_response` 带子代理用量遥测（`totalTokens`、`modelsUsed`、`resolvedModel` 等，v2.1.212+；后台派发在转后台那一刻返回 `async_launched`）——正好喂 Ferryman 费用账本，比解析 transcript 便宜。
6. **版本适配**：装好后先用 `claude --debug-file` 跑一单确认实际 `tool_name` 是 `Task` 还是 `Agent`（版本相关），matcher 两个都写不亏；`suppressOriginalPrompt` 一并实测。
7. **Codex 适配后置**：机制对等（PreToolUse 拦 spawn_agent + exit 2/deny），但要做第二套 hook 适配器 + 用户手动信任哈希，优先级放低；hosted 工具盲区意味着 Codex 侧拦截天然不全。

## 信心水平

- **官方文档确认**：PreToolUse 匹配内建工具（含派子代理的 Task/Agent）、exit 2 与 deny/ask/allow/defer 语义、ask 弹用户、deny reason 回模型、PreToolUse 超时 fail-open、UserPromptSubmit 阻断语义、Stop 类 8 次上限而 PreToolUse 无上限——均出自 https://code.claude.com/docs/en/hooks （2026-09-18 抓取）。
- **社区经验/推测**：deny 后模型"会重试或换路"的具体倾向（官方只说回合继续、模型自决）；含糊 deny 致循环（Steve Kinney 课程页，非官方）；子代理内钩子错误致崩（issue #21614，v2.1.23，已关 duplicate，现版本状态未知）。
- **中等信心**：Codex CLI 钩子全部细节（learn.chatgpt.com 文档镜像 + 两篇第三方博客，未在实机验证）。
- **未实测项**：本机 CC 版本的 Task/Agent 实际 tool_name、`suppressOriginalPrompt` 是否仍生效——装机首跑确认。
