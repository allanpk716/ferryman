# CC API 中转替换：深度研究与验证方案（只覆盖 Claude Code 链路）

- **日期**：2026-09-19
- **问题**：自建最小路由器替换 cc-switch 的 CC 链路（评估见 [20260919_自建CC专用最小路由器_评估](20260919_自建CC专用最小路由器_评估.md)），怎么把"研究清楚＋验证等价"做扎实——只关注 CC 相关设置与 Anthropic 链路。
- **现状缺口（一句话）**：已知 CC 发什么（入站捕获 117KB）和 cc-switch 源码写了什么（五件改写＋若干 no-op 门），**不知道 cc-switch 实际发到 bigmodel 什么**（出站形态从未实测）。三个关键事实因此悬空：出站头全集、media 降级的标记内容、`claude-code` beta 标记对套餐的真实作用。

## 1. 核心工具：上游捕获器（upstream tap）

```
CC ──▶ 被测路由 X ──▶ tap(127.0.0.1:15723) ──▶ open.bigmodel.cn/api/anthropic
```

- **X＝cc-switch**：把它 DB 里「GLM Coding」供应商的 `base_url` 临时改成 `http://127.0.0.1:15723`（DB 里可改可回）——第一次拍到 cc-switch 的真实出站形态。
- **X＝自建 router**：upstream 配 15723——拍到自建的出站形态。
- tap＝`experiments/capture/forwarder.go` 变体（SSE 冲刷已修，约 95% 现成），捕获含 headers＋body，落本地永不入库（**真钥会流经 tap，本地文件权限收紧，验完即删**）。

有了这个观测点，"等价"从推断变成测量。

## 2. 三层等价验证

### L1 形状等价（差分重放 → golden diff）

- 同一份入站请求体（场景捕获的 CC 原始报文）分别喂两条路径，各自的出站捕获做**逐字段 diff**（值、键集、数组顺序）；不可控字段白名单：ts、session_id 类。
- 判据：全场景矩阵 diff＝0；非 0 的差异逐条归属（"有意为之"要写明理由）。
- 复用件：`q14s3.py` 的重放发送器改差分重放器（去掉 max_tokens 改写）。

### L2 行为等价（上游真回应对照）

- 两条路径各自真打 bigmodel，比对：HTTP 状态、SSE usage 四列、stop_reason、错误语义（429/4xx 文案）。
- **cacheRead 当最灵敏探针**：同前缀请求两条路径的 cacheRead 必须一致——上游对请求内容的"看法"（含改写后的缓存键）直接反映在命中上（Q14 方法复用）。
- **套餐对照实验**：有/无 `claude-code-20250219` beta 标记 × 两条路径，共 4 格——验证 beta 重建是硬要求（丢标记被拒/错价）还是无害冗余。这一格决定头卫生的实现严格度。

### L3 功能等价（CC 端到端）

base_url 切自建 router，CC 全功能清单走一遍：

主对话（各档模型）／子代理派发回收／后台小请求（ai-title 用 haiku 档）／读图（走 media 降级）／1M 长上下文／工具调用往返／网络错误重试（API_TIMEOUT_MS=3000000＝50min，router 代理超时必须≥此值且 SSE 不断流）。

## 3. 场景矩阵（"CC 用的相关设置"的完备枚举）

| 维度 | 取值 | 验证层 |
|---|---|---|
| 模型名 | opus/fable/sonnet/haiku 四别名；子代理真名直发（glm-5.3-flash[1M]）；未知名（default 兜底） | L1+L2 |
| `[1M]` 后缀 | 有/无/大小写变体 | L1 |
| 对话形态 | 单轮；多轮；工具往返（tool_use/tool_result）；thinking adaptive；图片块；41k+ 长前缀 | L1（**多轮形态至今无 wire 样本**，本次补齐） |
| CC 特殊流量 | ai-title 小请求；count_tokens（存在性待实测确认） | L1+L3 |
| 异常路径 | 429；5xx；上游断流；重试风暴对照组（借鉴 0918 教训） | L2+L3 |
| 头 | beta 全集透传/重建；UA；x-stainless 族 | L1+L2（套餐格） |

## 4. CC 侧设置的处置清单（替换时动什么、冻结什么）

| 键 | 处置 | 验证 |
|---|---|---|
| `ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN` | **改**：指向自建 router＋`PROXY_MANAGED` 占位符 | 全功能清单 |
| `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU,FABLE}_MODEL` | **冻结**（claude-* 别名照发，router 换映射表即可切供应商） | 场景矩阵各档 |
| `CLAUDE_CODE_SUBAGENT_MODEL` | **冻结**（真名直发，router 精确匹配分支兜底） | 子代理场景 |
| `ANTHROPIC_DEFAULT_*_MODEL_NAME` | **冻结**（纯展示，不进请求；切供应商时可选更新） | — |
| `API_TIMEOUT_MS` 等行为类 | **冻结**；router 侧超时对齐（≥50min、SSE 不缓冲） | L3 重试/长响应 |
| beta 头（CC 生成） | 不动——router 按重建规则处理 | L1 头 diff |

## 5. 决策门（什么算"研究清楚"）

1. 出站 golden diff 全场景＝0（或差异全部解释并记录归属）；
2. 套餐对照 4 格结论明确（标记是硬要求／无害，二选一有实证）；
3. CC 全功能清单通过、账本 usage 正常；
4. CC 版本漂移有监控手段：入站捕获 diff 告警（新 beta/新顶层参数出现即知，避免静默 miss）。

四条满足 → 进评估文档 §4 的迁移三步（透传版→改写版→退役）。

## 6. 工具沉淀与执行顺序

`experiments/router-fidelity/` 套件：

1. `tap.go`——上游捕获转发器（forwarder 变体）；
2. `scenarios.py`——场景生成：驱使真 CC 产全矩阵流量（probe_cc 模式：独立 scratch 目录＋项目级路由覆盖）；
3. `diff.py`——两份出站捕获逐字段对比（白名单忽略表）；
4. `replay.py`——差分重放器。

执行顺序：**搭 tap＋跑场景矩阵（先拍 cc-switch 出站基线）→ 固化 golden → 自建 router 开发中持续 diff → L2/L3 → 决策门 → 迁移**。第一步不写一行 router 代码，纯观测，花费≈每场景一发真实请求（积分级）。
