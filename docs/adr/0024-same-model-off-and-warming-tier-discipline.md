# 同模型摆渡关停与保温升降档纪律

2026-10-07 用户拍板：生产关停同模型摆渡（`[ferry.same_model].enabled=false`，经 `/settings/restart` 安全重启生效，纯配置面无发版），交接叙事回归第三方摆渡（本地千问首发）；同时立**保温升降档纪律**——任何保温泳道默认 off，升档必须先过 observe 演练期且经济账为正，enforce 期连续两个评估窗净亏即降档（CONTEXT.md 词条，对将来新泳道自动生效）。

依据（2026-10 月度账，归因 v2）：132 次追加重放花费 8025 智谱积分、兑现 1271（净 −6754）；**98% 亏损额来自"会话未回归"**（85 次放任过期 + 4 次拦截收口），TTL 判据几乎无责（回归未命中仅 3 次/94 分）；need 天花板已被吃掉 78.6%（11/14）——**结构性到顶而非执行问题**：保本需 67% 兑现率（有价口径），实际 8.3%。质量面：9-28 盲评同模型 10/10 满分（完整摆渡指令）vs 本地千问 6.86/7（生产交接原文），且生产同模型用浓缩指令、实际达不到测出的满分。两账审计：保温兑现与 v1 摆渡 gross 不重叠（不同回合终型，合并口径月净 −1577）；v1 gross 中约 595 积分依赖"block 时缓存还热"的乐观假设（7 条 block 实读 <50% 前缀），摆渡线仍大赚。

修订关系：取代 ADR-0016 的"启用"决定；机制与判热代码保留，`enabled` 开关即回滚通道（重开仍须先过升降档纪律）。

## 后果

- 保温三泳道全 off（等待窗/问询守望本就 off）；30 分钟内回归仍由闸门热缓存判据放行（真实流量喂钟，不依赖保温）。
- 35 分钟以上闲置从"同模型续热放行"变"照拦开新会话"——彼时缓存已真死，拦截即摆渡哲学本义。
- 千问失败自动落骨架降级（确定性交接，盲评中位 5.5/7），闸门不变量永保；云端顺位链（glm-5.3-flash/Kimi k3）已实装未装配（生产无 `[ferry] chain` 节），启用前置＝冒烟盲评。
- 复评：10-14 cost_report 验账（保温道归零、交接成本≈0、摆渡毛省不掉）；10-21 千问交接抽样复评（含大会话样本——L2 分块质量未在真产考过，历史最大材料 158K token 未触发过 L2）。
- 遗留小票：qwatch 心跳 21 跳实付约 249 积分因生产不给 `BeatResult.CostActual` 赋值而漏出保温账（见 `.scratch/warm-shutdown-20261007/followups.md`）。
