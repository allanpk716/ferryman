# 账本常驻解析缓存（读侧派生物），不换数据库

统计界面翻页 ~4 秒的病根是 daemon 每次查询都从头解析全量账本（2026-10-09 实测 91MB、19.5 万行），且不止统计页：`/widget/summary` 30s 轮询、`/report`、dsh_dedup/dsh_receive 逐事件、gate 的 qwatch 扫描都在重复这份固定成本。决定把解析结果常驻 daemon 内存（每文件解析一次，之后只增量解析新追加字节），修在 accounts 读取层（Read/ReadMonths 内部），全部消费端点一起受益；实测暖后全量读 24ms、Kind=usage 47ms（原 ~4s）。

## Considered Options

- **A 常驻解析缓存＋增量追加（已选）**：直接消掉「每请求重复解析」的固定成本；账本仍是 append-only JSONL 唯一事实源（ADR-0002），缓存只是可随时重建的读侧派生物。
- B A＋按日预聚合表：A 之后 summary 只剩毫秒级线性扫，预聚合收益趋近于零，多养一份派生数据，否决。
- C 换 SQLite：动「JSONL 唯一事实源」领域铁律，迁移/备份/T39 式重写工具全要跟着改，代价与收益完全不成比例，否决。
- D 只修前端（停轮询/拉长间隔）：治标，翻页照样 4s，否决。

## Decision

- **全量常驻**（所有月份都留内存），不做热月 LRU：本地守护进程，实现最简、行为可预测。实测常驻堆 **287MB**（键全量驻留＋白名单值驻留后；无驻留约再高四成）——高于立项估计的 50~100MB，按既定协议先全量上线、实测数字落本 ADR，**真超标由用户在验收时拍降级热月**（降级路径：files 表按月淘汰，结构不变）。
- **共享只读契约**：Read 返回的 map 即缓存内部条目（零拷贝）。前提=消费方不改写返回行——daemon/report 全消费面已核（唯一形似的 restore.go `r["continuation"]` 是自建响应 map，非账本行）。后续新消费方同守此约。
- **换文件侦测三重**（任一命中→整文件重解，正确性永远以盘上字节为准）：size 收缩；size 相等且 mtime 变；已消费区末 64 字节尾样不符。覆盖 T39 式重写、原地覆盖、换文件。
- **撕裂行重解锚**：无 `\n` 收尾的尾段按旧 splitlines 语义仍计一行，但记截断锚——后续追加若续写该行，回退到行首重解（读取序：先回退再读增量，顺序反了会丢行）。并发写下的半行从「当坏行永久丢」变为「写完即转正」。
- **启动预热**：serve 起 goroutine 调 Prewarm，把秒级首解析（实测 2.6s）从首个用户请求挪到启动期；boot 回放（读两月）与预热共享同一缓存。

## Consequences

- 两个如实声明的语义微变：坏行 stderr 告警从「每次 Read 一报」变「首次解析一报」；撕裂半行不再每读报一次坏行。
- daemon 常驻内存上升 ~290MB（GC 峰值另计）；换机器/瘦部署时按上面降级路径处理。
- 统计窗轮询随本缓存同批改为可见性节拍（隐藏暂停/显示立刷/可见 30s）——单独先上会让「打开」失去后台预刷新而变卡，必须与后端同版本交付。
- 价格表 LoadPrices 默认路径加 stat（大小+mtime）缓存；显式 path（测试临时文件）不进缓存，改表走 settings 文本手术路径。
- 独立随行票：`[ferry] econ_provider` 计量键（provider="local" 查无价格表致「不可算」的修复），取用口统一 config.EconKey()。
