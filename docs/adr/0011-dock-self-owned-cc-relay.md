# 自建渡口：CC 链路中转自持，cc-switch 退守 Codex 轨

ADR-0006/0007 已把 daemon 放进 CC 流量路径（透传＋内存快照，上游指 cc-switch）。源码级评估（`docs/research/20260919_自建CC专用最小路由器_评估.md`，2026-09-19 经用户质疑后两轮复核补全）查明：cc-switch 约 1.9MB Rust 中，本机 Claude→GLM 链路实际生效的改写只有五件——模型档位映射（六键，子代理真名精确保留）、剥 `[1M]` 后缀、换上游真钥（GLM 配 `ANTHROPIC_AUTH_TOKEN` → 出站仅 `Authorization: Bearer`）、text-only 模型的图片降级（**GLM-5.3 在确认名单上**）、出站头卫生（**anthropic-beta 重建、确保含 `claude-code-20250219` 标记**——GLM Coding 套餐识别相关）；其余 90% 代码量是 Codex/Gemini/Copilot 多协议转换层、failover、GUI，与本链路无关。自建后 beat 与真流量走同一份改写，缓存键全链路自洽，"第三方改写行为漂移导致重放 miss"这一风险类别整体消失（ADR-0007 设的复审触发器作废）。

决定（2026-09-19 grill 定稿）：

- daemon 新增**渡口（dock）**：CC 专用中转层，改写五件＋内存快照＋心跳同层；命名避开与"摆渡路由"撞名（术语见 CONTEXT.md 渡口节）。
- **beat 从渡口入站口重放**——"beat 永远走会话同路由"不变式的彻底落实（与真流量同路径，连渡口自身的 bug 都天然对齐）。
- **常驻保障**：注册表 Run 登录自启（对齐 cc-switch 现模式）＋计划任务每 5 分钟探活看门；钩子自举继续兜底。现状零自启是切换的硬前置——不做则重启机器即断网。
- **cc-switch 永不整体退役**：Codex 轨（`currentProviderCodex` 活跃）继续由它服务；摘除仅限 Claude 链路，保持安装保持运行。
- **渡口流水入账本**：新科目 `dock`（改写前后模型名、四列 token、延迟、状态码——纯元数据，隐私不变量不破），兼作改写正确性与套餐计费的排障对账素材；智谱余额只读查询随面板提供（顶替失去的 cc-switch 余额面板）。
- 入站不鉴权（绑 127.0.0.1＋`PROXY_MANAGED` 占位符照抄）；**形态漂移告警本版实现**（新 beta/新顶层键即报，验证方案决策门第 4 条的落地形态）；config 改动重启生效，热加载后置。
- **切换节奏**：三层验证（`docs/research/20260919_CC中转替换_研究与验证方案.md`：L1 形状差分→L2 行为对照含套餐四格→L3 CC 全功能）通过即切；切换日做回退演练并落 runbook（与 Go cutover 同水位）；回退＝CC 的 base_url 指回 15721，一行。
- 迁移三步不变（透传版→改写版→摘链），每步可回退、可 Q14/差分复验。

## Considered Options

- **维持 cc-switch 为上游（ADR-0007 原样）**：可行且是当日既定路线；但改写保真永远依赖第三方行为不漂移，且透传版上线后每请求多一跳却不换任何控制权——被"反正已在路径里，边际成本≈500 行 Go"的论证推翻。
- **改 cc-switch 落盘请求体／加日志**：动第三方、落盘全量报文与隐私不变量冲突——否决（沿 ADR-0007）。
- **服务化常驻（Windows Service）**：注册面大、回退复杂，收益仅是崩溃秒级拉起——否决，Run 键＋5 分钟看门够用。

## 后果

渡口成为 CC 单点（daemon 挂＝断网），由自启＋看门＋一行回退兜底；真钥从 cc-switch.db 迁至本机 config.toml（T39 规矩：只活本机、永不入库）；切供应商只动渡口映射表，CC 侧别名层冻结（`CLAUDE_CODE_SUBAGENT_MODEL` 真名直发由精确匹配分支兜底）；摆渡路由（交接总结的 LLM 调用）与渡口零共用，边界不变。
