# 内容时钟：以内容推进而非 mtime 控制摆渡重触发与交接有效性

Claude Code 会对仍开着的会话文件周期性追加无时间戳的状态块（last-prompt / ai-title / mode / permission-mode / atis-latch），文件 mtime 前进而对话内容不动。旧判定全用 mtime 口径：`handed_off_at ≥ last_write` 的防重复摆渡守卫每小时失守一次，而交接的 covers_until 只认带时间戳记录、永不推进——结果是无收敛的重复摆渡（2026-09-16~21 实测 356 次摆渡服务 113 个会话，archify 单会话 21 次、骨干培训 PPT 51 次，全部内容相同且结构性无效），且"被拦 ⇒ 交接必已存在"的不变量在 enforce 下不可达（有效交接要求 covers ≥ mtime，永不满足）。决定：引入**内容时钟**（转录内最后带时间戳记录的时刻，懒尾解析、按 mtime 版本缓存），用在两处——①摆渡重触发守卫：内容未越过最近处置边界即不再入队；②有效交接判定：covers 对比内容时钟而非 mtime。闲置本身仍按 mtime 口径（文件时钟）。

## Considered Options

- **A 事后丢弃**（摆渡完成后发现 covers 没变即弃）：零新增读盘，但每小时一次模型调用已经发生——本地模型只浪费 GPU，摆渡路由将来换云端即真金白银。被否。
- **B-lite 内容时钟（已选）**：掐浪费在模型调用之前，同时修好交接有效性；闲置/窗口/心跳语义全部不动，观察周零扰动。
- **B-full 闲置改内容时钟**：连闸门幻影闲置（mtime 每小时被状态块回拨最多 1 小时）一起修，但牵动闲置定义、问询窗开关、等待窗恢复判据、心跳两道验、pending 清除——波及面大。**未做**，留待 B-lite 上线后以实测数据决定是否另立 ADR。

## Consequences

- 取不到内容时钟（尾部 >2MB 无时间戳行/读败）一律 fail-open 回旧 mtime 行为：宁可多摆渡一轮，不误判内容未推进。
- 台账新增 ContentTS/ContentStamp/HandledContentTS 三字段，仅内存：daemon 重启归零＝重启后每闲置会话多摆渡一轮（既有 handed_off_at 同语义，未变）。
- 30 天交接库清理（DESIGN §6.15 遗留 TODO）随本 ADR 落地：超龄 MD（含无索引孤儿）按文件名时间前缀删除，非交接命名文件保留。
