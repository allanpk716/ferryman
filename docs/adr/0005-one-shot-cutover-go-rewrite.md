# 一次性切换取代三关烧机：Go 收编按单场战役整体替换

承接 ADR-0003 的路线与动机（单 exe、公式单源、钩子自举）不变；本 ADR 修订其**验收与切换策略**：不再执行"移植测试全绿 → 逐字段一致 → observe 烧机数天"三关门禁，改为**单场战役打完全部迁移面（守护核心 + 摆渡执行器 + report/doctor/install CLI + 合并 exe）后一次性整体替换**——切换＝重生成 start-daemon.cmd 指向 ferryman.exe，无并行双跑、无影子期、无离线对拍基建。依据：①项目初期、单用户单机，回归影响面小且全留痕（serve 日志、账本 jsonl、/stats）；②闸门天然 fail-open，守护任何故障最坏退化为"不拦"，不砸正常工作流；③回退成本一行命令（点火脚本指回 Python，Python 打 tag `archive/python-final` 永久可跑）；④三关的时间成本（对拍基建＋影子期＋数日烧机）在初期价值倒挂——同样的时间花在真实流量上修 bug 更划算（用户决策）。代价（如实声明）：切换即 enforce，未经验证的回归会直接命中日常路径，需靠日志账本热修；最坏情况下错误/骨架交接短暂入生产。配套纪律：迁移期 **规格冻结**（Python 只收 bugfix，387 个测试为行为规格）；**公式单源**（report 与面板共用唯一 Go 策略包）；实验子系统（e0*/eval*，≈2700 行）随 Python 冻结不迁。切换后 Python 代码与旧 timeline exe 从 main 删除（tag 存档），合并版 ferryman.exe 同时伺服 7311 守护口与 15900 面板口。

## Considered Options

- **三关渐进（ADR-0003 原案）**：安全余量最大，但初期项目风险敞口小、回退廉价，门禁时间成本倒挂——被用户决策推翻。
- **第 2 步完即切**：更早吃真实流量，但制造不必要的骨架交接空窗期；战役连续执行时切换点后移零等待成本——并入单场战役方案。
- **双跑影子期**：验证最深，但需双数据目录与流量复制基建，属三关方案变体——同被推翻。
