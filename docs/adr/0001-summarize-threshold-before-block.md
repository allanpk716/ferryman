# 总结阈值先于拦截阈值（不倒挂）

交接文档初版把总结触发阈值（2h）放在拦截阈值（30min）之后，导致闲置 30m–2h 的会话被拦时没有交接可用。决定反转：总结阈值恒小于拦截阈值（默认 25/30 分钟，配置校验强制严格小于且差 ≥2min），并以"被拦 ⇒ 有效交接存在，或 pending 兜底链已启动"为闸门状态机的不变量。原顾虑"咖啡休息就被总结"实质是通知噪音——通过把通知时机从"总结完成"挪到"实际拦截"解决，而非推迟总结。

## Considered Options

- **保持倒挂 + 无交接时放行警告**：最常见的 30m–2h 场景（午饭/会议/通勤）完全失效，否决。
- **拦截时现场同步总结**：钩子超时 2–3s 容不下模型调用，否决。
