# 保温归因 v2:need×hit 四象限判兑现,按保温回合结算,报表时 join,v1 冻结并存

状态:已接受(2026-10-04;保温归因 v2 spec 定案,决策 D1/D2/D3/D4,底稿 `.scratch/warm-attribution-v2/spec.md`)。

## Context

成效账 v1 的毛节省只来自 block 科目(闸门拦截的避免额:2026-09 净省 660 智谱积分/10 次拦截,2026-10 头四天 2224/24 次),保温泳道在账上是盲区。收入侧无归因:2026-10-04 上午一条 122k 前缀重放把缓存焐热,47 分钟后会话回归(下一次真实用量)命中缓存,省下的约 63 积分只能人工翻流水挖出来;支出侧未入账:10 月智谱档重放已实付 53+ 次。收入不记、支出不计,净节省因此虚高且不可辩护——用户无法回答"保温(同模型摆渡追加重放,ADR-0016-ferry;等待窗心跳与问询心跳,ADR-0006/0007——让缓存存活超出自然闲置寿命的总称)到底赚不赚"。实验侧证据已备:同模型实派发 36 条重放中 33 条可与 dock 行唯一配对,3 条并发歧义(约 8%);前缀口径 p50=0.998,`handoff.prompt_tokens` 可作回合前缀的可靠代理。

## 决策

**纯度量,不动行为(D1)**:全部落在 report 层(internal/report 新增保温归因模块)+ 查询挂接(internal/daemon/query_report.go);不写新账本科目、不动 daemon 写路径、不动 watcher。为何:保温的去留与档位(等待窗心跳启用、same_model 阈值、[heartbeat] 开关清理)要等首份盈亏表拍板——先让数字可辩护,再动行为;度量若自带行为变更,盈亏表就永远没有"改前/改后"可比。

**归因双轴与四象限(D2)**:每个有回归的保温回合按两根轴判类——need=回归时距回合起点>自然 TTL(价书实测 1800s,非 τ),回答"这次保温是否必要"(不保温缓存必凉,命中才可能是保温的功劳);hit=回归首发实收 cacheRead≥回合前缀×80%,回答"保温是否真兑现"。四格处置:**need∧hit 计兑现节省**(前缀×(p_in−p_cache)/per);**¬need∧hit 白保温无害,单列不计省**(命中是 TTL 内的自然存活,与保温无关);**¬hit 记亏损,成本照计**(花了钱没焐住,收入为零)。为何不是"命中即节省":朴素判据把"本来就会热"记成功劳——缓存本就在自然寿命内的命中被计入保温名下,收入虚增、保温的真实价值反而不可信(CONTEXT.md 归因双轴词条的 Avoid 即为此立);只有 need 与 hit 同时成立,反事实避免(不保温就付全价)才真实兑现。成本腿一律按实收入账,四象限只决定收入腿怎么记、不豁免支出——净额=收入−支出才有辩护力。80% 与 TTL 阈值做成可配常量(实现定形态:config 或带注释常量,默认值如上)。

**结算单元=保温回合(D3)**:回合从会话最后一次真实写入起,到回归/拦截(block)/放任过期止;回合内全部保温动作的花费加总,收益在回归时一次结算,多跳回合一次结。为何按回合不按动作:一跳的成本服务的是整段窗口的缓存存活,而收益(回归首发的全前缀命中)是瞬时一次兑现的,不携带"哪一跳焐住的"信息——按跳摊收是假精度,按会话总账又对不上终型与月份;回合恰好是"保温在为谁工作"的因果区间,成本加总与收益一次结算对齐到同一区间,盈亏才有可核的定义。

**报表时 join,公式 v2 与 v1 冻结并存(D4)**:结算发生在 cost_report 查询时,把 `usage`/`dock`/`handoff`/`beat` 行按记账合同 join 出回合与配对,不在事件时刻入账任何节省额。为何 join 放报表时:结算需要三源证据,而保温动作发生时回归还没发生,写路径根本拿不到收入腿;ADR-0002 已定账本只记事实与实收、节省一律 report 层按版本化公式现算——join 沿用该分工,还让口径修订(TTL/80%/配对签名)只动公式版本重算,不迁账本。公式版本化:SavingsV2 = v1 语义不动 + 保温两腿(收入腿+支出腿),`formula` 字段值升 "v2";v1 有金测锁定,输出逐字节不变。为何冻结 v1 而非原地升级:v1 的 block 毛节省已对外报数(2026-09 的 660、10 月头四天的 2224),原地改语义等于历史数字换口径,既有消费者(cost_report v1 段、既有测试)全部波及,回退无干净退路;并存让新旧两版可对照审计,迁移出错时 v1 段仍是基准。

**记账合同(成本腿与口径全文,自 spec 照抄为准)**:

- **数据源分工**:真实请求(回归锚点、末次真实写入)= `usage` 行(cc 轨转录采集、重放结构性不落;dsh 轨事件/转录自带 ts);重放实付四列= `dock` 行(一切经渡口请求必落,体 metadata.session_id 归因);保温动作与前缀= `handoff`/`beat` 行。
- **配对合同(成本腿)**:匹配键 = session_id 相等 ∧ dock.ts ∈ [handoff.ts−2, handoff.ts+wall_s+90];命中签名 = |dock.(input+cache_read) − handoff.prompt_tokens| ≤ max(512, 2%×prompt_tokens) ∧ dock.output ≤ 8192;多候选 → 记 `ambiguous` 不硬配,与 unpaired 同处理——价书推算并标注歧义(2026-10-04 用户确认,见下节);零候选 ∧ wall_s=0(预派发失败)→ 成本记 0;零候选 ∧ wall_s>0 → 记 `unpaired` 回落价书推算并标注。
- **回合切分(收入腿)**:回归锚点 = 该 lineage 下一条 `usage` 行;回合起点 = 末次真实写入(usage 行 ts);终点 ∈ {回归, 拦截(block), 放任过期};dsh 缺时刻回落入账盖章时刻(方向保守——本 ADR 注明:回落以簿记盖章时刻替代缺失的业务时刻,属回落估计,其保守性由真实账本回放验收抽查覆盖,见 Consequences)。
- **前缀口径**:回合前缀 = 回合内首个保温动作行的 prefix(handoff.prompt_tokens / beat.prefix_tokens);不可得回落末次真实 usage 行四列之和并标注 fallback。
- **归因双轴**:need = 回归时距回合起点 > 自然 TTL(价书实测 1800s,非 τ);hit = 回归首发实收 cacheRead ≥ 回合前缀 × 80%。need∧hit 计兑现节省(前缀×(p_in−p_cache)/per);¬need∧hit 白保温无害单列不计省;¬hit 记亏损(成本照计)。80% 与 TTL 阈值做成可配常量(实现定形态:config 或带注释常量,默认值如上)。
- **跨月归属**:回合收益计入回归所在月;保温动作成本计入发生月。
- **成本计价**:智谱档按配到的 dock 行四列 × [prices.glm] 实价入账;本地 Qwen 档(provider=local)零成本。

## 备选对比

- **命中即节省(朴素判据,不设 need 轴)**:省掉双轴判定,但把 TTL 内自然存活的命中记成功劳,收入虚增且不可辩护——CONTEXT.md 归因双轴词条的 Avoid("命中即节省")即为此立。**否决**,need 轴是兑现节省的准入条件。
- **每跳事件时结算(重放/心跳完成即记省)**:跳完成时回归未发生,收入腿证据不存在,记的只能是预估;预估入账违反 ADR-0002 账本只记事实,且一跳成本对整窗收益的摊派是假精度。**否决**,收益在回归时一次结算(回合单元)。
- **v1 公式原地升级(不做版本化)**:少维护一个版本号,但历史 block 毛节省换口径、金测重写、消费者全波及、回退无退路。**否决**,v2 并存、v1 金测锁定。
- **结算前移进 daemon 写路径(顺写顺结)**:写路径拿不到未来的回归证据,还得为口径修订迁历史账,且动写路径违背纯度量(D1)。**否决**,全部留在 report 层。
- **ambiguous 硬配一条 dock(取时间最近候选)**:实测歧义率约 8%,硬配会把别的会话重放的钱算进本回合,错账比缺账更伤可辩护性。**否决**,记 `ambiguous` 单独计数披露;成本按价书推算标注(见下节,已确认)。
- **保温支出按缓存读价毛估**:冷重放全价实例(见 Further Notes)证明毛估系统性低估支出、净额照旧虚高。**否决**,支出优先按 dock 实收,回落价书推算必标注。

## 待定事项(活动约束 F7)——已解除

配对合同成本腿的 **ambiguous 分支成本处置**曾待定(2026-10-04 夜链时只定计数披露)。**2026-10-04 用户确认**:与 unpaired 同处理——价书推算(prompt_tokens×p_in/per,按动作行时刻取价书版本)并标注「价书回落」+Result=ambiguous 单列歧义计数,不冒充实收;已纳入单测(v0.8.7,票05 收尾)。

## Consequences

- cost_report 新增"保温盈亏"节:真兑现节省/白保温无害/亏损三类计数与金额、命中率、保温支出(优先按渡口流水实收,回落价书推算必标注),净额并入成效账 v2(v1 冻结不动);按保温动作类型(同模型重放/等待窗心跳/问询心跳)拆分计数与结果,样本不足的动作不被总论稀释。
- `formula` 字段值升 "v2";v1 段输出与既有 report_test.go 金测逐字节不变,v2 = v1 + 保温两腿。
- 账本科目集合不变,daemon 写路径与 watcher 零改动;支出的"实收优先"让冷重放全价这类成本真相直接上表,不再被"缓存读价"毛估掩盖。
- 实施验收含真实账本回放:对 C:/Users/allan716/ferryman/accounts/202610.jsonl 跑 cost_report,抽 3 个保温回合手工核对(含"回合终点确为真实回归而非重放行"),由协调者在终局评审执行,不拆票;dsh 缺时刻回落的保守性亦由此抽查覆盖。
- 纯度量不新增运行时开关;保温去留与档位拍板仍走既有配置面,等首份盈亏表(见 Further Notes)一并定。
