# 工作台升格：widget 为唯一桌面壳（9-30 定案补录；10-05 修订分期）

状态：已接受（2026-09-30 会话定案；2026-10-05 补录落库并修订分期）。定案后至补录期间未落任何仓库痕迹，本文为首次落库。

## 背景

界面散在两处：15900 浏览器面板（时间线查看器＋配置与调参页，原生 JS 三件套 `go:embed`）与 widget 悬浮窗（Tauri 2 子项目，ADR-0014）。2026-09-30 就「重构面板和设置界面」grill 两轮定案 widget 升格为工作台；但定案只存于会话记忆——无 ADR、无战役计划文档、无 mock 目录（2026-10-05 核实：main 上 widget 停 0.2.1，`widget/ui/mock/` 不存在），期间用户亦无法从仓库得知界面归一方向。

## 决策

1. **唯一桌面壳**：widget 升格为「工作台」＝Ferryman 唯一桌面界面壳，七视图全量——会话台账、单会话详情、时间线（计划卡/反跑/回放/演示模式）、成本成效账、闸门心跳总览、设置视图、策略推演。
2. **mock-first 铁流程**：每张视图先高保真静态 mock（零构建 vanilla JS）→用户过目→定稿→原地长成实现（假数据层换真端点）；不可跳过。界面设计由 Kimi 承担（`kimi -p` 任务书模式）；Claude 负责数据层与骨架、任务书钉硬约束、三道验收（浏览器实开＋renhua 文案＋数字对账）。UI 文案零开发黑话（renhua 铁律，领域词就地配人话、单位人话化）。
3. **15900 一次性退役**：拆除门槛＝全套视图平替验收通过；演示合成账本搬 daemon 查询面 `?demo=1`。退役拆的是浏览器页面，daemon HTTP 数据面不动。
4. **分期修订（2026-10-05）**：原定案「七视图一场交付、不分期」修订为「设置视图先行交付，其余六视图随后一场交付」。为何：工作场截至 10-05 未开工（无计划文档、无 mock），而设置编辑是日常刚需；等整场＝不可预期的等待。分期只切设置视图一片，六视图之间仍一场交付。

## Consequences

- W0 前置不变：widget 0.2.6 生产线（分支未归并，main 停 0.2.1）须先归并，任何工作台视图才有底座。
- ADR-0016-ferry 决定五中「widget 不做 GUI 配置」由 ADR-0022 修订；ADR-0014 的「纯读消费者」措辞随 ADR-0022 修订（写一律经 daemon、自身永不自持凭据不变）。
- 本篇补录即承认流程缺口：定案未落库 5 天。后续跨会话定案当场上 ADR，不留「只活在记忆里的定案」。

## 重开条件

分期修订可再收拢：若设置先行导致壳内导航/信息架构返工（设置视图先行做出的壳形与后续六视图打架），回退到一场交付重排。
