# 悬浮窗几何自愈：断言设计尺寸，不追防系统

2026-09-29 真机事故：RDP 断开重连后悬浮窗塌缩成 60×275 物理像素窄条，状态信息不可读。诊断链（RDP 事件日志、持久化文件时间戳、代码全量检索）：RDP 断开瞬间会话 DPI 150%→100%，Windows 将窗口物理尺寸 ×2/3，重连回 150% 后不还原；长活进程内逐次累积——实测 930×(2/3)³=275，与当日三次断开精确吻合。widget 代码从不写窗口尺寸（`resizable:false`，Rust 侧唯一几何写操作是 `set_position`），防不了系统行为；事件面只听 `CloseRequested`/`Moved`，塌缩无感知、无自救，只有进程重启才能回到 conf 默认尺寸。

决定（2026-09-29 grill 定稿）：

- **几何自愈（watchdog）**：设计尺寸 132×620 逻辑 px 定为不变量——窗口不可缩放，"内容完整最小尺寸"即唯一尺寸。几何事件流（`Moved`/`Resized`/`ScaleFactorChanged`）静止 250ms 后断言：物理尺寸偏离设计值（±2px 容忍取整抖动）即 `set_size` 拉回，并把位置夹回所在屏工作区（塌缩恢复后右/下缘可能压出屏外）。另设 5s 轮询兜底，事件全漏的极端场景下发现时限仍有界。
- **不押注单一事件种类**：实测塌缩时 `Moved` 必发（位置在重连秒级被保存）、`Resized` 未必发，断言对全量事件流静止触发。
- **持久化仍只记位置**：自愈断言的是设计值，无需记忆尺寸；也不能记尺寸——RDP 转换期间落盘会把系统造成的坏值存下来。

## Considered Options

- **可缩放 + 持久化尺寸**（window-state 插件路线）：被否——spec 钦定不可缩放（20260921 spec），且尺寸记忆会把系统造成的塌缩值一并存脏。
- **只防不治**（DPI/显示变化时主动预补偿）：被否——塌缩的确切机制在系统/tao 层、未钉死（重连的放大为何不发生仍存疑）；预防押注机制猜测，断言对任何原因的偏离都收敛。
- **重启即恢复**：事实成立（conf 默认尺寸覆盖塌缩值）但不可接受——用户高频断连（09-29 一天 5 次），每次手工重启不是解。

## 后果

每次几何事件静止做一次 `outer_size` 读+比较，尺寸无恙时零成本通过不碰窗口；断言动作会再触发一轮事件流，收敛于"尺寸已正→断言通过"。位置被夹动才落盘（与磁吸贴边同习）。启动 2s 静默窗内不动作（不吸走用户存的边距），窗内塌缩由轮询兜底。未来若窗口改可缩放（票 09 高度自适应方向），不变量须改为"断言持久化的用户尺寸"——届时修订本 ADR。
