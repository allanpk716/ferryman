## 1. 第一步·拍基线（tap 捕获 cc-switch 真实出站形态）

> 目的：第一次拍到 cc-switch 的真实出站形态（golden）。此后任何路径（渡口改写版）的等价性都对着这份 golden 做差分，"等价"从推断变成测量。

### 1.1 前置检查

- [ ] Go 在位（`go version` 可跑）、python 可跑（diff.py 用）。
- [ ] cc-switch 正常服务（15721 在听），CC 经它正常对话。
- [ ] **真钥警告**：tap 不脱敏，请求头（含真钥）原样落盘捕获目录。捕获目录不进 git、验完即删、权限收紧（工具自带 0o700/0o600，Windows 为 best-effort）。不要把捕获目录分享/提交。

### 1.2 操作

起 tap（后台常驻窗口）：

```bat
cd /d <repo>
go run ./experiments/router-fidelity -listen 127.0.0.1:15723 -out %USERPROFILE%\ferryman\router-fidelity
```

flag 实名（tap.go）：`-listen`（默认 127.0.0.1:15723）、`-upstream`（默认 https://open.bigmodel.cn/api/anthropic）、`-out`（默认 ~/ferryman/router-fidelity）。自检：

```bat
curl -s http://127.0.0.1:15723/__capture/ping
```

（回 `ok` 即 tap 在位；此端点零捕获。）

把 cc-switch 里 GLM 供应商的 base_url 临时改为 `http://127.0.0.1:15723`（cc-switch 界面/DB 均可改，可回）。此时链路＝CC → tap(15723) → bigmodel。

按场景清单驱真 CC（每个场景一轮真实请求，花费＝积分级）：

- 场景清单件已随本版落库：`python -X utf8 experiments/router-fidelity/scenarios.py --list` 列全 9 类 13 条场景，逐场景驱动（s08 含 ai-title 的 session_id 归属实测、s09 含 count_tokens 存在性确认）。
- 清单件不可用时的兜底：按研究文档 §3 场景矩阵人工驱动 CC，至少覆盖：四档模型别名（opus/fable/sonnet/haiku）；子代理派发回收（真名直发）；`[1M]` 后缀有/无；单轮与多轮；工具调用往返；图片块（media 降级路径）；长前缀（41k+）；ai-title 后台小请求。

跑完恢复：cc-switch base_url 改回原值 → Ctrl+C 停 tap。

### 1.3 验证

- [ ] 捕获落盘：`~/ferryman/router-fidelity/` 下 `*_reqNNN.json` 与 `*_respNNN.json` 按 seq 成对（每场景一对）。

## 2. 第二步·透传版上线（渡口挂在 cc-switch 之上）

> 目的：daemon 进入 CC 流量路径（CC → 渡口 15722 → cc-switch 15721），行为与直连完全一致；为心跳 enforce 备好快照源；为第三步备好灰度退路。

### 2.1 前置检查

- [ ] 第一步基线已拍并归档（golden 在位）。
- [ ] cc-switch 15721 活着；当前 config.toml 备份一份：

```bat

```

### 2.2 操作

## 3. 第三步·改写版上线（须 L1-L3 全过才做）

> 前提硬门：§6 四条决策门全过、L1/L2/L3 记录在案，才允许动本节。跳步＝违反红线。

### 3.1 前置检查

- [ ] §6 门 1-4 全过且有记录（L1 diff=0 或差异全解释；L2 cacheRead 一致＋套餐 4 格结论；L3 全功能清单；漂移告警在位）。
- [ ] bigmodel 真钥在手（只写进本机 config.toml，永不入 git/日志/账本）。
- [ ] 守卫规则预读（guard.go，`ferryman doctor` 与构造期共用同一判据）：
  - `rewrite_enabled=true` 但 `model_map` 缺 `default` 键或值为空 → 拒绝进入改写、退回纯透传＋告警；
  - `rewrite_enabled=true` 且 upstream 指回回环主机上的 **15721/15722/15723** 任一端口 → 判双重改写风险，拒绝进入改写、退回纯透传＋告警。**这意味着改写版验证时 tap 不能架 15723 被渡口指向——用 15724。**

### 3.2 操作

config.toml `[dock]` 节补齐（示例值以外，档位名以 L2 验证期实测映射为准）：

```toml
[dock]
listen = "127.0.0.1:15722"
upstream_base_url = "https://open.bigmodel.cn/api/anthropic"
rewrite_enabled = true
api_key = "<bigmodel api key>"
text_only = ["GLM-5.3"]

[dock.model_map]
default = "glm-5.3"
```

- `model_map`：别名键（claude-opus-5 / claude-fable-5-1 / claude-sonnet-5 / claude-haiku-4-5）按需补齐映射到 GLM 档；`default` 必填（未知名兜底）；子代理真名（如 `glm-5.3-flash`，剥 `[1M]` 后）精确匹配映射表则原样透传。
- `text_only`：命中名单的目标模型收到 image block 时降级文本占位。
- `balance_url`：默认 `https://open.bigmodel.cn/api/user/balance`，一般不用写（同 key 只读查询）。

重启 daemon，`ferryman doctor` 确认渡口守卫行 OK。

## 4. 看门停用流程（维护 / 换 exe 前）

> 铁律：**停进程 ≠ 停服务**。看门计划任务（任务名 `FerrymanWatchdog`）每 5 分钟调一次 `ferryman watchdog`，探到 7311 无监听就拉起 daemon。不停看门就维护，5 分钟内会被复活、新旧 exe 混跑。

```bat
ferryman watchdog uninstall
schtasks /Query /TN FerrymanWatchdog
```

（第二条应报任务不存在；`ferryman watchdog status` 等效。）

1. 停 daemon：托盘「退出」或关 start-daemon 窗口；确认无监听：

```bat
netstat -ano | findstr :7311
netstat -ano | findstr :15722
```

2. 维护 / 换 exe（build.ps1 产物覆盖仓库根 exe；注意 Run 键自启指向的点火脚本不变）。
3. 复装并复核：

```bat
ferryman watchdog install
ferryman doctor
```

doctor 复核两行：`Run 键自启在位（HKCU Run\Ferryman）`、`看门计划任务在位（下次运行: ...）`。等价地 `ferryman autostart status` / `ferryman watchdog status` 各回 installed。 Run 键自启（第一腿）不受看门停用影响——注销重新登录仍会拉 daemon，纯停机维护时两腿都停（`ferryman autostart uninstall` 可临时卸 Run 键，完事 `install` 装回）。
手动立即拉起（不装看门时）：`ferryman watchdog`（无参＝单次探活，无监听即拉起）。

## 5. 心跳启用手册（[wait_window] 三态）

### 5.1 三态语义（config.go：`mode` ∈ off | observe | enforce，默认 off）

| mode | 行为 |
|---|---|
| off | 零行为（缺节即 off） |
| observe | 排程照走，发送走 NoopSender（零网络）；每跳按演练入账（outcome=observe） |
| enforce | 真发：按策略节律重放该会话内存快照（max_tokens=1）经渡口入站口 15722 出站，与真流量同路径同改写 |

- `[wait_window]` 键（config.go 实名）：`mode`、`manual_wait_cap_s`（>0＝手动等待上限，只能把策略算出的 cap 调小；0＝未配置）。间隔/最小前缀等参数**不在配置里**——全部由策略计算器（internal/policy）按价格与实测 TTL 现算（公式单源红线）。
- 与 `[question_watch]`（问询守望）平行的独立三态：mode/min_questions/beat_interval_s/max_beats/ferry_deadline_lead_s，互不影响（enforce 降级告警里会注明"问询守望不受影响"）。

### 5.2 通用前置：策略可用

间隔与 cap 由策略计算器推导，缺输入则**本进程内零排跳＋告警一次**（宁可不算不造数）。两样都要在 `~/ferryman/config.toml`：

- `[heartbeat]` 节：`ttl_s` 填实测 TTL（复测实验产物；顺带 `enabled`、`ttl_measured_at`、`ttl_source` 记档）；
- `[prices.*]` 价格表节（p_cache 等）。

缺任一，serve 日志/告警通道出现：`等待窗心跳无策略：策略计算器不可用（...）——等待窗泳道本进程内不排跳；配置 [heartbeat] ttl_s 与 [prices.*] 后重启生效`。

### 5.3 observe 演练先行（先看账本再真发）

```toml
[wait_window]
mode = "observe"
```

重启，等真实场景（主会话派子代理后进入等待窗）。读账本（明细看原始流水；`ferryman account report` 的汇总是摆渡经济口径，不含 beat/dock 明细）：

```bash
grep '"kind":"beat"' ~/ferryman/accounts/<YYYYMM>.jsonl
grep '"kind":"wait_close"' ~/ferryman/accounts/<YYYYMM>.jsonl
```

- `beat` 行（accounts.go 白名单）：`lane`（wait=等待窗 / qwatch=问询守望）、`outcome`（hit|miss|error|observe；observe=演练跳未真发）、`prefix_tokens/cache_read/cost_pred/cost_actual`。observe 演练期 `cost_actual` 恒 0（零网络）。
- `wait_close` 行（每窗一行汇总）：`beats_fired`、`cost_actual`、`main_resumed`（主会话是否回归）、`useless_warm`（**跳了、主会话没回来＝无效保温，恒写入账**）、`close_reason`、`dur_s`。

演练期核对三件事：等待窗正常开合（wait_close 行出现）、节律符合预期（beats_fired 合理）、无效保温占比可接受。数据说话后再拨 enforce。

### 5.4 enforce 前置

```toml
[wait_window]
mode = "enforce"
```

- **必须已配 `[dock]`**（第二步透传版即可——快照采集与心跳发送不依赖改写模式）。渡口是快照源＋发送路径。
- 渡口关（无 `[dock]` 节）时 enforce **自动降 observe** 并告警一次（不拒启）：`[wait] ⚠ [wait_window] mode=enforce 但未配置 [dock]（渡口关，快照源不存在）——等待窗侧按 observe 演练对待（问询守望不受影响；配置 [dock] 后重启生效）`。
- daemon 重启后内存快照必然丢失：窗口仍调度则该跳记 error（snapshot_missing），不阻塞调度。

### 5.5 已知边界（设计内，遇上了不要当缺陷）

1. **compaction 后首跳 miss**：主快照按"最大请求体"选取，上下文收缩（compaction）后最大体可能陈旧 → 该窗首跳 miss → 停窗告警。一次有界浪费；处置＝复测 TTL 或无视。
2. **策略不可用零排跳**：价格表（[prices.*]）或实测 TTL（[heartbeat].ttl_s）缺失 → 本进程内零排跳＋告警一次，绝不拍脑袋造数；补配置后重启生效。
