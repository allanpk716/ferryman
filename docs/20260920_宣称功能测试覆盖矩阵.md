## 夜间发现（F1-F7，2026-09-20 22:30 起记，09-21 晨补 F5-F7）

- **F1（门槛失效形态）**：`min_ctx_tokens=20000` 低于本机当前会话基线（系统提示＋插件＋MCP 面即超 20K）→ micro 单轮会话被摆渡。功能按码工作，参数已不匹配现实。**待拍板**：门槛上调到多少（建议 35-50K），或明确接受。
- **F2（L2 近死码）**：提取层按设计丢弃一切 tool_result、单条正文截 4000 字（防注入面最小化）——真实 CC 会话以工具往返为主，提取后几乎必在 L1。L2 仅"30+ 轮贴满文本对话"可触（受控实验已活体实证路径真）。**含义**：L2 的维护成本与触发概率需对账，属产品问题非缺陷。
- **F3（resume 首提无告警）**：W0.5 对已凉 A 会话 resume 首提，闸门未出 observe 告警（静默放行）。候选解释：新 session_id 首提时尚无台账闲置史（继承时序问题）或族系未及时关联。**observe 周内专项观察**：同形态复测一次（明日白天手动 resume 一个凉会话看 hook 输出）。
- **F4（window 语义）**：config `window=229376` 决定 L1/L2 边界（131072 仅缺省）——文档与配置漂移，晨报日已实证。
- **F5（重复摆渡 churn）**：周期写入会话（文档处理两个大会话，写一次→闲置 25min→全量重摆渡）死端口窗内产出 8 份骨架交接。local provider 成本≈0，但交接库噪音与全量重摘要浪费真实存在。**待拍板**：是否加增量抑制（新内容不足上一份 covers_until 之后 N token 则跳过）。
- **F6（observe 零账面记录）⚠️ 阻断 7 天判据**：账本科目只有 handoff/inject/usage/window 四种，observe 告警只活在 hook stdout（转瞬即逝）——"逐条归因"没有数据源，验收线判据二无法执行。**最优先修**：gate 判定入账（kind=block，verdict=observe/warn）。
- **F7（close_reason 分布异常，不确定）**：115 窗 = 110 main_resumed / 4 prompt / 1 expired / **0 subagents_done**——与规格"止于最后一个子代理完成"形态不符。候选：主会话续跑的 usage 行总是先到、覆盖 subagents_done 判定（分类偏好而非漏记）。待读代码定论。
