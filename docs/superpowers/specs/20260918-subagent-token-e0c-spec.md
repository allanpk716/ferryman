# Spec · e0c:Claude Code 子代理 token 记账测量实验

日期:2026-09-18 · 来源:xcheck 夜链(评审环 20260918-145834 + 复审环 20260918-151538,终态 夜间收工)
输入:共识文档 rev1(含评审附录)· 术语:CONTEXT.md「记账」一节

## Problem Statement

用户的主会话在执行阶段会拆出若干子代理并行干活,但没有任何工具能回答:主会话自身用了多少 token、每个子代理各耗多少、一共开了几次。原始数据(每子代理一对转录/元数据文件,含逐响应官方四列 usage)全部躺在磁盘上,却无人读取。需要一次测量实验拿真实数据,再决定是否把记账做成正式功能。

## Solution(用户视角)

一条命令(`ferryman e0c`)扫描本机全部 Claude Code 会话,产出一份中文实验报告:逐会话的 token 明细账(主会话行 + 各子代理行)、子代理占比与分布、与 CLI 自报数的对账结果、异常样本长尾清单。全程只读 `~/.claude/projects`,不改任何既有系统。

## User Stories

1. 作为 Ferryman 维护者,我想对任意历史会话出 token 明细账(主会话自身 / 每个子代理 self 与 subtree / 开启次数 direct 与 total),以便回答"这场会话到底花了多少、花在哪"。
2. 作为维护者,我想看子代理消耗占会话总账的比例及按类型 / 深度 / 实际服务模型的分布,以便决定是否把记账做成正式功能。
3. 作为维护者,我想在实验期间把 CLI 自报数与文件四列加总逐个对账,以便确认口径可信(拒绝玄学)。
4. 作为维护者,我想拿到异常样本(中断 / 空 / 在跑 / 不成对)的长尾清单,以便定型时知道防御边界。
5. 作为用户,我想一条命令跑完实验并直接得到报告文件,不需要手工拼数据。

## Implementation Decisions

**模块切分(解析层纯函数 + 编排层 IO)**:

1. **usage 聚合器(纯函数)**:输入一段 jsonl 文本(或按行迭代),输出该文件的账目:四列加总、响应数(唯一 message.id 数)、按行级 model 分组的四列、长尾信号。
   - 聚合规则:assistant 行按 message.id 分组;**优先取带 stop_reason 的行的 usage**;组内非零 usage 互不一致 → 该组入长尾(不计入总数旁的暗箱);无 message.id 的行跳过并计长尾;半行/坏 JSON 行跳过并计长尾。
   - 占位行(usage 全零或 null)不贡献账目。
2. **子代理账目装配器**:扫描会话目录 `<会话id>/subagents/`,meta 与转录配对;产出每个子代理:{agentId, agentType, spawnDepth, 描述, self 四列, 行级 model 分布, 首末时间戳, 终态推断}。
   - 不成对规则:有转录无 meta → token 照入总账,agentType=未知,depth=未知桶(不参与 direct/total 分桶与 subtree,toolUseId 能从转录内容恢复则恢复父子);有 meta 无转录 → 计数+1、token 记 0、标"无转录"。
   - 计数基准 = **spawn 事件数**(转录文件数 + 有 meta 无转录数);转录文件数另列。
   - 终态推断:最后一条非空行为 assistant 且组内最后响应 stop=end_turn → 完成;文件为空 → 空文件;其余 → 中断;mtime 距扫描 <5 分钟 → 在跑(非终值)。
3. **会话聚合器**:主转录(经 usage 聚合器)+ 全部子代理 → 会话总账;direct spawn count = depth=1 的 spawn 事件数;total = 全深度;subtree 按 toolUseId 父链聚合。
   - 交叉校验(direct 口径):主文件 Agent/Task tool_use 调用数 vs depth=1 meta 数 vs depth=1 转录数,差值进长尾;(total 口径)各父转录的直接子调用数合计 vs total spawn 事件数。
   - 族系合计行:复用台账既有 lineage 识别规则,输出链上会话 id 列表(识别依据),整行标注"识别未验证"。
4. **快照一致性**:每个被读文件记录(扫描时刻, 字节大小, 内容 sha256);会话级记录扫描窗口起止时刻;**扫描末尾重枚举会话目录一次**,窗口内新增文件标"扫描窗口外"进长尾;活跃会话整场标"在跑(非终值)",其账目不进终值口径汇总。
5. **对账手记通道(实验③唯一可行通道)**:实验执行会话在派发子代理时旁路手记任务完成通知里的自报总量;落盘为 jsonl(逐行 schema:{ts, agentId, agentType, self_reported_tokens, source: "task-notification"});对账时按 agentId 配对,残差逐个列出;样本不足 10 则如实报告实际数。不改钩子、不改台账、不新开监听。
6. **CLI 与报告**:`ferryman e0c` 子命令(沿用 e0/e0b 惯例注册进 `__main__`),扫描 `~/.claude/projects`,输出 `reports/e0c-cc-subagent-tokens.md`:四组问题各一节(Q1 逐会话明细账 / Q2 占比与分布[含回传耦合固定注记] / Q3 对账 / Q4 长尾清单)+ 定型建议(附判据,不附决定)。
7. **回传耦合注记(固定文案)**:子代理结果回传主会话后以 input/cache_read 形式再计入主会话后续请求,"子代理占比"结构性偏低、主会话偏高——占比只作方向参考。

**架构约束**:不触碰 daemon / 台账 / 钩子 / 既有解析器(守望器跳过 subagents/ 的决策不变);实验代码独立成模块,复用既有防御式读取风格但不改其行为。

## Testing Decisions

- 解析层纯函数全部用合成 fixture 单测(仓库既有 pytest 惯例):同一 message.id 拆多行重复 usage、占位行、无 id 行、组内非零冲突、半行 JSON、空文件、缺 meta、有 meta 无转录、depth=2 嵌套、末尾新增文件。
- 装配/聚合层:构造小型会话树 fixture(主文件 + 两个子代理 + 一个嵌套孙子 + 一个缺 meta 样本),断言会话总账、双口径计数、subtree、交叉校验差值、长尾清单内容。
- 端到端:对 fixture 会话树跑 CLI 入口,断言报告文件生成且关键数字正确;对外部行为断言,不测内部实现细节。
- 真数据报告为人工验收物,不进自动测试。

## Out of Scope

实时监控、Codex 侧、钱/价格换算、守望器/台账/钩子改动、对账残差(~2%)的解释——全部留待定型决策。

## Further Notes(评审附录存疑/无定论条目,开发时要盯)

- 对账残差 ~2% 未解释:报告如实列出;若实施中发现残差异常放大(如 >10%),停下反馈用户,别默默绕过。
- 族系识别复用台账规则,准确率未预验证:合计行必须带"识别未验证"标注;发现 lineage 链明显错乱时停下反馈。
- 在跑判定窗口(5 分钟)是经验值:长尾清单给出实际分布即可,不当场调。
- 开发时若发现磁盘格式与本 spec 假设不符(如出现内嵌 sidechain 老格式),停下反馈,不硬猜。
