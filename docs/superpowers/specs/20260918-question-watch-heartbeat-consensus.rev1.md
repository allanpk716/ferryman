## 1. 背景与动机

Ferryman 是本机常驻守护进程，守望 Claude Code 与 Codex 两个 CLI 的会话转录文件（CC：`~/.claude/projects/**/*.jsonl`；Codex：`~/.codex/sessions/**/rollout-*.jsonl`），维护台账（session_id → 最后写入时间、上下文规模等），据此做三件事：

1. 闲置超**总结阈值**（默认 25 分钟）→ **摆渡**：调外部廉价模型把会话上下文总结成交接 MD；
2. 闲置超**拦截阈值**（默认 35 分钟）→ **闸门**（提交前钩子）拦截继续使用，引导开新会话并自动注入交接；
3. 会话低于**最小上下文门槛**（`thresholds.min_ctx_tokens`，默认 20K token）→ 既不摆渡也不拦截。

目的：缓存失效后继续旧会话需全量重付输入费用，拦截引导换新会话＋注入交接更省。

**新痛点**：使用"拷问式"讨论技能时（典型输出形态：一条 assistant 消息里 5~10 个编号问题，要求逐条回答），用户组织长答案耗时 10~40 分钟，远超服务商缓存 TTL（当前主力服务商 GLM 实测约 10 分钟）。后果链：

- 缓存过期，答案提交时全量重付输入费；
- 闲置钟照走，第 25 分钟触发一次无意义的摆渡（花钱产出没人用的交接）；
- 第 35 分钟闸门直接拦截提交。

本设计新增第四种处置：**检测到"提问潮"时，判定用户正在组织长答案，对该会话提前发 1~2 次心跳**（heartbeat：以最小请求重放会话前缀、刷新服务商缓存的保活请求），**把缓存可靠命中窗口从 TTL 的 ~10 分钟延长到 ~24 分钟（默认两跳；每加一跳 +7 分钟）**。**这是会话级、条件化、默认关闭的独立功能，不是全局心跳开关。**

## 2. 领域定位：三种等待状态

| 等待状态 | 例子 | 现状 |
|---|---|---|
| 机器等机器 | 主会话等异步子代理跑完 | 异步等待窗口（已建成，仅 CC 轨）：闸门豁免、摆渡推迟、窗口入账 |
| **机器等人** | AI 问了一堆问题，用户在憋长答案 | **本设计，尚不存在** |
| 人不在 | 会话真凉了 | 摆渡＋闸门，既有职责 |

本设计的"等答复窗口"是异步等待窗口（停车窗）的兄弟结构，复用同一套台账状态位、摆渡推迟接线与隐私不变量，但**不改动闸门语义**（见 D6）。

## 3. 十项设计决定

### D1 · 定位与红线推翻

本功能即 Ferryman 第一个心跳执行器。既有 `docs/DESIGN.md` §9 设计红线"**不保活**"，以及 2026-09-18 定稿的异步等待信号 spec 之 Out of Scope（"心跳执行器未授权不实施"）需经 **ADR 显式推翻**。理由：红线原意针对无条件全局 keepalive（社区实测跨夜不可靠、持续烧钱）；本功能是条件化、会话级、短窗（默认最多两跳）的保活，语义不同。放行节奏：先 observe（只记录"会怎么跳"，不真发请求），后 enforce（见 D9）。

### D2 · 检测方式：v1 纯启发式，不接模型（rev1：判据收紧定型）

- **靶子**：最后一条 assistant 消息的**纯文本**（实测拷问式技能输出为纯文本提问块，如 `❓ **Q1** - **标题**` 格式；非结构化工具调用）。
- **判据原料**（先剥掉代码块再统计），"独立问题单元"计数规则：
  1. **标记行**：含 `❓`、`**Qn**` 类提问标记 → 计入；
  2. **问号行**：行内含 `？`/`?` → 计入；
  3. **编号/列表行**：仅当**行内同时含问号或疑问词**（什么/怎么/为何/如何/哪个/是否/要不要/what/how/why/which/whether…）才计入——纯步骤/计划/汇报清单**不计入**；
  4. 去重合并计数。
  **实验定型依据**（exp/heuristic-fp.py，近 14 天 272 条真实末条 assistant 消息）：松判据（编号行全计）触发 163 条（60%，样例全为状态汇报/评审报告/票台账）；紧判据触发 10 条（3.7%，存活样例为真实提问潮）。**判据按紧档定型，不留给 observe 期再选**。
- **AskUserQuestion 工具调用（rev1：修复互斥）**：若转录末尾悬空的 tool_use 集合**仅由 AskUserQuestion 构成**，视为"正在等用户作答"——这恰是本功能的靶场景，**不阻止**等答复窗口开启（question-watch 自有命中确认谓词，含豁免名单；共享的悬空判定函数不改动，摆渡推迟路径继续按"在跑"处理）。其 questions 数组长度直接计入问题单元数。
- "一次一问"式讨论（brainstorming 类技能原生形态）天然不触发阈值。
- **不接语言模型**：零边际成本、可单测、不依赖网络；模型判断留作二期可选项（届时复用既有摆渡路由的模型调用路径，不需新增 API key 配置——仅指**检测**环节；心跳执行器路径另见 D4，与摆渡路由无关）。

### D3 · 阈值：独立问题单元 ≥5 触发，起步偏松（rev1：显式假设）

- 默认 **≥5**，配置可调。
- 偏松的理由基于**显式假设"跳必命中"**：误报代价＝两跳的缓存读价＋两小段输出费——该估算仅当 TTL ≥ 跳间隔稳定成立；GLM TTL 实测约 10 分钟但方差未建模，**单跳 miss 的真实代价是全前缀按输入价重读**。此假设由 D10 的 cacheRead 遥测持续证伪：连续 miss 即触发异常告警并自动暂停 enforce（降回 observe），不允许在 miss 状态下继续烧钱。
- observe 段实跑数据出来后回调（漏得多往 4 调，误报多往 6 调）。

### D4 · 次数、节奏与保形（rev1：覆盖上限如实化＋执行器保形验收）

- **需求方明确决定**：跳几次是这个检测模块自己的配置常数，**不与费用相关模块挂钩做动态推算**（记归记，算归算：每跳费用照记入账本，但账本数据不反过来指挥跳几次）。
- 命中确认（见 D2 谓词）后：**不立刻跳**（刚落盘的回复本身刚刷过缓存）；第 1 跳在命中后 **~7 分钟**（≈0.8×GLM 实测 TTL 10 分钟），第 2 跳再隔 **~7 分钟**，**上限 2 跳（默认）**。需要更长覆盖时**手改 `max_beats`**：每 +1 跳，可靠覆盖上限 +7 分钟。
- **覆盖上限如实声明**：默认两跳把缓存**可靠命中窗口保到 ≈ 命中后第 24 分钟**（t=0 落盘刷新→t≈10 失效；跳@7→t≈17；跳@14→t≈24）。t∈(24, 35) 是**已知死区**：缓存已死、闸门未拦、交接按 D6 死线在 t≈27 生成——用户在此区间提交＝全量重付但不被拦（有交接可用）；>35 分钟提交＝闸门拦截＋交接引导开新会话。**本功能不宣称"保到用户提交为止"，只宣称把保护窗从 10 分钟扩到 24 分钟（默认档）。**
- **执行器保形硬要求（rev1 新增，enforce 前必须全部成立并固化为回归测试）**——依据既有抓包实测与保真度实验方案（Q14）：
  1. beat **直打本地代理 `127.0.0.1:15721`**（cc-switch），不持有真钥；
  2. **发 CC 别名**（如 `claude-opus-5[1M]`），别名反查 settings.json `ANTHROPIC_DEFAULT_*_MODEL` 或 cc-switch DB 映射——发 jsonl 回显的上游名会被代理映射进 default 档，**必 miss**；
  3. 重放前缀 = `[system + tools + u1…uN]`（不含末轮 assistant 输出），与 CC 真实请求**逐字节等价**（BeatBuilder 与抓包模板逐字段 diff 全等才放行）；
  4. **不与摆渡路由共用任何路径**——摆渡走外部廉价模型的 chat/completions，与 CC 的 Anthropic 形状请求是两条通道，形状不同必 miss。
  验收 = Q14 段二（diff 全等）＋段三（3 臂实跳，首跳 cacheRead ratio ≥0.85×3、续跳 HIT、对账矩阵排除自我续命）通过，且请求形状锁定为回归测试。Q14 现状：段一（真实请求捕获＋形状规格）已完成（捕获模板在 `~/ferryman/captures/`），段二/三未执行（预算上限约 100~120 GLM 积分，enforce 放行前执行）。

### D5 · 取消语义、竞态防线与能力边界（rev1：加竞态防线）

- 每跳**发送前两道验**：①自计划开始后该会话**有任何新写入 → 整个计划作废**；②**发送瞬间二次新鲜度检查**——重新 stat 转录文件 mtime+size，与计划快照不一致 → 取消本跳并作废计划。守望轮询 3 秒 → 取消延迟 ≤3 秒；check-then-act 竞态由②压缩到"单次 stat 到 HTTP 发出"的毫秒级残余窗口，调度器与台账读取共享同一把 RLock 串行化，残余窗口命中记台账事件备查（不追求归零）。
- 已在途的请求不可撤回（HTTP 已发出），代价一次缓存读价——**以跳必命中为前提**（见 D3 显式假设与证伪回路）。
- **能力边界**：打字草稿不写会话文件、不可见；只有用户**提交**（新写入落盘）才触发取消。打字期间正是心跳的工作窗口。

### D6 · 闲置钟与等答复窗口（rev1：摆渡死线常数化＋失败兜底）

- 现状：闲置＝距台账所记最后一次写入的时长；心跳不产生写入。等答复期间闲置钟照走：第 25 分钟摆渡误触发、第 35 分钟闸门拦截——保活成功提交却被拦。
- **决定**：检测命中的会话挂"**等答复窗口**"（台账态，异步等待窗口的兄弟结构）：
  - **摆渡推迟但带硬死线**：窗口开启期间摆渡入队被推迟，**最迟在 `ferry_deadline_s = block_s − 8min`（默认 t=27，`ferry_deadline_lead_s = 480` 可配）强制入队**——给摆渡执行保留与既有机制同量级的余量（既有：总结 25→拦截 35，共 10 分钟；本设计 8 分钟略紧但摆渡模型调用实测远小于此）；
  - **失败兜底**：摆渡模型失败/超时走**既有骨架交接降级**（`_save_skeleton`，确定性骨架不过模型）——"被拦 ⇒ 交接必已存在"的不变量在等答复路径与既有路径**同一水位**成立；闸门不等待摆渡（沿既有语义：无交接时第二分支拦截，骨架路径把该分支的可达性压到与现状持平）；
  - **闸门语义一字不动**（仍 35 分钟拦截）；
  - 窗口随任何新写入（用户提交）立即关闭，摆渡恢复正常调度。
- 理由：默认两跳保到 t≈24，死线在 t=27 生成交接，t∈(24,35) 提交者全量重付但有交接可看，>35 提交者被拦且有交接引导开新会话贴答案。备选方案"等答复期间闲置钟暂停/心跳计入台账活动"仍被否：动了"判定只依据台账"的根基，且检测器误报会让会话长时间脱离闸门护栏。

### D7 · 作用域（rev1：去重复阈值）

- 独立配置节 `[question_watch]`，**默认 off**，与将来任何全局心跳互不牵连。
- **CC 轨先行；Codex 轨缓行**（Codex rollout 无结构化提问信号、文本启发式误报率高一档，且异步等待窗口也仅 CC 轨，两轨同频推进）。
- **最小前缀门槛：不另设新常数，直接引用既有 `thresholds.min_ctx_tokens`**（默认 20K）——单一配置源，两处语义共用（"低于它的会话不值得保活/摆渡/拦截"），杜绝双常数漂移。

### D8 · 可见性与复核证据形态（rev1：定义证据形态）

- 心跳（含 observe 演练跳）作为**事件落台账** → 时间线查看器（viewer）展示 → `/stats` 出计数与累计花费；另配一键停（配置开关）。
- **复核证据形态（enforce 条件③的据以判误报的清单字段）**：每条命中记录 = `session_id ＋ 命中时间 ＋ 问题单元总数 ＋ 判据构成（标记行/问号行/合格编号行各几条）＋ 转录文件绝对路径`；viewer 提供一键跳转/复制路径，人工拿路径开原转录核对该消息是否真提问潮。**不落消息内容**（隐私不变量不破：定位信息不是内容）。

### D9 · 放行节奏：三态开关，永不自动升级（rev1：Q14 状态锚定）

- `mode = off | observe | enforce`（对齐闸门三态词汇）。
- 升 enforce 三条件**全部满足**：① observe 跑满一周**或**累计 ≥10 次命中；② **Q14 段二（BeatBuilder 逐字节 diff 全等）＋段三（3 臂实跳通过）完成**（段一已于 2026-09-18 完成）＋ D4 保形四条硬要求固化为回归测试；③ 需求方按 D8 证据形态人工复核命中清单后点头。
- 切换永远人工拨开关，系统不自动升级；D3 的连续 miss 自动降级（enforce→observe）是**安全熔断**，不算升级路径。

### D10 · 记账与隐私不变量（rev1：遥测承担假设证伪）

- 每跳逐条记账（时间/会话/token/实收费用）入既有费用账本；**心跳的 cacheRead 即线上 TTL 遥测**：①证伪 D3"跳必命中"假设——连续 miss 触发异常告警＋自动暂停 enforce；②监测服务端缓存策略漂移——突变记异常。
- **隐私不变量**（沿用异步等待窗口先例）：检测判定只出 bool/计数，台账与账本**永不落消息内容**（D8 的转录路径是定位信息，允许）。

## 4 · 时序示例

```
t=0     提问潮落盘（此写入本身已刷新缓存，TTL≈10min）
        检测命中（D2 谓词：提问潮 + 悬空集 ⊆ {AskUserQuestion} + 无子代理在飞）
        → 开等答复窗口，排心跳计划（默认 2 跳）
t=7min  第 1 跳（两道验通过：无新写入 + mtime/size 与快照一致）→ 缓存续到 t≈17
t=14min 第 2 跳 → 缓存续到 t≈24
t=12min 用户提交（变体 A）→ 窗口关闭 + 第 2 跳取消（≤3s）→ 缓存命中，答案生效 ✅
t=27min 未答（变体 B）→ 摆渡强制入队（死线 block_s−8min），失败降级骨架
t=30min 提交 → 缓存已死（>24）全量重付；闸门放行（<35）；交接已生成可看
t=36min 提交 → 闸门拦截；交接引导开新会话贴答案
```
