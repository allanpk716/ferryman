# 收尾点亮役 · 实施规格(spec)

> 来源:评审对象 `.xcheck/20260925-074037/proposal.md`(rev1)+ 同环 decisions.md / FINDINGS.md;两轮异构评审(codex/kimi)终态=夜间收工。本规格只继承已确认共识、必要修复与验收预期;三个用户决策项(D1/D2/D3)未拍板,对应行为全部暂停,见「活动约束映射」。
> 术语遵守 CONTEXT.md 词汇表;相关 ADR:0014(widget 子项目)、0012(渡口多上游)、0006(不自动开 PR)、0008(并发帽)。

## Problem Statement

悬浮窗战役与渡口直连启用役留下若干尾巴:widget 的轮询框架在网络失败时只会固定 30s 重试、从托盘恢复时不立即刷新(评审遗留 M2);Kimi 供应商把重置时刻发成数字字符串时倒计时会静默丢失(评审遗留 M3);报表 JSON 输出曾出现非法转义(现行不复发,但无回归钉);另有三项等用户拍板的工作(/stats 坏死余额行删除、Kimi/DeepSeek 点亮、widget 自升级通道)。

## Solution(用户视角)

- daemon 不可达时,悬浮窗灰化并以递增间隔自动重探(10s 起指数退避、60s 封顶;恢复后回到 30s 常规周期);用户从托盘把窗口重新显示出来(或再次启动触发单实例拉起)时,数据立即刷新一轮。
- Kimi 返回数字字符串时间戳时,重置倒计时照常显示。
- 三项待拍板工作在用户逐项确认后按本规格「活动约束映射」节的内容执行,夜里不代拍。

## User Stories

1. 作为悬浮窗用户,我想要 daemon 不可达期间小窗以递增间隔自动重探(10s→20s→40s→60s 封顶),以便既不空转打满请求、也不至于太久才恢复显示。
2. 作为悬浮窗用户,我想要从托盘恢复或重复启动唤起窗口时立即刷新一轮数据,以便看到的不是旧值。
3. 作为悬浮窗用户,我想要任何一轮请求与"立即刷新"并发时轮询节奏保持正常(不出现双链翻倍),以便退避与刷新语义可信。
4. 作为悬浮窗用户,我想要 Kimi 把重置时刻发成数字字符串(秒或毫秒)时倒计时照常显示,以便额度窗口信息不缺。
5. 作为维护者,我想要报表 --json 输出带合法性回归钉(含 Windows 反斜杠路径的行),以便未来任何手拼 JSON 发射器回归立即被测试抓住。
6. 作为维护者,我想要 /stats 移除永远查询失败的坏死余额行(待 D1 拍板),以便健康面不再出现误导行。【暂停】
7. 作为用户,我想要悬浮窗点亮 Kimi/DeepSeek 两家余量圆控件(待 D3:钥匙供给),以便一屏看全三家供应商。【暂停】
8. 作为悬浮窗用户,我想要自动升级通道不被主程序发版打断(待 D2:通道方案拍板),以便随时能收到 widget 更新。【暂停】
9. 作为维护者,我想要发版文档如实记录"选项按默认实施、待确认"状态,以便文档不把未决写成已决。(评审 F8 的纪律要求)

## Implementation Decisions

**轮询框架(故事 1/2/3)**
- 由固定间隔定时器改为自适应 setTimeout 链:成功后 30s;失败后 10s 起指数退避(10→20→40→60s 封顶,连续失败计数封顶 4),成功即复位。
- 并发不变量:任意时刻至多一条调度链。以代际令牌(generation)实现:每次"立即刷新"递增代际,旧代际的链在下一个调度点比对失效即自弃;请求在途时的"立即刷新"允许两个幂等只读请求短暂并行,但不产生第二条常驻链,也不泄漏定时器。
- "立即刷新"触发面 = 窗口的两类用户可见恢复入口(托盘菜单"显示悬浮窗"、单实例重复启动拉起);由壳层向前端发一个无载荷事件消费。初次启动显示不属"恢复"(首轮本就立即拉取)。daemon 自行复活没有事件可感知,靠退避重试收敛(最坏 60s)——这是票面语义的诚实边界,不新增 daemon 侧事件。
- 兜底硬化(评审 F10 附注,一行级):链式调度下任意未预期异常不得永久杀死链——把"解析取数目标"一并纳入失败处理,任何意外异常视同本轮不可达走退避。
- 对外导出面变化:轮询启动函数的返回值从单一停止函数改为 `{stop, poke}`(唯一调用方同批适配);新增失败重试基值与上限两个导出常量。

**Kimi 重置时刻数字串(故事 4)**
- 解析规则:字符串先剪首尾空白;依次尝试既有 ISO 布局;全部失败后按纯数字解析,秒/毫秒自动判位(阈值 1e12,与数字形态同款),≤0 或非数字判无重置。带空白 ISO 串因此也被接受——显式申报的宽容化(提交信息点名),不改数字形态语义。

**报表 JSON 回归钉(故事 5)**
- 在既有报表 CLI 测试上加强:构造含 Windows 反斜杠路径的行,断言 --json 全量输出可被严格 JSON 解析且含核心键。纯测试加固,无生产码改动。

**待拍板三项的内容基线(夜里不执行,拍板后按此做)**
- D1(/stats 坏死余额行删除):从健康面移除该键与其取数函数;其余引用该函数的余额查询模块随之退役;配置里的余额端点字段保留为惰性(动它连坐配置迁移测试,另役处理)。可单次提交回滚。
- D2(升级通道,默认选项 2"固定指针"):发版流水线在版本化发布完成后,自动维护一个常驻"最新指针"发布对象——移动指针 tag、重建同名 Release 并挂更新清单资产;该常驻 Release 须标记为预发布,以免占据仓库"最新版"展示位并保护主程序升级通道的 latest 语义;升级端点指向该常驻 Release 的清单文件。文档注记措辞必须是"按默认选项 2 实施(D2 待用户确认,不同意可改选)",不得出现"已拍板"字样。
- D3(点亮两家):本机渡口配置追加两条上游条目(端点与模型映射按既有预置形状),钥匙由用户在场提供;重启守护后悬浮窗自动出新圆控件。月度 token 估算口径会随多上游消失单上游兜底而下降(降幅≈直连切换前的旧模型名行用量),属诚实归属口径,非缺陷。

## Testing Decisions

- 外部行为测试,不测实现细节;沿用仓库既有先例(包级 go test 纯函数夹具、widget 零依赖静态断言脚本)。
- Kimi 解析:表驱动单测(秒/毫秒数字串、非数字、空串、≤0、ISO 不回归、全链路进窗)——先写失败测试跑红,再最小实现跑绿。
- 报表回归钉:捕获 CLI 输出做严格 JSON 校验。
- widget:静态断言追加四条(退避常量、代际防护、poke 导出、恢复事件接线)——断言正则必须与所开代码形态逐字匹配(评审 F9 教训:箭头包装调用不得再用裸函数名字面量匹配);Rust 侧编译检查;人工冒烟清单按修正后口径撰写("当前退避间隔内自愈,最坏 ≤60s")。
- 会话内只跑限定包测试与单脚本断言(Windows 零闪窗纪律);全仓测试不在夜链会话内裸跑。
- 每票落地即跑票内声明的局部验证;票级评审只喂票 diff 与验收标准。
