# 同模型摆渡实施规格(2026-09-22,xcheck 夜链固化)

> 决策依据:ADR-0016(复审收敛版)+ 本链 decisions.md(D1-D14 已确认)。术语一律遵根目录 CONTEXT.md。评审遗留非阻断参考(F5 冷启动 bootstrap、F6 跳过原因编码、判热时钟数据源)已内嵌相应节。

## Problem Statement(用户视角)

会话快凉时,摆渡要请一个第三方便宜模型把整个转录重新读一遍才能写出交接的叙事部分——转录按第三方输入价全价计费,而这份上下文在本会话自己的渡口上游那里明明还有一份热缓存。用户想要:趁缓存活着,让会话自己的上游来写这段叙事,前缀按缓存读价计费;缓存死了就一切照旧,不多花一分钱、不改变任何既有时机。

## Solution(用户视角)

摆渡多一档"同模型":闲置约 20 分钟(而非等到 25 分钟总结阈值)且判定缓存还热、上游在已验证白名单内时,把捕获的会话请求体原样重放、只在末尾追加一条"写交接叙事"的指令,让原模型续写;判冷或不在白名单就静默跳过,25 分钟的第三方/骨架档分毫不动。档位默认关闭;任一上游要真正启用,必须先通过一发"追加重放实跳臂"实验。配套:阈值由策略计算器按上游现算(带证据的推荐值),扫参建议按 manual/recommend/auto 三档应用,面板能看全配置与三列值,按钮只在 CLI。

## User Stories

1. 作为多上游用户,我想要摆渡在缓存还热时用会话自己的上游生成交接叙事,以便前缀按缓存读价(约 1/4~1/50 输入价)计费而非全价。
2. 作为多上游用户,我想要判冷或上游不在白名单时摆渡静默等回原总结阈值,以便第三方/骨架的触发时机、遥测口径与费用分布不被改变。
3. 作为付费用户,我想要同模型档默认关闭、每家上游经实跳臂验证后才能启用,以便不为未验证的收益付学费。
4. 作为参数使用者,我想要策略计算器按该上游的 TTL 观测与价格现算触发阈值并钳位在 [10min, 总结阈值],以便参数有依据、不拍脑袋。
5. 作为参数使用者,我想要扫参定期产出带证据的建议值,并按 manual/recommend/auto 三档决定谁来应用,以便建议自动出、应用权在我、auto 有护栏。
6. 作为配置查阅者,我想要在面板看到全配置总览(密钥打码)和"配置值/生效值/建议值"三列按上游分列,以便不翻文件就知道什么在生效、有什么可调。
7. 作为配置变更者,我想要接受/拒绝建议的唯一写路径在 CLI(`ferryman tuning status/apply/reject`),配合托盘气泡提醒,以便配置变更是可审计的人手动作。
8. 作为记账核对者,我想要同模型费用进 handoff 科目带 lane 标注、跳过事件带独立原因,以便分档核算不混淆。
9. 作为守护进程运维者,我想要 doctor 检查同模型与调参的配置矛盾,以便静默失效早发现。

## Implementation Decisions

- **执行机制**:复用心跳捕获重放通道(internal/dock 快照 + internal/beat 发送器)新增"追加重放"形态——前缀字节不动,末尾追加一条摆渡指令消息,放开 max_tokens(封顶);响应只取模型叙事,走既有"确定性骨架+模型叙事"合成,交接产物结构不变。失败链:stop_reason=tool_use 或输出不合交接 MD 结构 → 判该档失败 → 第三方摆渡 → 骨架;同模型档不重试。
- **调度与判热**:同模型触发点独立于总结阈值(watcher 层新触发时点,冷启动种子 20min,计算器供给);判热时钟=距该会话最后一次上游请求(含体外心跳重放)的时长+该上游 TTL 观测闭式预判(数据源:心跳/渡口遥测流水,实施票钉死读取源);台账闲置(闸门语义)不动。判冷或白名单未中或未启用:该次触发零模型调用,静默交还,遥测记"同模型跳过"事件,原因独立编码(cold / whitelist_miss / not_enabled)。
- **上游白名单与启用门**:配置按上游登记白名单;白名单预置 ≠ 启用——每上游维护"实跳臂结论"状态,四条成功标准(①追加后仍命中,缓存读占比≥同前缀心跳基线;②与捕获快照字节差异仅末尾追加段;③无 tool_use;④输出可解析为交接 MD)全过才置启用;实验工具就绪为验收,实际实跳由人执行(需真实上游调用)。首发预置智谱;DeepSeek 同工具就绪待实跳;Kimi 与本地中转不预置。
- **参数供给**:internal/policy 计算器扩展按上游推导同模型阈值,钳位 [10min, 总结阈值];生效值/建议值按上游分列;手编配置上限默认全局单值、可按上游覆盖;manual 档配置值=生效值,recommend/auto 档为上限。反跑(internal/backtest)评分总体扩到闲置/摆渡事件,扫参网格纳入同模型阈值。
- **调参三态**:[tuning] mode=manual|recommend|auto,默认 recommend,永不自动升档;auto 五护栏(只改公式输入、钳位区间、每上游每周≤1 次生效、样本不足收敛只提醒、生效后通报+一键回滚);调参动作落状态目录 append-only 调参流水,不进账本。
- **交互**:托盘气泡通知+待审提示;CLI `ferryman tuning status/apply/reject <id>` 为唯一写路径;面板(15900)新增只读"配置与调参页"——daemon 提供脱敏全配置与三列值端点(密钥一律打码),面板只渲染不写。
- **记账**:同模型模型调用入 handoff 科目,结果码带 lane 标注(same_model/third_party/skeleton);跳过事件入遥测(usage/qwatch 同层),不入 handoff。
- **doctor**:新增检查——same_model 开而白名单空或全未启用;白名单条目无实跳臂结论;tuning=auto 而价格表缺 p_cache;同模型阈值与总结阈值钳位冲突。

## Testing Decisions

- 外部行为测试为主:配置解析与钳位校验(先例 internal/config/config_test.go);判热预测(给定 TTL 观测与时钟输入的冷/热判定);冷分支静默跳过与跳过原因编码(watcher 触发路径,先例 internal/daemon 现有测试);追加重放构造的字节保真(与捕获快照 diff 仅末尾,先例 internal/dock/snapshot_test.go);失败链回退;调参护栏(频控/钳位/样本门槛);面板端点脱敏(api_key 打码断言)。
- 不测:实跳臂的真实上游行为(人工实验);E1 评测质量(另役)。

## Out of Scope

- 实际执行实跳臂(需联网,工具就绪为验收);E1 评测实验。
- GUI 配置编辑;widget 侧任何改动;交接 MD 结构变更;闸门语义变更。
