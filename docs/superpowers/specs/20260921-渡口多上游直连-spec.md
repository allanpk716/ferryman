# 渡口多上游直连与换上游 · 实施规格(2026-09-21)

> 来源:夜链 20260921-110052 评审收敛稿(两环盲评+复审,终态收敛 1 轮修订);决策快照 D1–D16 与问题记录见 `.xcheck/20260921-111523/`(decisions.md / FINDINGS.md)。术语遵守 CONTEXT.md(渡口 / 渡口上游 / 摆渡供应商 / 换上游);架构决议见 ADR-0012。

## Problem Statement

用户在多个 LLM 供应商(智谱 CodingPlan、Kimi Coding Plan、DeepSeek 按量)之间切换,今天要靠链条外的桌面工具 cc-switch:CC → 渡口(本机 15722)→ cc-switch(15721)→ 供应商。切换动作发生在 cc-switch 层,多一层中转、多一套工具。用户要把供应商管理收进 Ferryman 本体:渡口直连各供应商、一条命令换上游、cc-switch 退役为回退条目,且不碰 CC 的任何配置。

## Solution

渡口获得一张"渡口上游表"(Anthropic 协议,每条带密钥与模型映射),`[dock].active` 单选;CLI 新增 `upstream list / use`,换上游 = 写配置 + 自动重启守护(几秒生效);旧单值配置首启零行为变化地迁移出 cc-switch 回退条目,并生成三条未激活预置(填 key 即用)。换上游即冷启动:内存缓存快照随重启清空,心跳自动跟随新上游,台账由启动扫描重建,交接库不受影响。摆渡供应商表(OpenAI 协议)完全独立,不参与联动。

## User Stories

1. 作为 CC 用户,我想 CC 永远指向渡口一个地址不变,以便换供应商时零改动 CC 配置。
2. 作为 CC 用户,我想用一条命令列出全部渡口上游(当前激活、各条可用状态、密钥脱敏),以便知道能切到谁、谁还没配 key。
3. 作为 CC 用户,我想用一条命令切换激活上游并在几秒内生效,以便低成本换供应商。
4. 作为 CC 用户,我想切换时被明确告知在途请求会中断、旧会话缓存按冷启动全量重付,以便对切换代价有正确预期。
5. 作为 CC 用户,我想切换后守护没起来时得到如实报错(配置已切、服务未起)与手动拉起/回退指引,以便自救而不是被沉默失败卡住。
6. 作为存量用户,我想升级后首启零行为变化(链路仍经 cc-switch,active 指向迁移出的回退条目),以便按自己的节奏迁到直连。
7. 作为存量用户,我想任何时候一条命令回退到 cc-switch,以便直连出问题时保命。
8. 作为新用户,我想首启就有智谱/kimi/deepseek 三条预置条目(未激活、key 留空占位),以便填一个 key 就能用,不必手搓配置。
9. 作为用户,我想面板余额行跟随当前上游(balance_url 每上游可配,不配不显示),以便看到的余额属于正在用的供应商。
10. 作为用户,我想 DeepSeek 的官方已知边界(不支持的消息类型与被忽略语义)在 doctor/文档列明、上游错误如实透传,以便不把它当本实现的故障。
11. 作为维护者,我想渡口上游表与摆渡供应商表完全分立,以便两条腿互不牵连、各自演进。
12. 作为维护者,我想心跳、台账、交接库在本特性里零改动,以便升级面最小、回归风险最低。
13. 作为维护者,我想对不存在的条目或缺 key 的条目执行 use 时被拒绝并如实报错,以便配置错误早暴露。

## Implementation Decisions

- **配置 schema**:`[dock.upstreams.<名>]` 条目 = base_url(必填)/ api_key / model_map(必含 default,可选 opus/sonnet/haiku 档位键)/ text_only(可选,默认 false)/ balance_url(可选);`[dock].active` 单选键。rewrite 隐含开启;上游为本地地址(回退条目指向 15721)时守卫强制透传、禁用改写(既有守卫规则)。
- **迁移与首启**:检测旧 `[dock]` 单值(upstream_base_url/api_key/model_map)→ 生成名为 `cc-switch` 的回退条目并**保持 active**(零行为变化);**同时**生成智谱/kimi/deepseek 三条未激活预置条目(api_key 留空占位)。幂等:迁移完成即写回新表并移除旧单值字段;二次启动检测到上游表已存在即跳过。
- **渡口转发**:转发目的地、出站密钥、模型映射、text_only、余额端点全部按 active 指向的条目取值;SSE 即时冲刷与透传保真口径(字节级或解析等价、usage 扫描)不回归。
- **模型改写(单层负责)**:一律改写为上游的**原生模型名**,不依赖上游对 claude-\* 名的二次映射;剥 `[1M]` 后缀→真名透传→别名映射→default 兜底的既有链条保留;count_tokens 同映射。
- **CLI 契约**:`upstream list` = 全部条目 + active 标注 + base_url/model_map 概要 + 可用状态(缺 key 显示"未配置,需手编 config 填 api_key")+ 密钥脱敏。`upstream use <名>` = 条目不存在→拒绝并列出可用条目;缺 api_key→拒绝并提示;通过→校验配置→原子写 config→触发守护重启→等健康检查;在途 SSE/长请求允许中断(输出如实提示);健康检查失败→命令失败退出,如实报告"配置已切换为 <名>,守护未起来",给手动拉起与回退指引;不自动回滚、不自动重试。
- **预置值**(实施期按各家官方文档核对拼写,终值用户验收):智谱 `https://open.bigmodel.cn/api/anthropic`,default/opus/sonnet→glm-5.3、haiku→glm-5.3-flash,balance_url=bigmodel 余额端点;kimi `https://api.kimi.com/coding/`,default/sonnet→kimi-for-coding、opus→k3、haiku→k3-256k(**不用 highspeed**——其"强制 thinking"属性未核实);deepseek `https://api.deepseek.com/anthropic`,default/sonnet/haiku→deepseek-flash、opus→deepseek-v4-pro。
- **余额**:`/stats` 与面板按当前上游的 balance_url 查询,不配不显示;替换现硬编码智谱端点。
- **不新增**任何对 CC 配置的写入;不新增 list/use 之外的命令。

## Testing Decisions

- **单元(外部行为)**:配置解析——新表读取、旧单值迁移(生成 cc-switch 条目+保持 active+生成三条未激活预置)、迁移幂等(二次启动跳过)、新表与旧单值并存时以新表+active 为准;model_map 映射(档位键/ default 兜底/ [1M] 剥离/真名透传);守卫——上游为本地地址时禁改写退透传;CLI——list 的状态与脱敏、use 对不存在/缺 key 的拒绝分支。
- **集成**:httptest 假上游验证渡口按 active 取目的地与换钥、改写与透传两模式;use 写配置→触发重启的健康检查路径(以可注入的启停接口测试)。
- **回归**:透传保真既有测试(SSE 冲刷、usage 扫描、头卫生)零回归;摆渡腿既有测试零改动。
- **先例**:沿用各包 table-driven `*_test.go` 风格;只测外部行为,不测内部结构。

## Out of Scope

WebUI 换上游控件(observe 周后另议)、Codex/OpenAI 协议、自动故障转移、热加载、按上游分拦截阈值、协议转换层、为任何上游注入 model 之外的字段(如 thinking)。

## Further Notes

- 维护纪律(仓库根 CLAUDE.md):中转 API 相关问题(协议兼容/流式/改写/供应商 quirk)必先读 cc-switch(farion1231/cc-switch)源码参考,禁止猜测。
- DeepSeek 官方边界清单(不支持 document/search_result/redacted_thinking/mcp_tool_use/mcp_tool_result;忽略 is_error/disable_parallel_tool_use/budget_tokens)随 doctor/文档列明。
- 非阻断留白(F8/F9,见 FINDINGS):迁移对旧可选字段(text_only/balance_url)的继承规则、新表与旧单值并存的解析优先级——复审建议实施期明确;本规格 Testing Decisions 已把"并存以新表+active 为准"定为测试预期,继承规则按"回退条目继承旧值"实现即可自然满足,无需扩票。
