- 决策依据：CONTEXT.md 词汇表（反跑、扫参、策略计算器、等待窗口、无效保温、成效账、公式单源）；ADR-0002（分析与账目分离同精神）；代码事实：`internal/report.StrategyTable`（既有"等待窗口策略对比（事后，可复算）"）、`internal/policy`（纯逻辑、`Compute` 闭式现算 τ/cap、policy.go:31 `DefaultBeatOutTokens=300.0`）、`internal/beat.Breaker`（MissLimit=2）、`gate.go` `EnqueueFerry` 仅两处调用（提交触发，无后台定时摆渡）
- 术语遵 CONTEXT.md（"扫参（sweep）"词条已入表）；grill 决策快照 D1-D20 与逐条证据见 `.xcheck/20260921-090607/{decisions,FINDINGS}.md`

## Problem Statement

心跳全链（矩阵 #27）开闸在即，但等待窗的 τ（间隔）与等待上限由策略计算器闭式现算（输入＝config `[heartbeat] ttl_s` 单点值＋价格表），从未在真实历史等待窗上验证过"开了到底划不划算、这套参数在历史数据上是不是接近最优"。现场实测慢且贵（须真跳、须渡口切换完成）。账本已无清理地积累逐事件粒度的 window 行（`opened_ts/closed_ts/dur_s/prefix_tokens/close_reason`，纯元数据；窗口功能 2026-09-19 上线，2026-09-21 09:15 时点全量 118 窗且仍在活体增长，真实项目过滤后 112 窗），v1 反跑条件已具备；更深的 30 天全项目历史在 CC transcript 目录（70 项目/327 会话），挖掘层另立 v1.x（见 Out of Scope）。

## Solution

新增离线 CLI 子命令（默认名 `ferryman backtest`，可改）：读账本历史 window 行＋价格表，复用公式单源（`internal/policy`、`internal/report` 反事实公式），在**参数网格 × TTL 场景轴**上重放等待窗，输出 docs 实验报告＝**差距表（当前闭式配置 vs 网格最优）＋输入校准建议**。数据集按真实项目 profile 过滤（参数化，默认全量）；命令带 `--json` 结构化输出供 agent 直接消费。跑两遍：第一遍现在（零真跳时代纯反事实推演，产出心跳全链开闸决策依据）；第二遍开闸后（`wait_close` 行有真 `beats_fired/cost_actual`，推演 vs 实测对账，校准 TTL 模型）。

## User Stories

1. 作为用户，我想不真跳一次心跳就知道"若开闸，历史窗上净节省多少、共跳多少次、花多少钱"，以便决定开不开。
2. 作为用户，我想看到闭式推导参数 vs 网格最优的差距表，以便判断策略计算器的输入（`ttl_s`）是否该校准。
3. 作为用户，我想在 TTL 三档场景（config TTL（无实测，采集日期 N/A） / −1/3 / −1/2）下看结论是否翻转，以便知道推演对 TTL 单点值的敏感度。
4. 作为用户，我想开闸后重跑同一命令对账推演与实测，以便校准 TTL 模型并复核第一遍结论。
5. 作为用户，我想用项目过滤清单（含/排 glob）把实验项目（ft-lab、压测目录）从数据集剔掉，只反跑真实工作项目。
6. 作为 AI agent，我想以 `--json` 拿到结构化扫参结果与退出码，以便直接读取结论并汇报。
7. 作为其他机器的 Ferryman 使用者，我想用自己的账本与价格表跑同一命令得到对我历史用法的分析——工具不含任何针对特定机器的假设。

## Implementation Decisions

### 扫参网格

- **主网格（可行域网格，唯一产生行动建议的网格）**：以 `ttl_s` 为扫描变量——档位 = config 当前值 × 乘数 {0.5, 0.6, 0.7, 0.8, 0.9, 1.0, 1.1, 1.2, 1.4, 1.6, 1.8, 2.0}（12 档，对数均匀；档位表即全集，无开闭区间歧义）；每档经 `policy.Compute(ttl_s′, prices)` 闭式生成完整参数组 (τ, 首跳时机, 等待上限)。**保证最优点必落在公式可生成的参数曲线上**，直接映射回 `ttl_s` 校准建议——行动出口闭合。
- **对照列（当前闭式配置）按 TTL 场景档重算**：每个 TTL 场景档 TTL′ 下的对照基线 = `policy.Compute(TTL′, prices)`（τ=safety×TTL′ 同步变化）——差距表永远是同档内对比，不跨档错位。
- **诊断网格（只读展示，不产生行动建议）**：自由三参独立扫描——τ 锚 = 各档闭式 τ × 乘数表 {0.5, 0.6, 0.7, 0.8, 0.9, 1.0, 1.1, 1.2, 1.4, 1.6, 1.8, 2.0}（与主网格同表，全集枚举）；首跳时机锚 = {开窗即跳, τ/2, τ}；cap 锚 = {闭式 cap ×0.5, ×1.0, ×2.0, ∞}。量化"公式曲线距自由最优还有多远"，报告单列并标注"诊断用，非可部署"；结论**只能**用于论证公式常数挑战（ADR 门槛），不得直接输出 ttl_s 建议。
- **确定性并列最优（tie-break）**：净节省（及一切排序键）并列时，按参数向量字典序取最小——τ 升序 → 首跳时机升序 → 等待上限升序。保证同输入两次运行逐字节一致（测试锚点）。
- **首跳时机对照语义**：闭式侧首跳 = `policy.Compute` 输出的首跳时机（与 τ 同源）；网格侧首跳按上条锚点集。

### 数据集（v1＝来源①记录窗）

- **① 记录窗（账本 window 行）＝ v1 唯一数据源**；② 流水重建（usage 行挖窗）暂缓——主会话 usage 遥测与窗口功能同日上线（2026-09-19 16:3x），与①同期，零增益，待遥测积累数月后再议；③ transcript 挖掘（~30 天 × 70 项目 × 327 会话，`~/.claude/projects/`）为 v1.x 独立立项，须先过隐私评审（读会话文件本体）与保真度对拍（09-19 后挖出窗与记录窗对拍）。
- **样本构成（2026-09-21 09:15 时点确定性规则重算；数据活体增长，报告以命令实跑时点为准并输出时点戳）**：全部窗 118 = 113 main_resumed / 4 prompt / 1 expired；**真实项目过滤后（剔 ft-lab）112 窗，全部 main_resumed——prompt 与 expired 为零**（4 prompt + 1 expired 全部来自 ft-lab 实验项目）；ft-lab 6 = 1 / 4 / 1。项目归属：Ferryman 54（含 orca 任务 9）、AntFeedingLog 41、xcheck 16、research_things 1、ft-lab 6，合计 118。
- **project 还原**：window 行 project 为空时经同 session_id 的 usage 行连接还原，**确定性优先级**：主会话行（subagent=""）> 子代理行；同级多个不同 project 取时间最新一条，平局按字典序**取最小**（与主网格 tie-break 同向）。无可连接行 → **"unknown" 桶**：照登、报告/JSON 单列；受 `--exclude` 显式排除约束，不被 `--projects` 正集包含。报告必须输出：未还原数、多值匹配数、过滤前后窗计数。（本机现状实测：多值 session_id 34 个、未还原 0——多值非假设是现实，主/子代理行 cwd 差异所致。）
- 重放主输入 `dur_s + prefix_tokens`，不依赖 close_reason。
- 按时间对半切**留出集**：前半选参、后半只验证；验证栏参数不得来自后半数据（**目标语义**）。**v1 实现取舍（终局评审发现，2026-09-21）**：引擎现于全部可重放窗上选参，留出集在报告中为分半呈现而非独立验证，报告注记已如实改写；真·前半选参+后半独立评分为白天候选项（二选一：实现真分半，或接受全窗选参并修订本条）。TTL 观测带采集日期标时效。
- provider 缺 `P_cache` 的窗入"不可算"桶照登（价格表既有语义：缺缓存价即无缓存经济），不剔除不估算。

### 评分口径

- 主指标＝净节省（Σ 避免重付 − 心跳花费），沿用成效账的版本化反事实公式（公式单源，不另写）。
- 无效保温单列不合并：**真实项目历史样本 expired 为零——历史空表照登并如实注明**；外加 expired 占比 0/10%/30% 三档场景敏感性（真实样本无亏损事件，场景档是唯一亏损侧证据来源）。

### 模型与保真

- TTL 第一版单点（与生产公式完全同输入，即 config `ttl_s`），三档场景轴：**config TTL（无实测，采集日期 N/A） / −1/3 / −1/2**；存在逐窗 TTL 观测后才用"实测值"档名并注来源与采集日期。报告硬标证据等级：**"单位成本输入（价格表、prefix_tokens）为事实；跳数、时点、熔断触发与总成本均为反事实推断"**——第一遍无任何 cost_actual 可对账（wait_close 行数为零）。
- 熔断照生产 `internal/beat.Breaker` 语义模拟（连续 miss≥2 停跳），复用实现不另写。
- 摆渡、闸门、交接事件**原样背景重放**：它们由提交事件＋转录 mtime 驱动，心跳不写转录、不产 usage 行，全部外生于心跳策略（`EnqueueFerry` 仅 gate.go 两处调用为证）。报告带**双计检查**节：同一窗内心跳花费与摆渡成本各自列报，不互相抵扣。
- 盲区声明为报告固定一节：**单跳成本依赖 `DefaultBeatOutTokens=300`（policy.go:31）硬编码假设，真实 out-tokens 偏离将随跳数线性放大误差；第二遍以 wait_close.cost_actual 对账**；渡口限流/共享配额不可见；GLM 端 TTL 策略漂移；单机单用户样本外推性。

### 通用性（不针对单机）

- 项目过滤参数化：`--projects`/`--exclude` glob（或 config profile），**默认全量**；"真实项目 vs 实验项目"清单永远活在 config/命令行，永不进代码。
- 数据源路径走既有 config 解析（`data_dir`、`FERRYMAN_CONFIG` 优先级同 daemon）；价格表驱动；无任何本机路径、项目名、时间窗硬编码。
- 本机首跑用本机 profile（排除 ft-lab、压测实验目录），作为使用示例写进文档而非默认值。

### 治理（与策略计算器的裁决关系）

- 运行时参数永远由策略计算器闭式推导唯一供给；τ/cap 不在 config（`manual_wait_cap_s` 仅向下夹紧），扫参**没有也不开 config 出口**。
- 扫参产物＝差距表＋输入校准建议（`ttl_s` 是 config 现成可改键）。挑战公式常数（`DefaultSafety` 等）仅当差距大且跨留出集稳定时立项，立项走 ADR。

### 形态

- CLI 离线子命令，报告落 docs/（实验报告惯例文件名），不进账本、不动面板（面板反跑保持三线对比展示）。

### agent 面（预期，v1 不实施）

- v1 CLI 带 `--json`（结构化结果＋退出码），agent 今天即可经 shell 调用。
- MCP 暴露（如 backtest_report 类只读工具）排 v2，与 ADR-0009 控层三件套同批评估：扫参是长时计算，MCP 同步查询语义不合适，异步任务语义 v2 定。

## Testing Decisions

- **金样本合成窗**：构造已知 dur/prefix 的窗集合，断言净节省与成本等于手算闭式值。
- **确定性**：同输入两次运行报告逐字节一致（排序键稳定；tie-break 字典序取最小为锚点）。
- **回归**：既有 `StrategyTable` 输出不变（扫参复用而非改动公式单源）。
- **熔断**：TTL 场景档短于间隔的合成窗，断言模拟停跳。
- **留出集**：报告含前半/后半两栏，断言后半栏评分用的参数集与前半一致。
- **project 还原**：构造 no-match / 多值匹配 / 主行优先级用例，断言确定性结果与 unknown 桶单列计数。
- **隐私**：报告只含元数据（时间、token 数、金额、项目路径可以；消息内容结构上不存在于输入）。

## Out of Scope

- **transcript 挖掘层（30 天深度）**——v1.x 独立立项：隐私评审（打开会话文件本体，隐私面扩大）＋与记录窗对拍的保真度验收先行，兑现"所有真实项目 30 天历史"。
- **流水重建层（usage 行挖窗）**——与记录窗同期数据，零增益；遥测积累数月后再议。
- **成本乘数场景轴**（单跳 out-tokens ×0.5/×2 档）——非阻断建议，随晨报提请拍板。
- **留出集构成披露表**（前半/后半 × 项目构成）——非阻断建议，随晨报提请拍板。
- **"决策 D3 vs 里程碑 D3"撞名措辞**——非阻断建议，随晨报提请拍板（里程碑统一写"心跳全链开闸（矩阵 #27）"）。
- 策略实验室（策略形状对比，如固定间隔 vs 随 TTL 观测自适应）——零真跳数据，无从校准。
- 问询窗参数回测（#25 落地攒数据后再议）。
- 任何写 config、面板扫参模式、自动调参、进账本的路径。
- MCP agent 面暴露（v2，见实施决定）。
- TTL 分布拟合（第二遍用 `ttl_observed_s` 逐窗观测后再升）。
