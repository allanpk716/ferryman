## 1. 背景与动机

Ferryman 是本机常驻守护进程，守望 Claude Code 与 Codex 两个 CLI 的会话转录文件（CC：`~/.claude/projects/**/*.jsonl`；Codex：`~/.codex/sessions/**/rollout-*.jsonl`），维护台账（session_id → 最后写入时间、上下文规模等），据此做三件事：

1. 闲置超**总结阈值**（默认 25 分钟）→ **摆渡**：调外部廉价模型把会话上下文总结成交接 MD；
2. 闲置超**拦截阈值**（默认 35 分钟）→ **闸门**（提交前钩子）拦截继续使用，引导开新会话并自动注入交接；
3. 会话低于**最小上下文门槛**（默认 20K token 量级）→ 既不摆渡也不拦截。

目的：缓存失效后继续旧会话需全量重付输入费用，拦截引导换新会话＋注入交接更省。

**新痛点**：使用"拷问式"讨论技能时（典型输出形态：一条 assistant 消息里 5~10 个编号问题，要求逐条回答），用户组织长答案耗时 10~40 分钟，远超服务商缓存 TTL（当前主力服务商 GLM 实测约 10 分钟）。后果链：

- 缓存过期，答案提交时全量重付输入费；
- 闲置钟照走，第 25 分钟触发一次无意义的摆渡（花钱产出没人用的交接）；
- 第 35 分钟闸门直接拦截提交。

本设计新增第四种处置：**检测到"提问潮"时，判定用户正在组织长答案，对该会话提前发 1~2 次心跳**（heartbeat：以最小请求重放会话前缀、刷新服务商缓存的保活请求），把缓存命中保到用户提交答案为止。**这是会话级、条件化、默认关闭的独立功能，不是全局心跳开关。**

## 2. 领域定位：三种等待状态

| 等待状态 | 例子 | 现状 |
|---|---|---|
| 机器等机器 | 主会话等异步子代理跑完 | 异步等待窗口（已建成，仅 CC 轨）：闸门豁免、摆渡推迟、窗口入账 |
| **机器等人** | AI 问了一堆问题，用户在憋长答案 | **本设计，尚不存在** |
| 人不在 | 会话真凉了 | 摆渡＋闸门，既有职责 |

本设计的"等答复窗口"是异步等待窗口（停车窗）的兄弟结构，复用同一套台账状态位、摆渡推迟接线与隐私不变量，但**不改动闸门语义**（见 D6）。

## 3. 十项设计决定

### D1 · 定位与红线推翻

本功能即 Ferryman 第一个心跳执行器。既有 `docs/DESIGN.md` §9 设计红线"**不保活**"，以及 2026-09-18 定稿的异步等待信号 spec 之 Out of Scope（"心跳执行器未授权不实施"）需经 **ADR 显式推翻**。理由：红线原意针对无条件全局 keepalive（社区实测跨夜不可靠、持续烧钱）；本功能是条件化、会话级、短窗（最多两跳）的保活，语义不同。放行节奏：先 observe（只记录"会怎么跳"，不真发请求），后 enforce（见 D9）。

### D2 · 检测方式：v1 纯启发式，不接模型

- **靶子**：最后一条 assistant 消息的**纯文本**（实测拷问式技能输出为纯文本提问块，如 `❓ **Q1** - **标题**` 格式；非结构化工具调用）。
- **判据原料**（先剥掉代码块再统计）：问号句、编号问题行（`1.` `2.` …）、`❓ **Qn**` 类标记行、疑问词开头的列表项；去重合并为"独立问题单元"计数。
- AskUserQuestion 工具调用若出现在转录里，作为加分旁路信号（其问题数组可直接计数），但不是主判据。
- "一次一问"式讨论（brainstorming 类技能原生形态）天然不触发阈值。
- **不接语言模型**：零边际成本、可单测、不依赖网络；模型判断留作二期可选项（届时复用既有摆渡路由的模型调用路径，不需新增 API key 配置）。

### D3 · 阈值：独立问题单元 ≥5 触发，起步偏松

- 默认 **≥5**，配置可调。
- 偏松的理由：误报代价＝两跳的缓存读价＋两小段输出费；漏报代价＝整个前缀按输入全价重读，两者差一个量级。
- observe 段实跑数据出来后回调（漏得多往 4 调，误报多往 6 调）。

### D4 · 次数与节奏：独立模块的明文常数，不接费用计算器

- **需求方明确决定**：跳几次是这个检测模块自己的配置常数，**不与费用相关模块挂钩做动态推算**（记归记，算归算：每跳费用照记入账本，但账本数据不反过来指挥跳几次）。
- 命中确认（问题消息已落盘 + 无悬空 tool_use + 无子代理在飞）后：**不立刻跳**（刚落盘的回复本身刚刷过缓存）；第 1 跳在命中后 **~7 分钟**（≈0.8×GLM 实测 TTL 10 分钟），第 2 跳再隔 **~7 分钟**，**上限 2 跳**。
- 收到新一轮提问潮 → 重新计时。
- 全部常数明文进配置，手改即生效。

### D5 · 取消语义与能力边界

- 每跳**发送前验条件**：自计划开始后该会话**有任何新写入 → 整个计划作废**，剩余心跳一跳不发。守望轮询 3 秒 → 取消延迟 ≤3 秒。
- 已在途的请求不可撤回（HTTP 已发出），代价一次缓存读价，忽略不计。
- **能力边界**：打字草稿不写会话文件、不可见；只有用户**提交**（新写入落盘）才触发取消。打字期间正是心跳的工作窗口。

### D6 · 闲置钟与等答复窗口（选项 ii，最重的一刀）

- 现状：闲置＝距台账所记最后一次写入的时长；心跳不产生写入。等答复期间闲置钟照走：第 25 分钟摆渡误触发、第 35 分钟闸门拦截——保活成功提交却被拦。
- **决定**：检测命中的会话挂"**等答复窗口**"（台账态，异步等待窗口的兄弟结构）：
  - **摆渡推迟**到临近拦截阈值才执行（不是跳过，保住"被拦 ⇒ 交接必已存在"的既有不变量）；
  - **闸门语义一字不动**（仍 35 分钟拦截）；
  - 窗口随任何新写入（用户提交）立即关闭，摆渡恢复正常调度。
- 理由：35 分钟内答完的场景完全覆盖（含"怕 10 分钟没看完"的主诉求）；超 35 分钟的长答案缓存必死，交接文档恰是开新会话贴答案的救命稻草。备选方案"等答复期间闲置钟暂停/心跳计入台账活动"被否：动了"判定只依据台账"的根基，且检测器误报会让会话长时间脱离闸门护栏。

### D7 · 作用域

- 独立配置节 `[question_watch]`，**默认 off**，与将来任何全局心跳互不牵连。
- **CC 轨先行；Codex 轨缓行**（Codex rollout 无结构化提问信号、文本启发式误报率高一档，且异步等待窗口也仅 CC 轨，两轨同频推进）。
- **最小前缀门槛**：明文常数（默认 20K token 量级）——低于它的会话心跳不值（重读便宜过保活），且这类会话本就不受摆渡/闸门管辖。

### D8 · 可见性

- 心跳（含 observe 演练跳）作为**事件落台账** → 时间线查看器（viewer）展示 → `/stats` 出计数与累计花费；另配一键停（配置开关）。
- observe 与真跳同轨展示，observe 段即可评估误报率。

### D9 · 放行节奏：三态开关，永不自动升级

- `mode = off | observe | enforce`（对齐闸门三态词汇）。
- 升 enforce 三条件**全部满足**：① observe 跑满一周**或**累计 ≥10 次命中；② 心跳保真度实验（Q14，方案已备）通过——心跳请求形状发错＝必 miss，不做实验真跳就是蒙的；③ 需求方人工看过 viewer 命中清单点头。
- 切换永远人工拨开关，系统不自动升级。

### D10 · 记账与隐私不变量

- 每跳逐条记账（时间/会话/token/实收费用）入既有费用账本；心跳的 cacheRead 即线上 TTL 遥测，突变记异常。
- **隐私不变量**（沿用异步等待窗口先例）：检测判定只出 bool/计数，台账与账本**永不落消息内容**。

## 4 · 时序示例

```
t=0     提问潮落盘（此写入本身已刷新缓存）
        检测命中：无悬空 tool_use + 无子代理在飞 → 开等答复窗口，排心跳计划
t=7min  第 1 跳发出（条件预检：无新写入 ✓）
t=12min 用户提交答案 → 文件新写入 → 窗口关闭 + 第 2 跳取消（≤3s）
        缓存命中，答案按缓存读价生效 ✅

变体：t=25min 未答 → 摆渡因等答复窗口推迟，不白做；
      临近 t=35min 仍未答 → 摆渡执行（交接就绪）；
      t>35min 提交 → 闸门拦截（有交接引导开新会话，答案贴进去）。
```

## 5 · 配置面（草案）

```toml
[question_watch]
mode = "off"               # off | observe | enforce
min_questions = 5          # 独立问题单元触发阈值
beat_interval_s = 420      # 心跳间隔（默认≈0.8×GLM 实测 TTL）
max_beats = 2              # 每窗口心跳上限
min_prefix_tokens = 20000  # 低于此规模不跳
```
