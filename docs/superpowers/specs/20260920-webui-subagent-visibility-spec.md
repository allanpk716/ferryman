# webui 会话列表与子代理可见性 规格（20260920）

来源：本仓 grill 会话六项决策（D1-D8，2026-09-20 用户逐条确认）＋ 评审链 20260920-114721/120414（round0 8 问题 → rev1 修订 → round1 双家复审一致通过）。术语遵守 CONTEXT.md 词汇表；子代理入账决策见 ADR-0008。

## Problem Statement

webui 会话列表对没有 ai-title 的会话显示"转录文件路径前 24 个字符"，用户无法辨认（真实账本 314 个族系里 107 个如此）；codex 会话因从不产 usage 行，标题与项目两列全空。更重的缺口：CC 子代理转录（占会话 output 约 47%，e0c 实测均值）完全不入账，webui 与报表的 tokens 系统性低估，与「会话总账 = 主转录 + 各子代理转录」的既有定义不符。

## Solution（用户视角）

1. 没有标题的会话在列表里显示可辨认的名字：优先"项目尾段 · agent · 月日"，项目也缺时"agent · 月日 · 会话号前 8 位"。
2. 子代理的每次模型调用用量随父会话入账（只记官方四列数字与子代理标识，消息内容永不入账——隐私铁律不变）。
3. 列表 tokens 列显示"主+子"拆分；时序页分上下两泳道（上=主会话、下=子代理合计），下方按子代理逐个画甘特条（跨度+请求刻点+尾标），点击在两道打参考线——子代理跑的时候主会话仍可能正常对话，两道并行可见。
4. 摆渡、闸门、闲置判定行为完全不变（子代理仍然不摆渡、不是独立会话）。

## User Stories

1. 作为 Ferryman 用户，我想在会话列表一眼认出没有标题的会话属于哪个项目，以便不用猜"c:/users/allan716/appdat"是什么。
2. 作为 Ferryman 用户，我想看到每场会话 tokens 的主/子拆分，以便知道子代理到底烧了多少（此前完全不可见）。
3. 作为 Ferryman 用户，我想在时序页同时看到主会话与子代理的请求活动，以便看懂"主会话闲置时子代理在跑"。
4. 作为 Ferryman 用户，我想按子代理逐个看存活跨度与请求点，以便分清哪个长跑、哪个短平快。
5. 作为 Ferryman 用户，我想点击甘特行在泳道上打同色参考线，以便对照主会话同时段活动。
6. 作为 Ferryman 用户，我想悬停子代理请求点看到所属子代理标识，以便排查具体某个子代理的消耗。
7. 作为账本审计者，我想子代理用量四列随父会话族系入账，以便会话总账完整且可跨月审计（会话文件 30 天清理后流水仍是地基）。
8. 作为守护进程运维者，我想子代理文件首见即全量回填、且守护重启后从断点继续不重记，以便账本不缺口、不重复。
9. 作为报表使用者，我想既有账本行读取不受新增字段影响，以便升级零迁移、旧数据照常可读。

## Implementation Decisions

- **采集分流**：路径含 `subagents` 段的转录文件，继续跳过台账 Touch、摆渡入队、闲置判定、问询守望与心跳排程（T32/T48 语义零变动）；唯一新增行为是喂给 usage 采集。
- **父会话归属**：父 sid 取自子代理转录行内 `sessionId` 字段（不靠路径猜）；入账行 session_id=父 sid、lineage_id=父转录路径的归一键（族系键）。
- **父转录路径推导**：从子代理文件自身路径剥离尾段 `/<父sid>/subagents/<文件名>` 得同目录父转录文件；与台账 TranscriptPath 交叉校验——**台账有值时以台账值为准**（F9），不一致记一行可诊断日志不阻断，台账无值用剥离结果。
- **标记字段与恢复**：usage 白名单新增最小标记字段，值=文件 stem（即 `agent-<agentId>`）；主会话行写空串（白名单必填语义不变）。采集状态键为父域复合键 (agent, 父sid, stem)；断点恢复三成分全部取自账本行内字段，零命名推导；旧账本无标记字段的行按主会话键恢复。
- **首见语义**：已存在未采集的子代理文件首见即从 offset 0 全量回填，与主转录既有语义一致（历史回填，台阶跳已由 ADR-0008 声明）。
- **列表兜底链**：ai-title → `项目尾段 · agent · 月日` → `agent · 月日 · <会话号前8>`；"月日"=族系最后活动时间，按 webui 既有本地时区格式化。
- **tokens 拆分**：聚合层按标记字段拆主/子两桶；口径不动（输入+缓存读+建缓存，不含输出）；列表单列内联"主+子"，子为零只显主数；低流水行不过滤。
- **API 契约**：既有字段语义与形状零改动；新增仅两处——时序接口的 usage 行携带子标记字段（逐点）、会话列表响应新增主/子两个 token 桶（既有合计字段保留）。
- **时序页组合形态（来自原型 D 变体，.scratch/webui-subagent-timeline/prototype.html）**：图区分双泳道，上道主会话、下道子代理合计，共用时间轴、各自 y 轴；等待窗带/断缓存斜纹/TTL 绿带/事件行贯穿两道；下方甘特区每子代理一行（条=首末请求跨度、竖刻点=每次请求、尾标 tokens 与时长），点击行打贯穿两道的同色参考线；子代理显隐沿用科目 chips 交互。
- **范围**：仅 CC 轨；Codex 轨、Orca runtime 守望目录均不动。

## Testing Decisions

只测外部行为，不测实现细节；门=`go test ./...` 全绿。

- 采集：父域复合键不串扰（两会话各带同名形态 agent 文件）；子代理行形状（归父、标记=stem、四列取自该文件；主行空串）；首见全量回填；重启恢复（含旧账本无标记字段 fixture）；台账优先推导的键与父转录后续入账键一致。
- 守望零回归：subagents 文件不 Touch、不入摆渡队、不参与闲置判定（既有 T32/T48 测试零回归）。
- 隐私：子代理行含消息内容字段被白名单拒绝（沿用既有拒绝测试形态）。
- 聚合与 API：主/子桶与账本手算一致；会话列表既有字段不变；时序行携带子标记。
- 前端无自动化测试：列表兜底链拿真实账本 107 个无标题族系抽验（含 codex inject-only 行、跨日族系月日）；时序页手工过真实账本（至少一场带等待窗的 CC 会话），既有功能（视图切换、断缓存跳转、窗口反跑、事件图例、演示模式）零回归。

## Out of Scope

- Codex 轨子代理（无此转录结构）。
- 摆渡/闸门/等待窗/问询守望任何语义变化。
- 列表 tokens 口径纳入 output（另立项）。
- 低流水行过滤、Orca runtime 守望目录移除。
- 消息内容入账（永不）。
