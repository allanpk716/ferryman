## 已知边界（如实）

- 判热时钟 = 距最后上游请求（含心跳重放）；守护重启后无观测 → 保守判冷（首日重启后同模型静默属预期，非故障）。
- 深夜/低负载时段 GLM 驱逐行为可能与白昼实测不同（E0a 风险区口径）；首周遥测按日分段看。
- 追加段会进入缓存（实跳臂 aged 臂 33216>32960 实证）——多次触发的前缀逐步变长，成本模型按"前缀含历次追加段"计。


## 2026-10-01 事故收官：34 连败根因与观测缺口修复

- **现象**：启用（09-29）至 10-01 08:59，same_model 泳道 34 次尝试全部失败（wall_s=0、双 token=0、model 空），零成功；失败行无原因字段、失败路径无日志——本清单观察三天无人能查因。
- **根因**：CC 请求体不带 `metadata.session_id`，旧渡口归因仅认体侧 → 会话归因恒空（旁证：09-23 渡口上线起 dock 科目行 session_id 全空）→ `SnapshotStore.Capture` 对空 ID 按设计跳过 → 快照库从未入库 → 追加重放 `Main` 扑空 → `snapshot_missing` 秒回。判热钟走转录 usage 喂入、与快照归因链不同源，故「判热通过 → 发不出去」。
- **修复（根因）**：`ea82dd3`（10-01 07:48 渡口归因头回落与防御）补 `x-claude-code-session-id` 头回落（UUID36 校验）；09:00 重启部署，09:01 起 dock 行恢复归因、快照开始入库。首笔 same_model 成功派发待自然触发实证（重启后判热钟清零判冷属预期，见「已知边界」第一条）。
- **修复（观测缺口）**：handoff 科目 failed 行补 `err` 字段——same_model=稳定字面量（beat 错误类别 ∪ `stop_tool_use`/`md_structure`），第三方/链级=截断 120 的错误摘要；same_model 失败补一行 `[samemodel] 失败（<err>，交还既有调度）` 日志。跳过原因（reason=为何没尝试）与失败原因（err=尝试了为何死）分立两名。
- **教训**：实跳臂实验（append-replay-arm）自建快照库、显式按会话 ID 键控 Capture，绕过了渡口归因链——实验 4/4 通过而生产全败。此类验收必须走生产归因路径。
