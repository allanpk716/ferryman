# Spec · DSH 同目录多会话交叉注入修复（dsh-cross-inject）

来源：`.xcheck/20261007-203713/`（proposal/decisions/FINDINGS 同链）。评审终态=无需修订；本 spec 继承已确认共识+必要修复+验收目标，评审建议映射：锚定边界记录（F1）、强续入口写明（F2 解除附带）、缩窗不实施（F3）、清单零注入随主线（F4）、R3 降级顺序（F5）、语义断言软信号（F6）。

## Problem Statement（用户视角）

同一个 DSH 工作目录里开多个会话、每会话一个主题时（如 research_things 每场调研一个会话），新建会话会被自动塞进"该目录线上最新交接"——别的主题会话的材料污染新会话（实证：2026-10-07 ASD-STE100 会话收到 LCU 调研交接 895 tokens）。根因：新会话创建时守护进程对"无被拦待领原话"的目录仍按"单线项目"假设自动归还最新交接；同目录多主题形态下该假设不成立，且"新鲜度=交接未被源会话后续写入顶掉"使闲置会话的交接永远排候选首位。

## Solution（用户视角）

新建 DSH 会话保持干净上下文：守护进程不再向"无被拦待领原话"的新会话自动注入任何交接全文或候选清单。被拦后新开同目录会话仍自动收到交接与被拦原话（已验收接班体验，逐字不变）；强续、续用、压缩链行为不变；CC/Codex 的 /restore 显式命令行为不变。

## User Stories

1. 作为在同目录开多主题会话的用户，我想要新会话上下文干净，以便新主题不被别的会话材料污染。
2. 作为被闸门拦截的用户，我想要新开同目录会话时自动收到交接与被拦原话（2 小时锚窗内、每笔被拦原话至多交付一次），以便不打字就能接着干。（保持现状）
3. 作为使用强续的用户，我想要强续路径行为不变（强续入口=闸门 bypass+续用档，不经本次修改的分支），以便已验收的强制继续照常工作。（保持现状）
4. 作为使用子代理的会话，我想要子代理会话不被注入交接，以便子代理上下文只含父会话安排。（增量防御，依探针结论条件实施）
5. 作为维护者，我想要覆盖单人/多人/同目录多会话拓扑的常驻测试矩阵，以便同类注入回归在合入前被拦截。

## Implementation Decisions

- **核心改动（R1，守护进程）**：`DshHandoff`（internal/daemon/dsh_receive.go）的"新会话"分支重写为——线内存在被拦待领原话（`LatestPendingFor("dsh", cwd)`）时照旧走既有锚定归还（restoreAnchored：锚会话交接+原话）；**无锚时回 `{"context": null, "continuation": true}`**——不再注入最新交接全文、不再注入候选清单（原 restoreNewest 的 dsh 自动调用废止；restoreNewest 本体保留给 CC/Codex 显式 /restore，逐字不动）。
- **continuation 键语义扩注（协议兼容）**：该键在插件侧的既有契约="零注入终态，清欠账止问"（v0.9.7 已实装，md=null+continuation=true→清欠账不置账）。本次将其含义从"续用档"扩为"续用档或新会话无料"——旧插件（v0.9.7）零改动即兼容；插件侧 daemon.ts/events.ts 头注释同步扩注（注释级，不改行为）。**不得回 `{context:null}` 无 continuation**——那会被插件当"材料未到"记欠账、每条用户消息重问（欠账死循环形态，2026-10-07 终局修复刚闭合过的回归）。
- **锚窗不缩（F3 裁定）**：`PendingAnchorS` 维持 7200s；被拦横幅文案不动。缩窗作为独立产品决策留晨报待用户拍板。
- **子代理硬禁（R3，条件实施，F5 降级顺序）**：先由 T5 探针钉死子代理会话创建是否触发 agent/created 及可识别形态（payload source/转录形态）；**钉不死则本票记"不适用/延后"完成并晨报说明，禁止硬凑识别规则误伤正常新会话**。钉得死则插件 onCreated 对子代理形态跳过问询。
- **ADR**：新增 ADR-0025《自动注入挂显式意图信号》——原则"自动路径永不激进注入；注入必须挂显式意图信号（被拦待领锚/用户显式命令/明确开关）"；边界记录（F1）：锚定归还按线（agent+目录）不按人/主题归属，锚窗内一次性交付，多真人共用同目录即共享一条线——现状为已验收行为，未来多真人形态需显式信号重设计。
- **术语**：交接/锚定归还/续用/强续/候选清单/线 等按根目录 CONTEXT.md 词汇表。

## Testing Decisions

- **守护进程单测（TDD）**：internal/daemon 表驱动新增——新会话+无锚 → `context:null`+`continuation:true` 且账本**无** inject 行；新会话+有锚 → 锚定归还照旧（交接+原话+inject 记账）；续用档/CC Restore 回归用例零变化。
- **插件契约测试**：events/daemon 测试新增——md=null+continuation=true → 清欠账、零注入、不置账；有锚 md → 注入照旧；现有 184 用例零回归。
- **E2E 常驻矩阵（tools/e2e_dsh 沙箱，真模型）**：T1 被拦手动新开=接班照旧；T2 双主题事故复刻=新会话零注入；T3 多候选=零注入；T4 锚窗边界（现状 2h）行为回归；T5 子代理探针（记录事实）；T6 跨 profile 互不注入（无锚面断言+窗内锚观察项仅记录不断言）；T7 强续/压缩后回归；T8 一键新会话按钮=接班照旧。**硬门禁=账本无 inject 痕+转录无交接文本；语义断言（回答不含对方主题专名）=软信号，告警不拦截（F6）**。
- **全套件**：守护进程 go test ./... + vet、插件 node --test 全量零回归；按项目纪律用隐身运行器落日志（不裸跑）。

## Out of Scope

- 线模型重构（"线"改按会话算）。
- CC/Codex /restore 任何行为变化。
- 候选清单被动展示（横幅/日志提示）产品化。
- 锚窗缩窄与被拦文案时效化（留晨报拍板）。
- 生产宿主/守护进程部署动作（合并换装是用户晨间操作）。

## Further Notes

- 晨报待用户项：①真机抽验 T1/T2/T8（生产环境三条）；②锚窗是否缩（D2，一行改动+文案同步）；③清单零注入已随主线实施（F4 裁定，可翻案）；④锚定按线不按人边界确认（F1，多真人共用形态出现时再重设计）。
- 部署耦合：合并后 daemon 与插件三拷贝须同步换装（单边更新安全但无效果）。
- 与 v0.9.7 票02 的关系：票02 管"续用"面（已修），本 spec 翻案其"真新会话行为逐字不变"保留条款（依据=用户 2026-10-07 报障实录），两改动面不相交。
