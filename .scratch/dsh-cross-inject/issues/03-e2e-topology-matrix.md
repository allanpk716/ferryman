# 票03 · E2E 常驻矩阵：多会话拓扑（T1-T8）

## What to build

把 tools/e2e_dsh 沙箱套件扩展为**多会话拓扑矩阵**（真模型、真压缩实录形态沿用既有 suite 形制），覆盖单人/多人(跨 profile)/同目录多会话三种形态，固化为本仓常驻 E2E——"多会话拓扑"从此是一等测试维度。

矩阵（断言按 spec 修复后行为）：
- **T1 接班基线**：会话 A 被拦 → 手动新开同目录会话 → 收到交接+被拦原话（现状保持）
- **T2 事故复刻（硬门禁）**：A 收工闲置 → 新开会话 B 问新主题 → B 零注入：账本无 kind=inject 痕 + B 转录无交接文本；语义软信号（B 的回答不含 A 主题专名）只告警不拦截
- **T3 多候选**：同目录 2+ 会话各有新鲜交接 → 新会话零注入（清单也不进上下文）
- **T4 锚窗边界回归**：窗内（<2h）被拦 → 新会话接班；无被拦待领 → 新会话零注入（窗值本身不动）
- **T5 子代理探针（记录事实）**：被守望目录会话内 spawn 子代理，记录：子代理会话创建是否触发 agent/created、payload 何字段可识别子代理形态。结论写入本票产出文件（供票04）
- **T6 跨 profile**：两 profile 同目录各开一会话（无锚面）→ 互不注入；窗内锚+跨 profile 观察项**只记录行为不断言**
- **T7 续用/强续回归**：压缩后回来首条、强续首条 → 零注入/放行行为与 v0.9.7 一致
- **T8 一键新会话按钮**：被拦后走插件"一键新会话" → 接班照旧（交接+原话）

## 验收标准

- [ ] T1/T8 接班场景：新会话收到锚会话交接+原话（账本 inject 痕+转录可验）
- [ ] T2/T3 硬门禁全绿：账本无 inject 痕 + 新会话转录无交接文本；语义软信号独立输出不拦截
- [ ] T4 窗内/无锚两腿断言符合矩阵
- [ ] T5 探针结论落盘（suite 产物目录下，含触发/识别形态或"不触发"事实）
- [ ] T6 无锚面断言互不注入；锚观察项有记录
- [ ] T7 与现状行为一致
- [ ] 既有 suite 用例（15）零回归；跑法沿用既有 run.sh/隐身纪律、日志落盘
- [ ] README 增矩阵一节（拓扑维度、硬/软门禁分层说明）
