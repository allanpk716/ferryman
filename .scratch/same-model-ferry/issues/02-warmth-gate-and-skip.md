# 票02 · 判热时钟与同模型跳过遥测

## What to build
判热预测器与跳过事件,打通端到端:watcher 在同模型触发点(票01 的阈值,种子 20min)先判热再决定是否进同模型档。判热时钟=距该会话**最后一次上游请求(含体外心跳重放)**的时长(数据源从渡口/心跳遥测流水取最后请求时刻——本票钉死读取源并留单测);判据=时钟时长+该上游 TTL 观测的闭式预判(观测不足时保守判冷)。判冷/上游不在白名单/上游未启用三种情况:该次触发**零模型调用、静默交还既有调度**(第三方/骨架仍走 25 分钟总结阈值,一行不改),遥测记"同模型跳过"事件,跳过原因独立编码(cold / whitelist_miss / not_enabled)。台账闲置(闸门语义)完全不动。

## 验收标准
- [ ] 判热预测器单测:给定时钟时长+TTL 观测,冷/热判定符合保守默认
- [ ] 跳过三原因独立编码,单测覆盖三条路径
- [ ] watcher 集成:判冷时无任何模型调用发生、25 分钟档行为与改动前逐字节一致(既有测试不动照绿)
- [ ] 最后请求时刻数据源钉死并有单测(含心跳重放计入)
