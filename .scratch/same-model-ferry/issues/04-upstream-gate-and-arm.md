# 票04 · 上游启用门与追加重放实跳臂工具

## What to build
"白名单预置≠启用"的状态机与验证工具,打通端到端:每上游维护实跳臂结论状态(待实跳/通过/未过,持久化在状态目录),票02 的 not_enabled 判据读取它。实跳臂工具(experiments/append-replay-arm/,遵循仓库 experiments/ 惯例):给定会话捕获快照,构造追加重放、真实发送到该上游、按四条成功标准评估(①追加后仍命中,该跳缓存读占比≥同前缀心跳基线;②与捕获快照字节差异仅末尾;③无 tool_use;④输出可解析为交接 MD),结论回写白名单状态。**本票只交付工具与构造/评估逻辑的单测,不执行任何真实联网调用**(实跳由人手动跑,工具就绪即验收)。

## 验收标准
- [ ] 启用状态机:预置→(实跳通过)→启用 /(未过)→保持未启用;状态持久化
- [ ] 实跳臂工具:构造、发送(可 dry-run)、四标准评估、回写,四个子命令/步骤齐
- [ ] 评估逻辑单测:四标准各自通过/不通过的判定用例
- [ ] dry-run 模式不联网也能走通评估以外的全流程
