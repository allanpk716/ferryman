# DSH 摆渡首单真机跑通后的三件遗留（spec · 2026-10-07 · 夜链 20261007-170808）

> 评审收敛稿：round 0 双家（codex/kimi）建议修改 → 自动修订一轮（rev1）→ round 1 双家一致同意。活动约束空。机器账 `.xcheck/20261007-170808/`（round 0）与 `.xcheck/20261007-172431/`（复审环）。

## Problem Statement

Ferryman 的 DSH 会话热缓存压缩链 2026-10-07 15:41–16:21 真机首单完整走通（5.5h 闲置→拦截 auto-continue→闲置 24min 触发压缩→16:09:33 领取执行→16:20 过期后归来冷重付仅压缩后小前缀 22,733 tokens input）。链路健康，但首单暴露三件遗留缺陷：

1. **压缩指令"领取不执行"空转环**：注册表播种后，宿主对"注册但未真开"的静置会话领取压缩指令但不执行——`bb5d5e37` 194 次触发 0 次执行、`f9d6523c` 160 次触发，~30s 一次重发；"过期无人领取"告警被"领取即清零"永久消音（领了不执行既不算过期也不算失败）。机制代码钉死：daemon 侧 poll 应答即清槽（compact_trigger.go 头注）+ 插件侧执行闸 compact.ts:434 在 entry.agent 为空时跳过执行但已领。
2. **同会话续用的交接注入面**：15:41:18 auto-continue 的是同一个会话（上下文本就在会话内），却同轮注入三份材料——自己昨天的交接文档全文（+33% 前缀冗余）、两份内容不一致的多候选清单（锚定 MarkInjected 消费+双路注入+全文比对去重失守）；清单指令"点名之前不要开始干活"与强续开场即新任务打架。
3. **强续横幅/bypass 记账报 0 tokens**：实际冷重付 17,693，横幅与账行双报 0。机制钉死一半：boot replay 按 session_id 键从账本**月文件**回放峰值，但 10-03 接法乙之前的历史流量无归因键（`5167d69a` 的行全部从 15:41 起），回放无料，峰值停在 0。

证据锚：DSH 转录 `session-5167d69a…/session.v4.jsonl.zstd`（15:41:18 三注入+横幅、16:09:33/16:10:03 compaction start/end、16:20:00 turn 2 零注入）；`~/ferryman/serve.out.log`（触发行计数）、`gate.log`；`~/ferryman/accounts/202610.jsonl`（bypass prefix_tokens=0 四行 vs 62,090 一行）。

## Solution（用户视角）

- 过期后回来的会话：压缩已把冷重付压到小前缀，不再被塞进冗余的交接文档/清单（想要可以开开关）
- 交接材料只在它该出现的地方出现：新会话开场
- 横幅和账本报的价格是真的，不是"约 0 tokens"
- 静置老会话的压缩指令不再 30 秒空转刷屏，送达断链有告警

## User Stories

1. 作为用户，我想要静置老会话的压缩指令要么被执行、要么有告警，以便压缩链不静默失明、日志不被 30 秒一条刷屏
2. 作为用户，我想要续用同一个会话（强续/压缩后回来）时默认不再被注入冗余交接材料，以便压缩省下的前缀不被摘要吃回去
3. 作为用户，我想要一个开关决定"续用会话时是否自动附上摆渡交接文档"（开关存在=用户 2026-10-07 确认；默认值=助手推荐 false、用户未拍板，翻转=config 一行），以便按自己偏好权衡上下文冗余与连续性
4. 作为用户，我想要强续横幅和账本报真实的冷重付额度（或如实说"额度未知"），以便对"这一条要不要换新会话"做出有依据的判断
5. 作为用户，我想要新会话开场的锚定文档/候选清单行为保持不变，以便既有工作流（2026-10-06 已验收形态）零回归

## Implementation Decisions

### 票01 · 压缩指令"领取不执行"空转环

- **领取后执行窗超时计"未送达"轮**：领取（DshPoll 派发应答）后 180s+余量无 `/dsh/compacted` ok 上报 → 计一轮 compact-undelivered（喂既有 3 轮 gateWarn），与"过期无人领取"同权
- **重触发节流**：槽内指令在有效期内不得被同会话新触发覆盖（compact_trigger.go"同槽新指令覆盖旧指令"加在飞判定）
- **插件侧不白领**：`entry.agent` 为空时不领取（或领取即上报不可执行），daemon 不计该轮为送达
- 空转会话经济性注记：缓存死透的会话压缩仍省下次冷重付前缀，派发照旧、只治空转与失明

### 票02 · 同会话续用的交接注入面 + 用户开关

- **续用默认零注入（daemon 单点挡）**：`/dsh/handoff` 对"目标会话已有历史"返回 null——判定主依据=**转录可解析出事件**（size>0 仅快路径，防宿主新会话 created 即落头部行误判），peak_ctx 仅辅助（票03 已证闸门时刻读 0）；交接材料（锚定文档+候选清单）只属真新会话
- **用户开关**：`[gate] dsh_handoff_on_continue`，默认 false（**助手推荐、用户未拍板**）。开启时续用时刻（强续首条/压缩后续用首条）在横幅外附最新己线交接文档。**开关只控制己线交接文档、不控制候选清单**——清单任何情况不附续用会话（设计判断、非用户确认项，依据=同轮双清单冲突与指令打架实证）
- **restore 确定性**：RestoreCandidates 排序全序=covers_until desc → created_at desc → handoff_id/路径字典序；同状态同答；候选集因 MarkInjected 消费的变化是合法状态迁移（不要求跨状态逐字节一致）
- **dedup 结构化**：同会话同轮 [Ferryman] 注入按首句模板判重（"本项目有 N 份可用交接"一族），不同 N/不同清单也拦

### 票03 · 强续横幅/bypass 记账 0 tokens

- **闸门路径同步兜底**：gate 读到 dsh 会话 PeakCtx=0 且转录非空 → 即时补值（优先账本回放；账本无行按转录粗估量级）再判定；补不动则横幅降级"重付额度未知"，不报"约 0 tokens"。**时序前提：兜底补值先于 bypass 记账取值（同函数内先补后记）**
- bypass 记账 `prefix_tokens` 同源修复（同一处取值，兜底之后）

### 背景约束（不触碰）

- D7：DSH 心跳保活维持关闭（[question_watch] dsh_mode="off"），本役零触碰
- 渡口/上游/发版纪律不变（资产名硬契约、监督者全包换装、插件三拷贝同步）
