# 成本成效账视图(用量统计界面)· 实施规格

> 来源:2026-10-08 夜链(评审收敛稿 .xcheck/20261008-215320/proposal.md + 同环 decisions.md/FINDINGS.md);本文件为实施的唯一规格基线。术语遵仓库 CONTEXT.md。

## Problem Statement

用户的统计信息散落两处:悬浮窗只有紧凑的剩余量/余额圆盘,cost_report 是纯文本报表。用户要一张 cc-switch 风格的用量统计仪表盘(KPI 卡 + GitHub 式日历热力图 + 请求明细表)放进工作台;因用户以手机为主要工作界面,先用手机可评审的 mock 过目,通过后才做成品。

## Solution

1. 先产出**真实数据快照**驱动的静态 mock(深色令牌、零构建),挂本机局域网服务的随机路径上,推送链接到用户手机;
2. 用户过目通过后,统计页进 widget(Tauri 桌面壳)成为「成本成效账」视图窗,数据由 daemon 两类新只读端点供给;
3. 全程诚实口径:算不出的(成本/节省额当前生产配置下)如实标「不可算」并附原因,不编数。

## User Stories

1. 作为用户,我要在手机浏览器打开推送的链接就能看到统计页效果(KPI 卡/热力图/明细表/深色风格),以便不下电脑就能评审界面。
2. 作为用户,我要 KPI 一排看到总成本/总请求数/真实消耗 tokens/缓存命中率/节省额,其中算不出的项如实标注「不可算」与原因,以便知道每个数的来路。
3. 作为用户,我要热力图按日显示用量,并在 Tokens/请求/成本/节省额四档间切换,时间窗从数据起点自适应延伸,以便一眼看出用量节奏。
4. 作为用户,净节省为负的日子要用区别于正值的冷色显示并在图例说明,以便不被误导。
5. 作为用户,我要明细表逐请求列出时间/项目/会话/模型/四列 token/成本,并按时间范围+项目+模型筛选,以便追查具体会话。
6. 作为用户,我过目 mock 通过后,统计页要进桌面壳(Ferryman Widget 程序)成为正式视图,以便与设置视图同一家。(门控:mock 过目)
7. 作为用户,统计窗关闭时只是隐藏、再开秒回,以便常驻无感。(门控:同上)

## Implementation Decisions

### 聚合数据契约(mock 快照与 daemon 端点共同遵守、可对拍)
- 日界=本地时区自然日(与 /report 月 scope 同源);周起点=周一(与悬浮窗周界同源)
- KPI=全时段(账本起点至今天);真实消耗 tokens=四列 token 全期合计
- 请求数=逐 usage 行计数(与 /report requests 同源,含子代理行,页面标注口径)
- 缓存命中率=cache_read/(cache_read+input_tokens)(新定义,页面 tooltip 公示公式)
- 逐日序列=按事件行 ts 归入本地日;节省额按五类事件行(block/bypass/inject/handoff/window)行局部金额归日
- 负值日(当日净节省<0)=冷色单独梯度+图例注明(实测 21 个有事件日中 11 天净负)
- mock 快照与 daemon 端点按同一契约生成,同参数下数值必须一致

### 成本口径
- 金额统一按经济价格表单位(智谱积分)展示,不跨单位合计(积分与元不混加)
- kimi=包月零边际成本(真实 0 元,标注「包月零边际」非「不可算」);DeepSeek=「不可算」
- 渡口经济表无对应价格表时(当前生产实况:econ=local 无表),成本与节省额整面「不可算」一等展示态+配置指引;配置补齐后自动点亮,无需改界面
- handoff 按行 price_ver 计价(现状 1,220 行中 12 行可价;其余入「无价格」单列,与 cost_report unpriced 同源)

### daemon 数据面(门控票)
- 两类只读 GET 端点,经 internal/daemon/queryapi.go 注册表挂 15700 server——自动继承既有 Bearer+仅 127.0.0.1+CORS 白名单访问模型(F8 吸收)
- 聚合端点:KPI 四列汇总+逐日序列(服务端按日聚合)
- 明细端点:过滤(时间范围/项目/模型)+分页+单次返回上限(≤500 行/次);绝不整段下发 14 万行流水
- 具体路由命名照注册表现有风格,实施票内定

### mock 评审通道(今夜三票)
- 快照脚本:读真实账本 JSONL,按契约产出 stats.data.js;字段最小化——**剔除 title 等明细表未展示字段**;会话列=session_id 短截断(F9 吸收);附对账断言(锚点:2026-09 五类事件=10/2/50/778/760,2026-10=67/15/63/442/216;九月 requests=76,245)
- mock 页 stats.html:深色令牌沿用 widget/ui 现有 CSS 变量族;零构建 vanilla JS、零外部资源;「不可算」为一等展示态
- 界面初稿由无头界面 CLI 工具(kimi)按任务书产出(文件头注记出处),泳道只做验收与机械修复,不改设计
- mock 服务:绑 0.0.0.0:8080(决策 D5),页面挂**随机路径段**(每次服务启动生成,推送链接含当期路径——F10 吸收);根路径 404;自动到期自杀(明晨截止);由 Claude Code 会话内启动(继承隐藏控制台,零闪窗)
- 每轮 mock 更新后由主会话经 Pushover 推链接(凭据已核实)

### 成品视图窗(门控票)
- tauri.conf.json 声明新窗(label/url 实施票定,visible:false 起步)、启动创建、关闭=隐藏(运行时创建 webview=永白屏,本机实证)
- conf 与 src-tauri Rust 侧改动归主会话实施泳道;界面工具只产 widget/ui/ 文件;成品票验收含 conf diff
- 成品数据接线=轮询 daemon 聚合/明细端点(30s 级,与悬浮窗同节奏)

### 测试相关既有先例
- widget/ui/tests/assert-static.mjs(静态断言测试)——mock 页照此加断言
- daemon 端点 Go 单测:构造小账本断言聚合/分页;对拍=端点输出与快照脚本同参数一致
- 仓库测试纪律:用户在场不裸跑全仓 go test;门控票只跑 touched 包

## Testing Decisions
- 快照脚本:对账断言内置(行数/五类计数锚点/KPI 公式抽查);跑一次即验收
- mock 页:静态断言(文件存在/关键挂载点/令牌引用/数据文件可解析);真机(手机开链接)留人工验收——这是 mock 的本意
- daemon 端点:Go 单测(小账本构造断言);同参数对拍快照脚本
- 不测实现细节;UI 效果以用户手机过目为验收(mock-first 门)
