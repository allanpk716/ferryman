# 升级链可靠性（v0.3.0 载具：W1-W4）实施规格

> 源：`.xcheck/20260929-160525/proposal.rev1.md`（评审收敛稿）+ decisions.md（D1-D10）+ FINDINGS.md。术语见 CONTEXT.md「升级窗口语义」；人话注解见 docs/20260929_升级链可靠性战役计划.md 术语表。

## Problem Statement

升级/重启 Ferryman 守护时，正在工作的 Claude Code 会话会被拒连最长约 3 分钟甚至遭遇截断；升级链还存在拉起失败不可见、蜂群抢跑导致回滚、并发升级双跑三类可靠性缺陷。用户要：升级不再打扰工作中的会话（空载升级约 4 秒窗），且升级事务失败可见、可彩排。

## Solution（用户视角）

- 升级/重启动手前，程序自动等流量空闲（没有在途请求、10 秒没新请求）才停旧；等不到就问人（在场）或告警后按现状硬切。
- 拉起失败立刻告警，不再静默失败。
- 已开着的会话钩子不再抢跑抢注，升级一次成功。
- 有一个彩排环境：构建两个真实版本、完整跑升级事务、注入故障，发布前先演练。

## User Stories

1. 作为本机用户，我希望升级/重启动手前程序自动等流量空闲，以便正在工作的会话不被打扰。
2. 作为本机用户，我希望升级中途拉起失败能立刻被告警，以便知道出了什么问题而不是全场静默停两分钟。
3. 作为本机用户，我希望升级期间已开着的会话钩子不抢跑导致回滚，以便升级一次成功。
4. 作为开发者，我希望有彩排环境完整演练升级事务并注入故障，以便发布前验证升级链而不拿生产冒险。
5. 作为本机用户，我希望并发触发两次升级不会双跑，以便不会出现两个监督者互相踩踏。

## Implementation Decisions

1. **守护侧统计字段**（W1）：/stats 暴露 `dock_inflight`（渡口 15722 代理面当前在途请求数）与 `last_request_ts`（最后一个代理面请求完成的 Unix 秒，无请求为零值）。两字段**只统计 15722 代理面请求**；管理口 15700 流量（mcp 实例/心跳/widget 轮询/闸门钩子）不计入。**零请求视为静默成立**（由消费方判定，本票如实暴露零值）。
2. **监督者静默门**（W1）：动手前查旧守护，门前置三分支——①已验证旧守护不存在（端口空且无进程）→跳过门直接进既有流程；②守护在但 /stats 不可达→直接进入非静默兜底路径（不干等无法观测的静默窗）；③可达→严格执行"在途=0 且距最后请求 ≥10 秒"。判据不满足默认等 60 秒；终端在场则交互问（继续等/现在切/放弃）；非交互发 notify 告警后硬切（兜底路径，D10：不适用验收线，拒连窗与截断如实记录进 update.log）。旗标 `--wait-quiet=<dur>` / `--force` 供脚本态。**门通过后立即 POST /shutdown**（先关监听拒新、再排在途），把竞态窗压到调度延迟。
3. **事务拉起直连与验证**（W2）：监督者事务拉起（launchAndVerify/rollback/restoreServiceQuiet）弃 wscript/VBS 层，改 `cmd.exe /c start-daemon.cmd + CREATE_NO_WINDOW`（ADR-0015 2026-09-29 补记）。拉起验证：spawn 2 秒起做活性探针，**成功谓词＝本事务配置的管理端点实际应答**（端点取配置注入，不硬编码 15700），重试至 10 秒截止；探针失败只报相位错误＋notify 告警，**不单独触发回滚**——回滚仍由既有 90 秒版本校验裁决。蜂群/看门/Run 键的 VBS 链不动。
4. **守护层锁让路**（W3）：serve 启动早期查 update.lock——持有者活（PID 活且映像 ∈ {换装目标, 自中继副本}）→打印一行、退出码 0 静默让路（唯一化同款）。锁判定从 update 包导出只读助手，daemon 不复制第二份。顺带修 `lock.go` holderAlive 对自中继副本判陈旧的盲区（并发第二次 update 误接管→双监督者）。
5. **彩排台**（W4）：影子实例（独立 DataDir/独立双端口/独立启动脚本/本地桩发布端点），真构建两版 exe 跑完整监督者事务，探针流打流量。验收三场景（D10 口径）：静默路径（间歇流量间隙 ≥10s：门放行、连续 10 次事务零截断、拒连窗 ≤10s）；强制路径（--force＋1 rps 探针全程打：如实记录不判 ≤10s）；长流场景（在途流 >60s：零截断＋硬切边界如实记录）。故障注入集：拉起即杀、模拟蜂群抢拉旧版、陈旧锁、备份位被占、排水中强断——逐项按设计恢复。彩排断言不访问生产端口。

## Testing Decisions

- 只测外部行为：/stats 字段值与口径（代理面计入、管理面不计入、零值语义）；门的三分支与判据、等待/交互/旗标行为；探针谓词（端点应答才算过）与"失败仅告警不回滚"；锁让路退出码与双 update 单飞；彩排三场景断言。
- 沿仓库既有惯例：internal 包内 `_test.go`，seam 注入（update 包 proc*/launch 已有注入缝，沿用并扩展）。
- 不测实现细节（goroutine 结构、内部函数切分）。

## Out of Scope

- W5：v0.2.5 release 页标注作废（未决，对外动作，待用户批准）。
- edge 常驻代理（D2 延后，触发条件见 ADR-0018）。
- 内存态跨升级交接（D4 明确冷启）。
- restart-daemon.ps1 的门逻辑对齐（~/ferryman 仓外运维脚本，晨报列跟进行动）。
- P1 无痕死亡、P2 闸门 enforce、P4 心跳零发跳（范围排除）。
- 自动更新（不存在自动触发机制，升级一律手动）。

## Further Notes
