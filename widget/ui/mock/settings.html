闸门与阈值

闸门（守在编辑器会话门口的一层拦截：会话凉透了还继续往里发消息，就会被拦下、引导你开新会话接着干，避免为已经死掉的缓存全价重付）。

闸门总开关 gate.mode

总开关 「只提醒」= 不拦，只在旁边告诉你缓存已死；「拦截」= 直接拦下这条消息。从「拦截」往下降会弹确认。
Claude Code
Codex
DSH
三条轨道各自独立：总开关管默认，轨道上的选择覆盖总开关。三态永不自动升级，只会越调越松。

阈值 改了先给你看对照，确认后才存

总结阈值 summarize_s 分钟 会话闲置到这个时长，就自动生成一份交接文档（记下干到哪了、下一步干啥），给新会话接着用。
拦截阈值 block_s 分钟 会话闲置超过这个时长，新消息就会被拦下引导开新会话。要比总结阈值大。
最小上下文门槛 min_context 万 token 会话太短就不值得摆渡——低于这个量的会话直接放行，不生成交接。
缓存已死提醒 cache_warn_s 分钟 闲置到这个时长弹一句纯提醒：缓存已死、本条消息要按全价付。填 0 关闭。

心跳与保温

心跳保温（缓存快过期时自动发一条不花钱的轻量请求，把缓存「拍醒」续命）。这组参数动了会先给你看改动对照。

心跳 [heartbeat]

心跳开关 默认关。开之前建议先跑缓存 TTL 实测，把下面的保鲜期填成实测值。
缓存保鲜期 ttl_s 分钟 缓存的保鲜期（TTL）：超过这个时长不动，缓存就被服务商回收。同模型摆渡判热也用这个值。

问询守望 [question_watch]

问询守望（你一口气抛了一串问题等答复时，帮你守住这段时间的缓存不失效）。
模式 mode
提问潮门槛 min_questions 条 最后一条回复里带的问题数达到这个值，才认为你在等答复。
心跳间隔 beat_interval_s 分钟
每窗最多跳数 max_beats 跳 等待窗（一次等答复的时间窗口）里最多拍醒几次，防止无限保温。
摆渡死线提前量 ferry_deadline_lead_s 分钟 赶在拦截阈值之前这么久完成摆渡，留足余量。
